# ADR-0035: A8 two-contribution handoff oracle

## Status

Proposed; candidate only, not adopted or reviewed. Intended canonical path:
`docs/adr/0035-a8-two-contribution-handoff-oracle.md`.
0035 is provisional: recheck the shared namespace immediately before adoption.

## Context

A8 integrates Claude, Codex and Copilot through two filesystem artifacts.
AC-004 requires the final consumer state to reflect both producers
(`specs/epic-196-a8-integration/requirements.md:293-296`). The existing
Fixture Contract uses only the second nonce in the final hash while claiming
both contributions (`specs/epic-196-a8-integration/design.md:338-343`, before
this revision). A second independent nonce cannot demonstrate the first
producer's contribution solely because both processes ran.

## Decision

Bind the final consumer output to both artifacts. Codex reads the first
artifact's nonce1 and then writes an independently generated nonce2 to the
second artifact. Copilot reads nonce1 and nonce2 from those artifacts and
writes exact UTF-8 bytes `COPILOT-CONSUMED:<nonce1>:<nonce2>` with no trailing
newline to the existing output file. The driver verifies its SHA-256 against
the same byte sequence using the known per-run nonces. Nonces are the existing
delimiter-safe tokens generated by the harness; this decision does not expand
their accepted character set or change trace fields.

The design embeds this decision's operative requirements so task reviewers
need no new ADR read permission. Separate mutation checks vary each nonce
alone and reject an output that retains that nonce's old value. Real host
provenance and the authenticated continuous run remain separate evidence.

## Alternatives and rationale

- Keep nonce2-only: minimal code, but cannot satisfy both-contribution binding.
- Derive nonce2 from nonce1: gives a transitive dependency but changes the
  independent-producer mutation contract and obscures separate contributions.
- Read both artifacts and serialize both tokens: selected; explicit dependency
  with no new trace schema, output file, signing scheme or external service.

## Consequences and boundaries

The final consumer now requires read access to both existing artifacts.
Bash and PowerShell prompts, fixture/live oracles and self-checks must agree.
Missing first-artifact access must fail rather than synthesize a contribution.
No model-mode change, Auto fallback, permission expansion, guard bypass,
review waiver or retrospective reinterpretation of old outputs is authorized.
Historical one-nonce results remain historical; this decision does not mark
them as satisfying the revised oracle. Rollback would require reconsidering
AC-004, not silently restoring the old expression.
