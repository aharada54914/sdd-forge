# Independent workflow boundary review

The companion JSON records all **5 live workflow files, 26 jobs and 248 run bodies**, including action pins, effective job permissions, environment inputs, outputs, matrix constraints and job dependencies. Source hashes bind this review to the merged `92815291` workflow tree plus release correction `fccb8830`. This is contextual review of the workflow graph and executable step semantics, not just YAML parsing.

Three confirmed release defects were repaired in `fccb8830`:

1. A `gh` response of `null` for successful run count made `[ "$COUNT" -lt 1 ]` fail inside an `if`, after which the original body printed “CI green confirmed … null successful run(s)” and exited zero. The gate now requires a positive decimal count and validates the release ref type and commit SHA before querying CI. Actual step-body regressions cover positive counts, zero, null, empty, nonnumeric, negative and multiline values plus malformed SHA strings.
2. On manual dispatch from main with an older tag, the archive used the tag but the SBOM scanned the dispatch checkout. A real two-commit Git fixture reproduced an SBOM containing only `dispatch-only-dependency`. The workflow now extracts the actual archive into a private temporary directory, passes its root to the existing generator, and removes the temporary directory on exit. The same regression now observes only `tagged-dependency`.
3. A present malformed dependency lock was silently omitted from the SBOM. The generator now refuses unreadable/malformed lock inputs, non-object lock/package maps and unreadable workflow inputs with a fixed diagnostic. Optional missing source directories remain valid. Regressions assert nonzero exit and no output for corrupt JSON and invalid root/package-map shapes.

The new `--source-root` defaults to the existing checkout root, preserving all existing CLI calls. It is passed explicitly through the generator's functions; no module-global state is mutated. Output JSON remains standard-library serialization. The release workflow's checksums and attestation still bind the exact uploaded tarball/SBOM, and publication remains dependent on both CI-green and loop-gate jobs. This review did not publish or sign a release.

Other contextual conclusions:

- **test.yml:** read-only permissions; required-checks depends on every other job and runs with `always()`. Each ordinary dependency requires success; advisory can be skipped only with trusted `active=false`. The coding-standards and all three MCP jobs are included. Matrix values are closed literals. Direct source interpolation is limited to those literals, runner temporary paths, GitHub result enums and the trusted activation boolean; external refs/SHAs enter through environment or checkout inputs. Explicit Bash steps containing `tee` inherit Actions' `-e -o pipefail`; the MCP multiline default-shell steps run only on Ubuntu. Native PowerShell failure-propagation controls confirm separate steps cannot hide an earlier Python failure. The two optional CLI installation steps are best effort and are not live-host evidence.
- **A9 advisory:** base code executes; exact PR head is checked out as data with no persisted credentials. Activation performs only existence checks. The collector uses a private temporary directory and no raw evidence upload. It is an advisory observation, not approval or independent release evidence.
- **self-improvement.yml:** the enforcement enumeration pipeline now explicitly enables pipefail. Empty baseline on lookup failure is conservative for enforcement. The no-CI labeling path is intentionally advisory. Completion checks exact run/attempt/head, object shape, exact check names and integer-zero outcomes; diagnostics expose fixed categories. Recovery requires successful completion of the whole predecessor job, including post actions, and `complete=true`. The recovery job has only issue-write permission. Tokens are passed as data; no prompt or PR text is inserted into a run program.
- **context-approval.yml:** the environment checker requires manual main dispatch, the exact repository, disabled administrator bypass, the owner reviewer, a main-only deployment policy and absent live bootstrap artifacts. It runs before and after the protected-environment boundary. Signing uses the immutable reviewed checkout and exact candidate digest; only the public staged directory is uploaded. Environment configuration checks do not prove secret custody or a human's approval.
- **model-freshness-check.yml:** separate issue-writing observer with read-only content access, a ten-minute timeout and noncancelling concurrency. Fetch-unavailable is explicitly fail-soft by the observer contract; it is not used as a release gate.

Applicable rules include CS-001/002/004/005/007/008/009/010 at source, serialization, expression, path and credential boundaries; CS-011–019 at ownership and failure propagation; CS-020 at embedded/generator Python shapes; CS-022–026 at process bounds, case and encoding; and CS-027–030 at evidence/oracle scope. There is no workflow SQL sink, browser HTML rendering sink or TypeScript narrowing operation (CS-003/006/021). Fixed YAML matrix values and platform-owned contexts are not untrusted event text. The existing self-improvement action's write permissions are its authorized PR/issue function, not an implicit permission grant to PR test jobs.
