# Test harness contextual review for #688

`test-context-review.json` covers **348 tracked Bash/PowerShell files**, including test launchers, the native checker adapter, executable fixtures, helpers and golden graders. Each row records source SHA-256, source-linked literal dependencies, the relevant sink lines and its contextual review group. This is a review of harness behavior; it does not use a passing test as proof that the tested implementation complies with every rule.

The inventory starts from `git ls-files`, not the CI selection. Eight sink families index source evaluation, embedded programs, native invocation, structured data, regex replacement, status handling, protocol shape/case and path/option boundaries. Context review follows the fixture producer to its process/parser and assertion. The 115 expandable Bash heredoc candidates were examined separately: arbitrary filesystem paths in executable shims required quoting; remaining expandable data uses closed fixture identifiers, generated hexadecimal digests, or deliberately malformed protocol examples. Dynamic PowerShell commands and Python program strings were also followed beyond the line containing `-Command`/`-c`, finding defects that a single-line scan missed. Candidate inventories alone are not semantic evidence.

## Confirmed corrections

- **CS-001/002/009:** model-selector `-Command` paths now travel through scoped environment data. Generated POSIX test shims serialize arbitrary paths as shell literals; the shared helper is exercised through real `/bin/sh` with empty strings, quotes, Unicode, newlines, backslashes and substitution syntax. PowerShell-generated shims use the corresponding destination-specific literal quoting.
- **CS-002/004:** canonicalizer, weakening, approval signing/verification and facet-staleness Python helpers now receive paths through argv. The domain v2 suite's child-v1 runner is literal source with a suite-path parameter. Hook fixture JSON uses `ConvertTo-Json`; uninstaller JSON/TOML path strings use a serializer.
- **CS-009/013:** every newly corrected `Start-Process`/`ProcessStartInfo.Arguments` adapter reuses `lib/native-arguments.ps1`. This includes registry digest/parity, collection, scenario, phase-2 path capture, raw risk-upgrade byte capture, domain capture and Windows lane launching. Existing `ArgumentList.Add` consumers are already structured argv. The existing cross-model actual-argv oracle was run independently and preserves empty, quoted, backslash and newline arguments exactly.
- **CS-007:** fixture root relocation uses byte-literal replacement rather than interpolated `sed` regex/replacement syntax. Hash listings use relative paths; release-surface prefixes are removed literally. Workflow section bounds use literal heading prefixes. The replacement helper is checked with `[]`, `#` and `&` in both old/new paths.
- **CS-019/028:** the Python guard's empty-stdin test no longer appends `echo` or substitutes PowerShell's `$?` into Bash. It asserts actual guard exit 2 and empty output. Empty redirected stdin is not a TTY.
- **CS-025/027/028:** the active Lite step-2 simulator now rejects a singleton-array root, wrong-case keys/schema, array-valued track and scalar array fields. Baseline replay returned `PASS` for the singleton array; six new controls reject it and the other shapes. Actual schema/verdict and lowercase-digest assertions were tightened to case-sensitive comparisons where the protocol requires them. Human-readable diagnostic prose checks remain distinct.
- **CS-009/028:** persistent installer controls create `pack[ab]` beside `packa`, inject placement failure, then test rollback, successful replacement and uninstall. Both old installer controls fail; production fix `01902a1d` passes while preserving neighbor bytes. The rollback injector intercepts only the staging move and delegates every other operation to the real PowerShell cmdlet.

Changes are in `e5c70bcb`, `5dd9506b` and `339d0bd9`. The production literal-path fix is owned separately by the shell audit.

| Rules | Contextual disposition |
| --- | --- |
| CS-001/002/004/007/009 | Reviewed at generated program, process, serialization and regex sinks. Corrected flows are listed above. Deliberately malformed fixture strings remain invalid because rejecting them is the assertion. Fixed enum/hash interpolation in data fixtures is not a general serializer for external data. |
| CS-003/006/008 | No test-harness SQL execution or browser HTML rendering sink was identified. HTML/SQL-looking adversarial strings are validator inputs. Network/CLI URLs in release and live-host tests are fixed test contracts or passed as argument data; production URL construction has its own owner review. |
| CS-005 | Workflow text extraction is test input. Extracted release bodies execute with test doubles and fixed repository code; actual Actions expression/run environments are covered by the root workflow audit. |
| CS-010 | Tokens, signatures, keys and API-key-shaped strings in these tests are synthetic corpus entries or local fixture credentials. Live-host execution requires its explicit profile and is not inferred from mock receipts. |
| CS-011–016 | Shared fixture builders, loop drivers, native argument encoding, catalog registration and byte capture retain clear owners. No new configuration framework, public API or general shell evaluator was introduced. Frozen baseline algorithms and independent expected vectors intentionally remain separate from the current implementation they check. |
| CS-017–019 | Negative commands intentionally return nonzero and are captured before assertions. Cleanup-only ignored errors do not produce a success verdict. Launcher delegation uses `exec`, explicit exit status or a result counter. The empty-stdin false-positive oracle was corrected. |
| CS-020/021 | Native TypeScript narrowing is outside these host files and covered by #690. Embedded Python paths cross argv; its complete language-level review belongs to #687. Closed malformed Python/JS strings created solely as negative fixtures are not production parsers. |
| CS-022–024 | Job/process tests retain their timeout, wait and cleanup owners. Local finite fixture children are distinguished from live external CLIs and deliberately hung timeout fixtures. Runner-level bounds do not imply an individual child has a timeout. No new retries were added. Native Windows process behavior remains a Windows-lane obligation. |
| CS-025/026 | Protocol case and shape must be exact; user-facing prose comparisons need not be. Raw-byte suites use stream capture, while semantic JSON suites deserialize. UTF-8/CRLF fixtures deliberately vary encoding to test the consumer boundary. |
| CS-027–030 | Fixture-name dispatch is limited to test scenario selection. Actual validators receive the test payload, including malformed shapes and failed subprocesses. Static source checks, synthetic skill simulations, real script execution and native-host observations are labeled separately. No acceptance condition was deleted or relaxed. |

Specific retained mechanisms: Bash 3.2 frontmatter `eval` uses only fixed identifier prefixes; key/value expansions remain escaped until the evaluated assignment, so values are not re-parsed as shell source. Generated fixed fixture source is intentionally executable; adversarial input text is not. The Lite simulator is explicitly synthetic, and golden/predecessor copies are compatibility inputs. Windows `.cmd` shims model Windows CLI dispatch, not POSIX shell interpretation.

## Validation and handoffs

The source-bound validation receipt lists commands and outcomes. The domain v2 native Pester suite passed **319/319**; its v1 child runs in a fresh process. More than thirty targeted Bash/native PowerShell suites passed, including the full workflow-state Bash suite. Actual-argv capture, quoted/Unicode selector paths, and the four-target installer matrix with an apostrophe/brackets/Unicode/`#`/`&` temporary directory passed. A concurrent source change during an earlier matrix invocation changed its byte manifest; a stable-source rerun passed. This earlier run is not counted as passing evidence.

`phase2-guard-invariants.tests.ps1` passed 55 checks with one pre-existing, explicitly reported staged-runner activation skip; that skipped path is not execution evidence. The original domain schema Pester suite passed 8/8 after tightening its lowercase grammar.

`phase2-contract-path-helper.tests.ps1` parses here but requires Windows `powershell.exe` for execution; a Linux attempt fails at that platform boundary and is not counted as a pass. Native OS CI and actual live-host evidence are maintained by the root task. These source reviews do not imply every test ran on every platform.

Concurrent source ownership: shell owns cross-model, task-context, scripts, design-system and self-improvement regressions; checker owns design-sync and the machine-rule adapters; research owns renderer controls; the independent provenance reviewer owns its workflow-state additions. Their commits must be reconciled with row hashes before claiming the final merged tree. This snapshot's hashes identify exactly the reviewed bytes and never silently endorse later edits.
