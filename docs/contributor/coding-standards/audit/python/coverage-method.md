# Python contextual review, issue 689

This record supersedes the initial 16-site partial review, without changing that earlier snapshot into a completion claim. `contextual-coverage.json` binds the final working-tree bytes of 230 current Python files, 569 syntactic sink candidates, 24 production heredoc bodies, and six historical sources with actual current consumers. A candidate count includes deliberate executions and name-based false positives; it is not a defect count. Each file includes an AST inventory, boundary line locations, subsystem, findings, and linked sink indices. Body hashes use dedented text without the terminating heredoc newline; whole-file hashes are exact bytes.

Review combined enumeration with enclosing-function and subsystem contracts. AST parsing and Ruff were used to locate constructs, not to certify runtime types. JSON/YAML consumers, explicit type guards, broad catches, subprocess result handling, mutable defaults/state, text encoding, dynamic regex inputs, URL/path assembly, secret diagnostics, serializers and execution inputs were examined in context. Relevant rules are CS-001–004, CS-006–012, CS-017–020, CS-022–023 and CS-025–026. CS-005, CS-021 and CS-024 concern other-language features. Reuse rules CS-013–016 and whole-audit evidence rules CS-027–030 retain their #691/#692 owners; this artifact supplies evidence, not independent closure of those issues.

The scope is finite source review, not a proof that no defect can exist. “Contextually reviewed” describes the method applied to this population, not arbitrary manual repetitions of every rule at every line. Absence of a sink makes that rule inapplicable at that site; a present sink requires the following contextual decisions. Native Windows/macOS process behavior was not independently demonstrated by the Linux regression evidence.

## process

Production subprocess inputs are argv arrays; data paths are separate arguments. The deliberate execution surfaces are project-skill's validated/sealed task command, fixed-review's hash-bound receipt command, the transactional publisher, and test fixtures that intentionally execute generated POSIX shell programs. These are not generic opportunities to delete execution. Test `eval`/`exec` sites load trusted checkout AST/source fragments to exercise generated contracts; they do not accept external data as executable source. JSON interpolation transports serialize with the JSON library. SQL fixture statements are fixed test inputs; there is no production SQL query builder.

Project-skill owns timeout/output limits, Linux process supervision and finally cleanup; PY-038 repairs the failed-Popen descriptor handoff. Research-acquire owns network/read limits and its worker lifecycle. Git can invoke hooks, filters and transports, so “local Git” is not a finite-computation exemption: PY-044–060 add the existing 30-second inspection deadline and classify failure. The real direct-child timeout regression verifies process termination, but is not a descendant-tree guarantee across operating systems. Embedded bundle Git checks also use that deadline. Repository read failure must not silently create a valid snapshot: PY-040 and PY-064 repair status handling.

Fixed local parser/serializer helpers operate on regular fixture/input files and have no external network/hook execution in the relevant transitive path; no arbitrary global timeout was added. Verification suites retain caller/CI-job-owned lifetimes, including intentional long-running lifecycle tests. Promotion/rollback publisher execution retains its transactional lifecycle and recovery contract rather than receiving a new asynchronous kill point. These exceptions are based on the invoked work and ownership, not a blanket “trusted program” exemption. No assertion is made that a kernel or network filesystem cannot block.

## regex

Production dynamic patterns either escape external literal text, select fixed grammar tokens, or intentionally interpret versioned schema regex syntax. Project-skill frontmatter keys come from a fixed tuple; research ADR identifiers are constrained digits before interpolation; feature/path/tool flag and nonce matching uses escaping. Glob construction escapes literal characters and only expands the supported wildcard. Guard normalization broadens rejection; it does not silently broaden a permitted role. Case normalization for hostname, extension/media type, Windows path collision and secret query-key detection is deliberate. HMAC format validation precedes normalized comparisons; identifiers governed by exact schemas retain exact comparison.

## transport

Signing-environment requests use a fixed GitHub API host, bounded calls, and authorization headers without printing the token. PY-039 prevents booleans/numeric fields and malformed API container shapes from satisfying repository policy. Research acquisition validates scheme/host/port, resolves and pins public addresses, checks the connected peer, revalidates redirects and bounds redirects/body bytes/deadlines; XML rejects entity/DOCTYPE expansion. A name-based `execute` candidate in project-skill is the owned process helper, not a database connection. URL parsing alone is not an outbound-request finding.

## Subsystem and boundary decisions

Quality validators consume explicitly guarded objects or schema-validated documents. Runtime checks are necessary despite annotations. PY-001 and later boundary findings repair malformed JSON and invalid UTF-8 failures; PY-041 prevents schema-invalid unhashable IDs reaching semantic sets; PY-042 checks supplemental declaration arrays before counting. Embedded gates now reject top-level and nested malformed shapes through existing failure contracts. Missing traceability requirements are rejected as required by the documented contract; blank companions to a valid ACS/test string and optional null evidence retain their existing semantics. Cross-model malformed structure is tool error 2; a non-PASS verdict remains consensus failure 1.

Broad catches at CLI boundaries explicitly fail, at admission classifiers deny the exemption, or clean up and rethrow. Optional historical metadata readers may return no metadata; that is not admission success. Panelist history extraction is a tolerant optional input, whereas required gate objects use strict validation. Select-agent-model optional fallback-name metadata remains separate from strict candidate routing; this work does not alter model-selection policy. Output serializers use JSON/YAML APIs. Decision-packet HTML uses escaping; test HTTP responses contain controlled fixture data.

Mutable containers are local or owned by an instance/call; no mutable Python argument defaults were found. Lazy module caches avoid repeated imports rather than storing per-request authorization. Temporary global ROOT/stack/recursion settings have restoration paths. Generated invariants and digest constants remain producer-owned, with tests for generated bytes/required tuples; independent copies were not edited as handwritten logic. The relocated `mcp/shared/sync-diagnostics.py` copies exact core bytes to two constant destinations and has no external-input command boundary.

Production Python text I/O pins encoding; binary and descriptor operations were distinguished from text. CI snippets that emit only fixed ASCII tokens do not acquire a new locale-sensitive external-text contract. Deliberately invalid Python fixtures are test data, not active executable modules. Tests use controlled fixtures, owned temporary roots and explicit assertions of status/output; the same subprocess/serialization rules were assessed without converting deliberate negative-test payloads into product findings.
