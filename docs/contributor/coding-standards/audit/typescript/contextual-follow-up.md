## Traced rule decisions

- **External values and type escapes:** CI `tools/actions.ts` validates consumed GitHub fields with Zod before mapping into output; transport JSON is unknown. Local `tools/env.ts` validates unknown tool inputs before fixed allowlist lookup. SDD `parsers/json-object.ts` guards object shape and formats parsed JSON without invoking user-defined `toString`; downstream evidence checks retain their separate strict/tolerant meanings. Node error assertions only read an optional `code` property; they do not grant success on invalid data.
- **Dynamic regex:** SDD `tools/evidence.ts` and `parsers/report-lookup.ts` escape arbitrary interpolated text. `parsers/spec-header.ts:18` receives literal header keys from core and next-command callers. `parsers/evidence-bundle.ts:144` receives task IDs from the task parser's constrained header grammar. The hook's `new RegExp` inputs are generated invariant constants or escaped SDD_SUDO_NAME. Static tests use fixed API-name/canary lists. These uses are distinct from unchecked arbitrary regex construction.
- **Processes:** All three `scripts/run-tests.mjs` collect regular compiled test files, sort them, spawn process.execPath with argument arrays, and propagate a failed/signal exit. Canonicalizer/digest JS wrappers pass a fixed neighboring Python path and argv without shell evaluation; only ENOENT tries the second Python executable. `check-adversarial-report.mjs` uses execFileSync argument arrays, maxBuffer/timeout, `--end-of-options` for the supplied base ref, and `--no-ext-diff --no-textconv` for Git diff. Its report-digest pin is checked before schema/currentness decisions.
- **Exceptions and async:** MCP startup promises have terminal failure handlers writing stderr; stdout stays SDK protocol. Local probe engine connects timeout/maxBuffer to execFile's child termination, bounds global concurrency, and releases queued slots in finally. Hook permission-evidence read failures return false, which denies promotion; stop-marker inspection errors explicitly deny. Hook stdin failure formerly became empty input, but later envelope validation still denied; `500daa7c` preserves the actual read failure without claiming a prior authorization bypass.
- **Read-only/path contract:** SDD `path-guard.ts` resolves real paths, checks allowlist and lexical/resolved denylist, bounds file sizes, and returns failure envelopes on unreadable files. Directory-cycle correction tracks active ancestors, preserving separate aliases. Existence-only callers intentionally receive false; callers requiring diagnostic distinction use the diagnostic APIs. This review does not assert race-free filesystem snapshots against concurrent hostile mutation.
- **Responsibility/reuse:** Three test launchers and two Python dispatchers are small runtime adapters with stable roles; similarity alone does not demand a new generic dispatcher. Hook approval, WFI, domain, and second-approval decisions remain independently owned policies. CI JSON/text transport and diagnostic infrastructure candidates are handled by #691; its later github-client backing-buffer review must be integrated before treating that transport as reconciled.
- **Test escapes and generated artifacts:** `@ts-expect-error` in root-immutable is the negative compile-time mutation test. Remaining non-null assertions on test fixture lookups or fixed array calls are test construction assertions rather than external-input validation. Bundled dist includes upstream SDK/AJV code (including schema compilation) and is regenerated by package builds; dependency code is not hand-edited to satisfy source scans. Frozen human-copy/report snapshots retain their historical status.
