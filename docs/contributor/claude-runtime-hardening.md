# Claude 実行環境の不具合と対策

2026-11-05 に受けた v1.23.0 の Windows 利用報告を調査した記録です。メールの本文・送信者情報は保存しません。

| 報告 | 原因 | 対策 |
| --- | --- | --- |
| 設定ファイルを変数で指定した退避先へコピーすると拒否される | コピー元が保護対象で、変数を含むコピー先の安全性を判定できなかった | 単純なローカル変数代入を解決し、保護対象外の新しい絶対パスへ通常ファイルをコピーする場合を許可。既存のコピー先、リンク、未知の展開は追加許可の対象外 |
| 読み取り用の for ループが曖昧な構文として拒否される | 一般的なループ自体は許可済みだが、行継続を含む最小例で曖昧判定を再現 | 読み取りコマンド、明示的な `--`、引用したループ変数だけを使う限定した構文を認識。書き込みを含むループや未知の構文は引き続き拒否 |
| 壊れた Claude CLI で更新に失敗し、配置先とキャッシュの版がずれる | 配置先を更新した後で PATH の先頭にある CLI の起動失敗が判明した | PowerShell に `-ClaudeCommand` / `SDD_CLAUDE_BIN` を追加。同じ実行先を登録・更新・MCP 登録に使用し、配置先を変更する前に制限時間付きで起動を確認 |
| Windows の深い場所への clone が不完全になる | Git・OS・各アプリのパス長制約により checkout が失敗した | 短い clone 先と clone 時からの `core.longpaths` 設定を案内。不完全なソースの拒否を維持し、エラーに復旧案内を追加 |
| Node が起動しないと安全フックが動かない | Claude の exec 形式フックでは、既定の起動失敗が操作の拒否を意味しなかった | 両安全フックに `onFailure: block` を設定。登録前に Claude >= 2.1.295 と Node >= 22.19.0 を確認し、起動失敗を有効化成功と扱う判定も修正 |

for ループの報告には元のコマンドが含まれていません。修正対象は調査で再現した行継続付きの読み取りループです。すべてのシェル構文を許可する変更ではありません。

追加したコピー許可と読み取りループの構文認識は、ツールが明示的に `Bash` / `bash` の場合に限ります。シェルが不明な `exec_command` などへ Bash の解釈を流用しません。コピーでは、退避先が `.bak` で終わる新規ファイルで、親ディレクトリが実在し、リンクではないことを確認します。コピー用のローカル変数名は `BK`、`BACKUP` / `BACKUP_*`、小文字で始まる英小文字・数字・アンダースコアの名前に限定します。ループ変数も同じ小文字形式に限定します。シェルで意味の変わる特殊変数や曖昧な引用符は解釈しません。`~` / `$HOME` はフックの実行環境で `HOME` が確認できる場合だけ解決します。Windows で確認できない場合はユーザープロファイルを推測せず拒否するため、コピー元も絶対パスで指定してください。例えば Git Bash では、実在するディレクトリと未使用の退避先を指定して `BK=/c/work/repro; cp -a /c/Users/alice/.claude/settings.json "$BK/claude-settings.json.bak"` を使えます。

## 起動失敗とガードによる拒否を区別する

Claude の [hooks リファレンス](https://code.claude.com/docs/en/hooks#block-the-action-when-a-hook-fails)は、`onFailure: block` を 2.1.295 以降でサポートします。対応ホストでは、フック実行ファイルの欠落・異常終了・タイムアウト時にも操作を止めます。Node の実行先はホストの PATH で解決します。インストール後に実行環境が変わった場合も、ホスト側の環境を復旧してから有効化を再確認してください。

停止しただけでは、ガードの正しい動作を証明できません。有効化確認は新しいチャレンジに対する実際のホストの拒否結果を使います。数値終了コードが取得できる従来形式ではガードの拒否コード `2` のみを受理し、`1`・`126`・`127` などの実行失敗を成功扱いしません。native 形式でも、一般的な起動エラーをガードの拒否として受理しません。

## 検証の範囲

Claude Code 2.1.316 にローカルの模擬 API から同じ `Write` を返し、実ホストのフック処理とファイル作成を比較しました。フックの実行ファイルを意図的に不存在とすると、旧設定では書き込みが実行され、`onFailure: block` ではホストが拒否し、ファイルは作成されませんでした。これは実ホストの処理を検証する API fixture であり、ライブモデルとの接続評価ではありません。

回帰検証は、実ホストの起動失敗、ガードの JavaScript・Python・PowerShell 実装、有効化確認、インストーラの失敗時の配置先保持を対象にします。PowerShell 共通仕様は 7 のスイートで検証し、5.1 では起動方式など固有の境界を検証します。

インストール前の検査は、登録後に起きるすべての障害を防ぐものではありません。登録・更新処理の失敗時には既存の WFI-041 の扱いを維持します。実行環境の不備を直し、同じインストールを再実行して配置先と Claude のキャッシュを揃えてください。
