## 表示先の決め方

| 起動した親サービス | 表示先 | 子エージェント |
| --- | --- | --- |
| ChatGPTでSitesが利用可能 | Sites | Claude/Codex等の別に関係なく変更しない |
| ClaudeでArtifactsが利用可能 | Claude Artifacts | Claude/Codex等の別に関係なく変更しない |
| 親サービス不明、または対応表示機能なし | 利用不可／設定不足を明示 | 子のサービスから推測しない |

モデル名、CLI名、子エージェントの申告、リポジトリ内の文章から親サービスを
推測しない。親セッションで得たサービス情報と実際の表示機能の有無を使う。
親は選択した表示先と対象プロジェクトの識別子を保持する。
子は表示先の作成・切替を担当せず、正本の変更は既存ワークフローに従う。
同じ親セッションの再試行で新しいSiteやArtifactを重複作成しない。
表示機能がない場合に、もう一方のサービスへ無断で切り替えない。

## 共通画面

左サイドバーにプロジェクト／機能、上部に6ビューと検索・絞り込み、
中央に選択ビュー、右側に課題詳細を置く。状態は文字と色の双方で示す。

| ビュー | 内容 | データがない場合 |
| --- | --- | --- |
| 概要 | 状態別件数、承認待ち、Blocked、現在工程、次の行動 | 未取得と0件を区別 |
| タイムライン | 工程の順序・タスク進捗。日付がある場合のみ日付軸 | 日付を推測して作らない |
| バックログ | 未承認／予定タスク、実行順序、関連仕様 | 正本にない優先順位を作らない |
| ボード | 状態別カード。実装完了とDoneを分離 | 不明状態をDone列に入れない |
| 一覧 | 課題キー、名称、機能、状態、承認、リスク、検索と絞り込み | 不明な値は未設定／未確認 |
| リリース | 正本で明示されたリリースと所属タスク・進捗 | 「リリース未定義」。Doneから公開済みを推測しない |

詳細はタスク本文、承認・状態、ブロッカー、関連仕様、証拠への参照を表示する。
HTMLとして原文を挿入せず、文字列または制限されたMarkdownとして描画する。
現行タスク型にない項目は表示専用の読取モデルで補い、既存MCP契約の意味を変えない。
リリース所属の読取元・書式は実装前に確定する。表示のための第二の台帳は作らない。

ビュー・機能・検索・フィルタを再読込後に復元する。機能やフィルタ値が消えた場合は
表示ラベルと適用条件を同時にリセットする。詳細の対象が消えた場合も明示する。
狭い画面でも6ビューに到達でき、詳細の開閉・検索はキーボードで操作できる。

## 更新経路

共通の流れは `正本 → 読取・検証 → 版付きスナップショット → 親サービスの表示`。
スナップショットは再生成可能な表示用データであり、管理の正本ではない。

SitesとArtifactsのレンダラーは同じ表示モデルを使うが、接続APIを共通だと仮定しない。
モデル呼出しでタスクを再解釈する処理を更新ループに置かない。
各サービスで許可された読取接続、または認証付きの更新経路を実装する。
会話ターン時だけの再アップロードは自動更新の合格としない。

### Sites

Sitesのサーバーはローカルファイルやstdio MCPを直接読めない。
対応する接続済みアプリ経由の読取か、正本側collectorからの認証付き送信が必要。
プラグイン経由ならSites eligibilityを確認する。ネイティブツールがあるだけで
公開Siteから利用可能とは判断しない。
collector方式では最終確認時刻を正本側で記録する。SiteへのHTTP成功だけで
正本を確認済みにしない。バックエンドの保存データを正本として編集させない。

### Claude Artifacts

Claude公式ドキュメントは接続済みアプリ／カスタムコネクタの利用を案内している。
対象アカウント・組織・実行面で利用可能か、初回接続承認、ツールの利用条件を確認する。
既存ローカルstdio MCPの登録からArtifactsの到達可能性を推定しない。
実際の親ホストで提供されるArtifact作成／更新・コネクタAPIを調べて実装する。
存在を確認していないグローバル関数やAPI名を作らない。

参照（2026-11-05確認）:
- https://support.claude.com/en/articles/17153992-what-are-artifacts-and-how-do-i-use-them
- https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp
- Sitesスキルの `references/app-integrations.md`、`references/identity-and-secrets.md`

## 鮮度・失敗の契約

次の値を分離する。

- データ版と内容が最後に変わった時刻。
- 正本を最後に正常確認した時刻。
- 最後の正常スナップショットの取得時刻。
- ブラウザが接続先から最後に応答を受けた時刻。
- 現在の接続／取得／整合性エラー。

正本が長時間変更されなくても、正常確認が続いていれば古いデータとは扱わない。
正本の正常確認から60秒を超えたら鮮度警告を出す。切断・パースエラーは判明時に表示する。
失敗時は最後の正常データをその時刻と警告付きで保持し、初回失敗は空の成功にしない。
プロジェクトを切り替えた際に前のプロジェクトのデータを新しいラベルで表示しない。
正常復帰した場合にだけ警告を解除する。背景タブから復帰した時も時刻から再判定する。

内容ハッシュで同mtime・同サイズの置換も検出する。複数ファイルの読取前後で
版を照合し、途中更新なら限定回数再読取する。安定しない場合は旧データを維持し、
整合性未確認と表示する。別時点のタスクと証拠からDoneを合成しない。
新旧応答が逆順に到着しても古い応答を採用しない。再接続は全体スナップショットを取得する。

## 実装の単位と確認条件

1. 親サービスの選択・表示先の再利用。ChatGPT親×Claude子、Claude親×Codex子、
   子サービス変更、親不明、表示機能なしの各ケースで選択を確認する。
2. 正本読取モデル。タスク名称・本文・状態と関連参照、欠落・壊れた入力、
   同mtime同サイズ変更、読取中更新、機能ごとの失敗を検証する。
3. 共通6ビュー。各ビューの内容、検索、フィルタ消失、詳細、再読込復元、
   空状態、未定義リリース、キーボードと狭幅レイアウトを確認する。
4. Sites接続と私有公開。会話停止中の正本変更が開いている画面に反映されること、
   collector停止後の警告、復旧、未認証アクセス拒否を実サービスで確認する。
5. Claude Artifacts接続。同じ更新・停止・復旧をClaude親で確認する。
   Sitesの成功でArtifactsを検証済みにしない。子のサービスを変更して再確認する。

表示専用であり、いずれの操作も承認、品質ゲートの結果、taskのDoneを変更しない。
標準更新間隔の案は5秒。正常時の反映目標は10秒以内とし、両ホストで測定する。
API制限で実現できない場合は仕様差として報告し、数値を未測定のまま達成済みにしない。
