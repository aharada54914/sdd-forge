## Problem Evidence

REQ-006 names a per-check execution record — `command`, `exit_code`,
`started_at`, `finished_at` — among the provenance fields the evidence
bundle must carry, and `generate-evidence-bundle` does emit them: its
`checks[]` telemetry copies each value straight from the contract. But
`design.md` section 2, which defines the verification-contract schema,
declares no such per-check fields, so nothing ever feeds the pass-through.
Measured across every shipped contract: all four values are `null` in every
bundle. The seq-845 and seq-846 quality gates both recorded this, the second
adding that it "needs a design-reconciliation ticket, not another
implementation cycle" — the pass-through mechanism itself was proven real by
hand-authoring a contract carrying the keys, at which point BOTH generator
twins emitted the values identically.

The gate also warned against the wrong fix: pinning the bundle-side values
non-null would assert a behavior the generator does not and cannot have,
since it never executes the checks. That is the vacuous-assertion class this
review wave repeatedly caught, so the telemetry pins deliberately assert the
structural key set instead.

## Why-Why Analysis

1. Why are the values always null? No contract carries them.
2. Why does no contract carry them? The contract template and schema do not
   define them, so no author has a slot to fill.
3. Why did the schema omit fields REQ-006 names? Section 2 was written around
   the Red/Green and requirement-mapping additions; the execution record was
   specified on the BUNDLE side (section 5) and never mirrored onto the
   contract side that feeds it.
4. Root gap: a requirement was written against the downstream artifact
   without the upstream schema that could supply it.

## Root Cause Hypothesis

REQ-006's execution record is specified only where it is consumed, not where
it originates, so the generator's pass-through has nothing to pass through
and the requirement is unsatisfiable by construction.

## Proposed Change

1. `design.md` section 2 gains the four fields as OPTIONAL per-check keys,
   with their format stated (`command` a non-empty string, `exit_code` an
   integer, both timestamps ISO-8601 UTC) and the pass-through relationship
   to the bundle made explicit. Optional, because contracts shipped before
   this field set exist and must stay valid — the same grandfathering
   principle `verification-contract/v2` already established.
2. `verification-contract.template.json` carries the four keys so authors
   have the slot.
3. `check-contract` format-checks each field WHEN PRESENT and ignores it when
   absent, so a contract cannot feed the bundle a value the schema forbids.
4. Negative coverage for each format rule in the gate suite.

## Expected Effect

An author who records how a check was run gets that record carried into the
bundle verbatim, so REQ-006's execution record becomes satisfiable instead of
structurally null. Contracts that omit the fields behave exactly as today.

## Verification Metric

All four format rules reject their malformed shapes and accept their valid
ones; a contract omitting the fields still passes; the existing gate tally is
unchanged.

## Verification Plan

Apply both patches to a scratch clone and run six polarity probes plus the
full gate suite. Then confirm a bundle generated from a contract carrying the
fields shows them in `checks[]` on both runtimes.

## Rollback-Plan

Revert both patches. The fields are optional and additive, so no contract or
bundle becomes invalid on rollback.

## Result

Prepared 2026-08-23 on this branch, staged for the human-apply route because
`design.md` is a frozen approved spec and `check-contract.py` is
guard-protected.

- `plugins/sdd-quality-loop/templates/verification-contract.template.json` —
  landed directly (not protected): the four keys added to all 11 template
  checks, defaulting to null.
- `docs/ci-staging/wfi-046-percheck-execution-fields-spec.patch` — design.md
  section 2 schema block and the accompanying field rule.
- `docs/ci-staging/wfi-046-percheck-execution-fields-gate.patch` —
  `check-contract.py`: the `re` import the timestamp rule needs, plus the
  four optional format checks.

**Verified on a scratch clone with both patches applied.** Six polarity
probes: contract omitting the fields PASSES (grandfathering intact); a valid
execution record PASSES; `exit_code: "zero"` REJECTED; `exit_code: true`
REJECTED (bool is not an integer here); `started_at: "2026-08-23 20:00"`
REJECTED; `command: "   "` REJECTED — each naming the offending check and
field. Gate suite on the patched clone: **PASS 156 / FAIL 0**, unchanged.
