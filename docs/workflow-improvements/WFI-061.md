## Problem Evidence

A human approved the exact delimited-region `type-changed` amendment in the
durable Amendment Re-Review Context
(`specs/epic-196-a8-integration/investigation.md:141-157`). Commit
`a01dbf5a661a2cafc6f53130e06ec3b7df07fd6a` then changed the frozen
`design.md` bytes to add the approved semantics
(`specs/epic-196-a8-integration/design.md:948-961`). That commit changed only
`design.md` and the approval-bearing investigation record.

The amendment was legitimate, reviewed by a human, and necessary for T-002,
but it invalidated the hash pinned by the earlier specification-review
provenance. T-001's quality gate consequently reported a stale
specification-review manifest input hash
(`reports/quality-gate/20260831T003856Z-epic-196-a8-integration-T-001.md:19-39`)
and accepted the provenance drift as a Major finding
(`reports/quality-gate/20260831T003856Z-epic-196-a8-integration-T-001.md:65-73`).
Review ticket RT-20260831-004 requires reconciliation through the governing
review/provenance workflow and a clean rerun
(`docs/review-tickets/RT-20260831-004.yml:10-23`).

There is no sanctioned mechanical amendment-rebinding path. The operator must
manually reconstruct and rerun the review stages, even though the context
already contains the human's verbatim approval and the amendment is committed.
That recovery can itself enter WFI-060's investigation-only round deadlock.

## Why-Why Analysis

1. Why did a human-approved amendment invalidate the workflow? Because the
   prior review correctly pinned the old bytes.
2. Why was the new approved state not recognized? Because approval recording
   and provenance rebinding are separate manual activities with no connecting
   transition.
3. Why is a full manual rerun fragile? Because the operator must reconstruct
   attempt order, hashes, identities, and downstream invalidation by hand.
4. Why is the approval record insufficient by itself? Because prose approval
   does not produce an append-only machine-verifiable old-to-new lineage.
5. Why should this be a sanctioned path rather than a validator exception?
   Because independent review of amended content must remain mandatory; the
   missing capability is safe orchestration, not permission to bypass review.

## Root Cause Hypothesis

The workflow has only “original frozen input” and “stale provenance” states.
It lacks a first-class transition for an explicitly approved, committed
amendment that binds the old digest, new digest, approval record, and required
re-review cascade. Operators therefore choose between invalid provenance and a
manual reconstruction of the full state machine.

## Proposed Change

| Target File | Change | Evidence |
|---|---|---|
| New review-loop amendment-rebind command, with `.sh` and `.ps1` entry points | Validate the approved amendment and open a new append-only re-review lineage. | The approved text and implementation commit are already durable at `investigation.md:141-157` and `design.md:948-961`. |
| Specification-review contract schema and validator | Add an amendment lineage record containing prior contract ID/digest, prior artifact digest, new artifact digest, amendment commit, approval-record path/digest, and new attempt ID. | RT-20260831-004 shows the current validator sees only stale input. |
| Downstream review-stage prechecks | Invalidate and reopen every stage bound to the amended artifact, then require normal independent reviewers before any passed status is restored. | The quality report at lines 65-73 shows downstream provenance otherwise remains misleading. |
| Workflow-state validation twins | Recognize only a complete, validated lineage plus the required fresh review contracts; reject bare approval prose or an unreviewed digest substitution. | The existing stale-hash failure must remain the default for unauthorized byte changes. |

The command should require a clean tree and an ancestor amendment commit; prove
that the commit changes only the declared frozen artifacts and their sanctioned
approval record; verify the verbatim approval, approved text fingerprint, and
new document digest; reserve fresh reviewer identities; and emit a new record
rather than edit an old contract. It must never convert the amendment directly
to `PASS`. Its output is an authorized **re-review starting point** whose
success still depends on the ordinary independent verdicts.

## Expected Effect

Approved amendments become explicit, reproducible state transitions rather
than provenance accidents. Unauthorized byte changes continue to fail, while a
valid amendment carries a deterministic lineage and automatically reopens the
review stages whose conclusions depended on the old bytes.

## Verification Metric

Baseline (Epic 196): 1 of 1 approved frozen-document amendments made the
persisted manifest stale and required a manually reconstructed review cascade.

Target: 100% of sanctioned amendments produce a complete old-to-new lineage
and fresh independent review contracts; 0 bare approvals or direct hash
substitutions are accepted as a passed review.

## Verification Plan

1. Replay commit `a01dbf5a...` from the previously passed contract. The command
   must validate the approval context and create a new pending re-review lineage.
2. Complete the ordinary reviewer stages and prove workflow-state validation
   passes only after all newly bound contracts pass.
3. Alter bytes without an approval record; the command and validator must fail.
4. Supply approval prose whose fingerprint, commit, or new digest disagrees;
   each mismatch must fail closed.
5. Add an undeclared file to the amendment commit; the command must reject it.
6. Attempt to overwrite the original contract or skip an affected stage; the
   append-only and cascade invariants must reject both cases.
7. Verify shell/PowerShell parity with identical positive and negative fixtures.

## Rollback-Plan

Disable the amendment-rebind entry point and stop recognizing newly emitted
lineage records for future amendments. Preserve existing records as audit
evidence and require the prior full manual re-review route. Never rewrite or
delete an already emitted lineage record during rollback.
