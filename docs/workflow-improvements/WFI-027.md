## Problem Evidence

Creating `specs/<feature>/investigation.md` **after** a specification review has
reached a terminal verdict permanently invalidates that review's contract, and
no supported command can repair it. The feature `sdd-context` is in this state
now.

Observed sequence, with filesystem timestamps from the working tree
(2026-08-15):

| Time | Artifact |
|---|---|
| 17:26:17 | `reports/spec-review/sdd-context/attempt-1/round-1/spec-review-contract.json` |
| 18:57:09 | `reports/spec-review/sdd-context/attempt-1/round-2/spec-review-contract.json` (verdict PASS) |
| 19:53:44 | `reports/impl-review/sdd-context/attempt-1/round-1/impl-review-contract.json` (verdict NEEDS_WORK) |
| 21:48:57 | `specs/sdd-context/investigation.md` **created** |

`investigation.md` was created in response to the impl review's own Major
finding `ASSUMPTIONS-VALID`, which reads: "`investigation.md` absent; design has
3 non-trivial assumptions with no empirical grounding. Run investigate-codebase
or add investigation.md"
(`reports/impl-review/sdd-context/attempt-1/round-1/reviewer-b.json`). Adding
the file is one of the two remediations the round's own proposed-changes
document offers (`design-round-1-proposed-changes.md:53`).

Two gates then fail, and they fail in a cycle:

1. `impl-review-precheck.sh sdd-context 1 2` exits non-zero with
   `persisted spec contract reviewer manifest is missing investigation evidence`.
   The check at `impl-review-precheck.sh:241-243` requires that, whenever
   `specs/<feature>/investigation.md` exists **on disk right now**, every
   reviewer in the persisted contract carry an entry for it whose sha256 equals
   the file's **current** hash. The spec contract predates the file and cannot
   contain such an entry.
2. The documented escape — start a fresh attempt — is closed by the same defect.
   `spec-review-precheck.sh sdd-context 2 1 --reset` exits non-zero with
   `previous terminal contract is invalid`. `--reset` requires the previous
   attempt's terminal contract to pass `validate_contract` (`:298`), and
   `validate_contract` builds its expected manifest by appending
   `investigation.md` at its **current** hash whenever the file exists on disk
   (`:232-235`).

The expected/actual difference was computed directly against
`attempt-1/round-2/spec-review-contract.json`; it is exactly one path:

```
expected: calibration, precheck-result.json, acceptance-tests.md, investigation.md, requirements.md
actual:   calibration, precheck-result.json, acceptance-tests.md,                   requirements.md
missing:  specs/sdd-context/investigation.md
```

No other input differs, because `validate_contract` reads `requirements`,
`acceptance` and `calibration` hashes **from the contract itself** (`:222-226`).
`investigation.md` is the sole input whose expected hash is taken from the
current filesystem rather than from the record under audit.

The remaining escapes are closed too. `attempt-1 round-3` is rejected because
`validate_contract` demands a `NEEDS_WORK` prior round (`:282-283`) and round 2
is `PASS`. Editing the persisted contract to add the entry would fabricate
provenance: it would assert that reviewers at sequences 0686/0687 read a file
that did not exist when they ran.

The identical construction exists in five further places, so the defect is not
confined to one stage or one platform:

- `impl-review-precheck.sh:241-243`
- `task-review-precheck.sh:176` and its guarded block
- `spec-review-precheck.sh:232-235`
- `impl-review-precheck.ps1:177-181`
- `task-review-precheck.ps1:189-193`
- `spec-review-precheck.ps1:339-341`

## Root Cause Hypothesis

One predicate is being used for two different questions.

- **"Did this completed round bind its reviewers to the inputs it claims?"** —
  an audit of a historical record. Its authority is the record.
- **"Does the round I am about to launch cover every input that exists?"** — a
  completeness requirement on new work. Its authority is the filesystem.

For `requirements.md`, `acceptance-tests.md`, `design.md` and the calibration
reference, the gates answer the first question against the contract's own
recorded hashes, and `impl-review-precheck.sh:229,238` even accepts *either* the
recorded or the current hash — an explicit acknowledgment that a spec artifact
may legitimately have moved on since the round that reviewed it.

`investigation.md` alone is checked against the live filesystem while auditing a
past record. Because the guard is *existence* rather than *contract content*, a
file that appears later retroactively changes what a finished, immutable record
was required to contain. That is unsatisfiable by construction, and it is
triggered by doing exactly what the impl reviewer asked for.

This is the same geometry as the `--provenance-rereview` hash deadlock: a
contract whose acceptance condition can only be met by a state that no longer
exists. WFI-023 already recognised `investigation.md` as hash-frozen *during* a
round; it did not anticipate the file being **introduced** between rounds.

## Proposed Change

1. **Audit against the record, in all six scripts.** Replace the on-disk
   existence guard with a contract-content guard. Where a persisted contract is
   being validated, derive the expectation from the contract:
   - If the contract records an `investigation.md` entry for any reviewer, then
     every reviewer must record it, and the hash must match either the recorded
     value or the file's current value — the same latitude `:229` already grants
     `requirements.md`.
   - If the contract records no such entry, the round legitimately predates the
     file and the check does not apply.

   This keeps the check non-vacuous: a contract that claims investigation
   evidence is still held to it across both reviewers, and a contract that binds
   only one reviewer is still rejected.

2. **Move the completeness requirement to where new work is admitted.** The
   obligation "a round must see the investigation that exists today" belongs to
   the reservation of a *new* reviewer context, not to the audit of an old one.
   `validate-review-context-set.sh --reserve` (and its `.ps1` twin) is the
   authority on manifest validity and currently treats
   `specs/<feature>/investigation.md` only as an allowed path. It should require
   the entry, at the current hash, whenever the file exists at reservation time.

Item 1 alone unblocks `sdd-context`. Item 2 is what prevents the change from
becoming a net loss of coverage, and the two must land together.

## Expected Effect

- A feature that adds `investigation.md` in response to a review finding can
  proceed to the next round. Today it cannot proceed at all: both the next round
  and the next attempt are refused.
- Coverage is not weakened. Every round reserved after item 2 lands is bound to
  the investigation that exists when it is reserved, which is strictly earlier
  and stricter than checking at audit time.
- The audit stops asserting counterfactuals about finished rounds. A contract
  that omits an entry for a file created after it will read as what it is — a
  record of a round that predated the file.

## Verification Plan

1. A regression test constructs a fixture feature with a terminal `PASS` spec
   contract that omits `investigation.md`, then creates
   `specs/<fixture>/investigation.md`, and asserts that
   `spec-review-precheck.sh <fixture> 2 1 --reset` and
   `impl-review-precheck.sh <fixture> 1 2` both succeed. Before the change the
   test fails on both commands with the two error strings quoted above; this
   asymmetry is what establishes it is not vacuous.
2. A second regression test asserts non-vacuity in the other direction: a
   contract that records `investigation.md` for reviewer A but not reviewer B is
   still rejected, and one whose recorded hash matches neither the recorded nor
   the current file is still rejected.
3. A reservation test asserts item 2: with `investigation.md` present, a manifest
   that omits it is refused by `validate-review-context-set.sh --reserve`.
4. Both `.sh` and `.ps1` twins are exercised, and the existing parity suite
   (`downstream-review-precheck-parity.tests.sh`) must stay green.
5. `sdd-context` reaching impl review round 2 is the end-to-end confirmation.

## Rollback-Plan

Revert the six script edits and the reservation change together, then delete the
regression tests. No artifact format changes, so existing contracts, manifests
and ledger records remain valid under either version. The only observable
difference is which of them a gate accepts — reverting restores the stricter
audit-time check, and with it the deadlock.
