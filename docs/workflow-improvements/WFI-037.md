## Problem Evidence

The guard states a universal invariant and enforces a much narrower one. Its
own denial message, `plugins/sdd-quality-loop/scripts/sdd-hook-guard.py:969-971`:

> SDD deterministic gate: agents must not modify gate scripts, hook
> configuration, or critical test files. These are part of the enforcement
> chain and cannot be bypassed by sudo.

"gate scripts" is a category. What the guard actually holds is a hand-maintained
list of path suffixes, and a hand-maintained list of five shell verbs. Both are
enumerations of the protected case, with the default branch on the permissive
side, so anything absent from either list passes.

### Defect 1 — the protected-path set omits most of the enforcement chain

`_is_protected_gate_file()` (`sdd-hook-guard.py:982-1013`) decides entirely by
suffix match against `PROTECTED_GATE_SUFFIXES` and
`PROTECTED_GATE_PLUGIN_JSON_SUFFIXES`, both supplied by the generated invariants
module. Counted 2026-08-19: **70 suffixes** in the installed plugin
(`~/.claude/plugins/cache/sdd-plugins/sdd-quality-loop/1.10.0/`) and **80** at
repository HEAD. The installed copy is what actually runs.

Measured against the live tree: `plugins/*/scripts/` holds **121 files**, of
which **83 match no protected suffix**. Narrowing to the ones that are demonstrably
part of the enforcement or verification chain — those named by a file under

Three of these are load-bearing in ways worth naming individually.

### Defect 2 — the shell write detector recognises five verbs

For a shell command, `_shell_write_targets_are_safe()`
(`sdd-hook-guard.py:1164-1193`) tokenizes and delegates each segment to
`_simple_shell_command_is_safe()` (`:1138-1161`), which scans for a token whose
basename appears in the write vocabulary. When none does, `:1146-1147`:

```python
    if write_at < 0:
        return True
```

The vocabulary, read from the generated invariants at repository HEAD and in the
installed copy alike:

```
SHELL_WRITE_ARG_CMDS  = ('tee', 'touch', 'rm')
SHELL_WRITE_DEST_CMDS = ('cp', 'mv')
SHELL_PS_WRITE_CMDS   = ('set-content', 'out-file', 'new-item', 'remove-item')
SHELL_INDIRECT_CMDS   = ('eval', 'xargs', 'source', 'sh', 'bash', 'zsh', 'dash', 'ksh')
```

Five POSIX verbs, four PowerShell verbs, eight fail-closed interpreters. The
string `git` does not appear anywhere in the guard.

Probed 2026-08-19 by loading the guard module and calling
`_shell_write_targets_are_safe()` directly — read-only, nothing written. Every
probe aims at `plugins/sdd-quality-loop/scripts/kill-switch.sh`, a path the
guard's own `_is_protected_gate_file()` confirms is protected, so a permissive
verdict cannot be explained by an unprotected target:

```
A. modelled verbs, protected target (expect DENY)
   cp DENY   mv DENY   tee DENY   rm DENY   touch DENY   echo > DENY      6/6

B. real writers outside the vocabulary, SAME target (expect DENY)
   git checkout ALLOW   git restore ALLOW   git apply ALLOW
   git stash pop ALLOW  git reset --hard ALLOW   git clean ALLOW
   sed -i ALLOW   patch ALLOW   install ALLOW   ln -sf ALLOW
   truncate ALLOW dd ALLOW   python3 ALLOW   perl -pi ALLOW   node ALLOW
                                                              15/15 ALLOWED

C. genuine readers, same target (expect ALLOW)
   cat ALLOW   grep ALLOW                                     0 false denials
```

Group A is the non-vacuity control: the same probe harness, the same target,
verbs the vocabulary does model, all denied. Group B differs from group A only
in the verb. A first version of this probe aimed at an unprotected path and
returned an identical verdict for every row including the controls — it measured
nothing, and is recorded here because the corrected form is what makes group B
readable.

The two defects compose. Defect 1 means 31 chain scripts are outside the set
entirely; defect 2 means that for the paths that *are* inside it, a command
built from any verb outside a nine-word vocabulary is never examined.

### Observed, not only probed

During the WFI-030 work on 2026-08-19, `git apply <patchfile>` rewrote both
`check-workflow-state` twins inside a detached worktree with no guard
interaction at all. That instance exercises defect 1 (those two files are
unprotected), not defect 2; group B above is what demonstrates defect 2 against
a path the guard does list.

### What this is not

The opposite failure — a command that writes nothing being denied because it
merely names a protected path — was hit six times during this session
(`grep`, `awk`, `git log -S`, a `cp` whose protected path was the *source*, and
twice while trying to measure the guard itself). That direction is the subject
of WFI-022 (Status: Applied) and issue #62 (closed). Group C above shows the
shell analyser is not the layer producing it, so the recurrence is a retention
question for WFI-022 rather than a finding of this one, and no change proposed
below touches it.

## Root Cause Hypothesis

Both halves of the guard enumerate the dangerous case and default to permitting
everything else, against populations that grow every epic.

The file policy is a hand-maintained list of individual paths. Each new
verification script must be remembered and added; nothing fails when one is
forgotten, because the omission presents as "allowed", not as an error. The
stated invariant is a category ("gate scripts"), so a reader of the message has
no way to notice that the category and the list have diverged — and no test
compares them.

The shell policy has the same shape one level down. A closed verb vocabulary
decides whether a command is even a candidate for analysis, and the default
branch returns "safe". The vocabulary models the verbs an agent would reach for
when editing a file directly, and omits the ones it reaches for when moving a
tree around — version control, patch application, in-place stream editors, and
general-purpose interpreters. Those are exactly the verbs an agent uses when
applying a staged change, which is the workflow the protection exists to keep
under human control.

A protection whose failure mode is silence cannot be maintained by attention. It
needs a default that fails closed, or a test that measures the gap.

## Proposed Change

Close the coverage gap, widen the vocabulary, and add the test that keeps both
from drifting again.

(b) A vocabulary test replaying groups A, B and C against a protected target, asserting 6/6 denied, 15/15 denied, and 0 false denials. |

**Why the exception list is bounded.** `plugins/*/scripts/` holds 121 files; 38
are already protected. The exceptions are the scripts an agent legitimately
authors during ordinary work, which is a far smaller and far more stable set
than the 83 currently unprotected. Enumerating exceptions puts the maintenance
burden where a mistake fails loudly: forgetting an exception blocks a write and
is noticed immediately, where forgetting a protection is silent.

**Why `git` needs subcommand awareness rather than blanket treatment.** `git
log`, `git show` and `git diff` are the guard-friendly way to inspect protected
files, and this session leaned on them constantly. Treating the whole of `git`
as a writer would convert defect 2 into a much larger instance of the WFI-022
false-positive problem. The split above is the minimum that closes the write
paths without closing the read paths.

**Non-decreasing guard (`Meta-Change: true`).** Nothing is removed. The
protected set grows by at least 31 entries and changes to a policy that cannot
silently shrink; the write vocabulary grows by 11 verbs plus git subcommand
handling; two test suites are added. The permissive default branch at
`:1146-1147` is narrowed, never widened. No measurement, grader, threshold or
record shape is touched, so there is no metric for this change to make easier to
satisfy. Group A and group C are asserted unchanged, so the change is shown not
to have traded coverage for false positives.

## Expected Effect

Scripts that the enforcement and verification chain executes, and that an agent
can rewrite without the guard objecting, fall from 31 to 0 — and stay there,
because the drift test fails the build when a new one appears.

Writer commands that reach a protected path without being recognised as writes
fall from 15 of 15 to 0 of 15, so the protection over the paths the guard does
list stops depending on which verb an agent happens to choose.

   `tests/constant-parity.tests.sh` — it must stay green, unchanged in method.
   Note it is **not** evidence for this change: it compares `check-contract`

   regenerate into a temporary directory and assert every generated module is

   unprotected chain scripts. Non-vacuity: temporarily un-protect a single chain
   script and assert the test names exactly that script and fails.
3. Run the new vocabulary test: group A 6/6 denied, group B 15/15 denied, group
   C 0 false denials. Non-vacuity: revert only the guard changes with the suites
   left in place; group B must return to 15/15 permitted and group A must stay

   harness.
4. Twin parity: run both new suites under `tests/guard-parity.tests.ps1` as well,
   guarded by a `pwsh` capability probe with a visible `skip -` line when the
   shell is absent. A green PowerShell run that never evaluated the probes would
   prove nothing.
5. Exercise the false-positive direction explicitly before and after: `git log`,
   `git show`, `git diff`, `cat` and `grep` against a protected path must be
   permitted by the shell analyser in both states. If any becomes denied, the
   git subcommand split is wrong and the change is not ready.
6. Run `bash tests/guard-parity.tests.sh` and `bash tests/constant-parity.tests.sh`
   in full — both are pre-existing protected suites and must stay green.
7. Confirm the installed plugin is refreshed before the measurement is believed:
   the copy under `~/.claude/plugins/cache/` is what the hook executes, and it
   currently lags the repository by 10 suffixes. A repository-only fix leaves the
   running guard unchanged.
8. The next retrospective reads the primary metric by re-running the drift test's
   enumeration over the measurement window, against the baseline of 31 recorded
   here.

## Rollback-Plan

Revert the commit whose message contains `WFI-037`, then regenerate the invariant
modules from the restored JSON source. The generated twins are derived artifacts,
so no separate revert is needed for them once the source is back.

Rollback restores the permissive default in both halves: the protected set
returns to its enumerated form and the write vocabulary to nine verbs. Nothing
that was written while the change was in force needs migrating — the guard
decides per invocation and keeps no state. The two new test suites are removed
with the same revert; the pre-existing parity suites are untouched in either
direction.

The one asymmetry worth stating: if the directory-default policy proves to
generate false positives faster than the exception list can absorb them, the
proportionate retreat is to keep step (a) of the JSON change — the 31 explicit
additions — and revert only step (b). That preserves the measured coverage gain
and gives up only the drift resistance.
