## Problem Evidence

The retrospective's **Review Rounds** column has never held a measured value.

Artifact rule 2 names its source precisely:
`reports/implementation/<feature>/T-NNN-review-<positive integer>.md`, associated
by path task ID with the report's own `Task` identity, de-duplicated on
`(task ID, round number)`. The rule is careful and unambiguous.

No such file exists. `reports/implementation/epic-192-a4-facet-manifest/`
contains exactly `T-001.md` through `T-005.md` — five files, no review reports,
for five tasks. The previous period reported the same column as N/A.

So the column reads 0 for all five tasks, and 0 is also what it would read for a
feature whose every task sailed through without a single independent review
round. The two situations are indistinguishable in the output, and one of them
is "the instrument is not connected".

This is the third measurement defect found in one retrospective, alongside the
`Task ID:`/`Task:` key mismatch that zeroed the gate-report count for four
consecutive periods and the in-file cycle collapse of WFI-031.

## Root Cause Hypothesis

Rule 2 was written against an artifact the workflow does not produce.

No skill emits `T-NNN-review-<n>.md`. `implement-task` writes the task's
implementation report; `quality-gate` writes gate reports under
`reports/quality-gate/`; the review loops write their evidence under
`reports/{spec,task,impl}-review/`. Independent review rounds *do* happen and
*are* recorded — they are simply recorded somewhere rule 2 does not look, under
a different naming scheme.

The deeper property is what makes this class dangerous: a metric whose source
does not exist fails **silently and in the safe direction**. A rule pointed at a
missing file yields zero, zero renders as a healthy number, and nothing in the
report distinguishes "no rework" from "not measured". Rules 1 and 3 both fail
loudly when their inputs are malformed — rule 5 requires exclusions to be
recorded in the data-completeness explanation. Rule 2 has nothing to exclude,
because there are no candidates at all.

## Proposed Change

| Target File | Change Description |
|---|---|
| `plugins/sdd-quality-loop/skills/workflow-retrospective/SKILL.md` | Decide rule 2's source and make it one that exists. Either repoint it at the review-loop evidence already on disk (`reports/{spec,task,impl}-review/<feature>/attempt-<M>/round-<N>/`, where rounds are already numbered and contract files already record verdicts), or drop the column. Repointing is preferred: the data is there and is the same data the Review Gate Metrics table already reads. |
| `plugins/sdd-quality-loop/skills/workflow-retrospective/SKILL.md` (Data Completeness) | Require that a metric whose source root is **absent** be reported as `N/A` with the absent root named, never as `0`. This is the general fix and matters more than the specific one — it converts silent zeros into visible gaps for every present and future rule. |
| `plugins/sdd-implementation/skills/implement-task/SKILL.md` | Only if the per-task review report is genuinely wanted as a distinct artifact: state that it is emitted and where. Otherwise leave untouched — inventing a new artifact to satisfy a rule is the wrong direction when the rule can point at existing evidence. |

## Expected Effect

Review Rounds either reports a real count or says `N/A` and names what is
missing. More importantly, the `N/A`-over-zero requirement makes the next
disconnected metric announce itself in its first retrospective instead of after
four periods, which is how long the `Task ID:`/`Task:` mismatch went unnoticed.

## Verification Metric

Target-Metric: number of retrospective metric columns rendering `0` while their source root is absent
Expected-Direction: decrease
Horizon: the next completed feature retrospective
Baseline: 1 (Review Rounds, `epic-192-a4-facet-manifest`, 2026-08-19; and the same column N/A in the preceding period)
Target: 0 — every column with an absent source renders `N/A` and names the missing root

Secondary: Review Rounds reports a non-zero measured count for at least one
task in the next feature that runs any independent review round. `epic-192`
would have reported 3 for its task-review loop (a1r1 → a1r2 → a1r3).

## Verification Plan

1. **The zero disappears.** The next retrospective shows Review Rounds as a
   measured count, or as `N/A` naming the absent root — never a bare `0` for a
   source that does not exist.

2. **The general rule bites, not just this column.** Present the retrospective
   with a feature whose `reports/quality-gate/` directory has been removed
   entirely in a scratch copy. Quality-Gate Runs must render `N/A` with the
   root named, and Data Completeness must drop to `Blocked` per its own
   definition — not render `0` and `Complete`. If the fix hard-codes a special
   case for Review Rounds and the transplanted absence still yields a silent
   zero, this WFI is **Rejected**: the column was the symptom, and the class was
   the reason to fix it.

3. **Not satisfied by prose.** Adding a footnote that says "0 may mean
   unmeasured" does not count. The distinction must be in the rendered cell,
   where someone comparing two periods will see it.

## Rollback-Plan

Revert the commit whose message contains `WFI-033`. The change is confined to
metric-definition and data-completeness prose in the retrospective skill (and,
if taken, one sentence in `implement-task`). No script, artifact path, or
existing report is modified, so reverting restores the prior rule 2 exactly.
Retrospectives written while it was applied stay readable — an `N/A` cell is
strictly more informative than the `0` it replaced, and needs no migration.
