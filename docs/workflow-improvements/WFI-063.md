## Problem Evidence

T-001's quality gate reported both runtime twins failing activated TEST-006
(`reports/quality-gate/20260831T003856Z-epic-196-a8-integration-T-001.md:19-38`)
and accepted the observation as a Major test defect
(`reports/quality-gate/20260831T003856Z-epic-196-a8-integration-T-001.md:65-73`).
RT-20260831-002 records that the canary activated because T-005 legitimately
reached `Implementation Complete`, producing `FAIL` and
`coverage_complete=false` in both twins
(`docs/review-tickets/RT-20260831-002.yml:12-29`). T-005's lifecycle state is
confirmed at `specs/epic-196-a8-integration/tasks.md:809-825`.

The remaining condition is not an implementation defect. T-008 explicitly
requires a HUMAN APPLY STEP: a maintainer and independent reviewer generate
Ed25519 keypairs, register the two roles, countersign five records, and run the
live-host handshake before the validator may report `discharged`
(`specs/epic-196-a8-integration/tasks.md:1543-1554`). Its Done condition names
the same two-party action and exact `discharged` predicate
(`specs/epic-196-a8-integration/tasks.md:1615-1634`).

Commit `9ff52bca40ecd164c0ad679c6deb645bf7975211` committed the five intended
draft records as the agent-complete part of T-008. They are deliberately
non-authoritative: the sample record names pending operator/reviewer identities,
reports `SKIP`, and has both signatures set to `UNSIGNED`
(`tests/hook-activation-live-proof/claude-active.json:21-34`). Nothing in the
implementation can legitimately manufacture the human keys or independent
countersignature.

The current verdict vocabulary cannot distinguish this declared wait from a
failed implementation. The deterministic evidence is accurate, but its only
hard-failure representation files a defect ticket against work that is
correctly awaiting a human gate.

## Why-Why Analysis

1. Why did the quality gate file a test defect? Because the activated canary
   returns a hard failure until its discharge evidence exists.
2. Why does the evidence not exist? Because two named humans must create keys,
   countersign records, and run genuine host sessions.
3. Why can the implementation not resolve it? Because synthesizing those
   identities or sessions would violate the trust boundary being tested.
4. Why is the wait represented as a defect? Because the gate taxonomy has PASS,
   work-needed, and blocked outcomes, but no typed human-dependency disposition.
5. Why must the new state be constrained? Because an untyped “deferred” escape
   could hide ordinary defects and weaken the default-fail contract.

## Root Cause Hypothesis

The measurement model conflates “evidence proves the implementation is wrong”
with “evidence proves a declared external human prerequisite is not yet
discharged.” Both prevent completion, but only the first is a defect. Without a
typed nonterminal state and machine-checkable discharge predicate, reports and
tickets cannot preserve that distinction.

## Proposed Change

| Target File | Change | Evidence |
|---|---|---|
| Quality-verification report and contract schemas | Add `DEFERRED: awaiting-human-gate` as a nonterminal disposition distinct from PASS, NEEDS_WORK, and BLOCKED. | The current report records a hard failure at lines 21 and 68 despite the declared human step. |
| Task metadata / dependency schema | Require a unique gate ID, responsible human roles, machine-checkable discharge predicate, evidence paths, and optional expiry/escalation. | T-008 already names the roles and predicate at `tasks.md:1620-1634`. |
| Deterministic gate and ticket emission | Emit deferred only when the failing check is mapped to an unmet declared human gate; do not create a defect ticket until evidence claims discharge but validation fails, or the declaration expires. | The committed drafts explicitly remain `UNSIGNED` at `claude-active.json:30-34`. |
| Lifecycle and workflow-state validation twins | Keep the task non-Done, require a fresh gate after discharge, and preserve failed status for every unrelated check. | T-001 was correctly retained at Implementation Complete in the report at lines 91-95. |

For this campaign, the named condition can be
`T-008:HUMAN-APPLY-LIVE-HOST-DISCHARGE`. It is discharged only when the trusted
registry contains the maintainer/operator and independent-reviewer identities,
all five drafts carry valid Ed25519 signatures from those roles, genuine session
records exist, and the aggregate validator returns `discharged`. Until then the
quality result is not PASS and neither T-008 nor a dependent task may become
Done. A generic test failure with no predeclared gate ID remains a defect.

## Expected Effect

Reports distinguish an actionable implementation failure from a controlled
wait on named humans without weakening completion rules. Owners can see who
must act and which exact predicate resumes verification, while stale, forged,
or invalid human evidence still becomes a hard failure.

## Verification Metric

Baseline (Epic 196): 1 of 1 activated human-gated dependencies was classified
as a Major test defect even though its unsigned drafts and human discharge step
were working as specified.

Target: 100% of declared unmet human gates receive the typed deferred state and
named discharge condition; 0 ordinary test failures are deferred; 0 deferred
tasks are marked Done.

## Verification Plan

1. Run the T-008 state with all five records explicitly unsigned. The gate must
   emit `DEFERRED: awaiting-human-gate`, the named condition, and no PASS.
2. Remove the declared gate ID while keeping the same failure; it must remain a
   normal hard failure.
3. Claim discharge with a missing signer, invalid signature, wrong role, or
   absent genuine session; each case must be a defect, not deferred.
4. Supply valid two-party signatures and genuine sessions for all five cells;
   the deferred state clears and a fresh quality run evaluates all checks.
5. Prove an unrelated failing check remains visible and prevents PASS even when
   the human gate is legitimately deferred.
6. Verify shell/PowerShell parity and mutation-test the requirement for a
   predeclared, machine-checkable discharge predicate.

## Rollback-Plan

Stop emitting the typed disposition and map future unmet human dependencies
back to the existing hard-failure outcome. Preserve already emitted deferred
records as audit evidence and do not reinterpret them as PASS. No task status is
advanced by either the change or its rollback.
