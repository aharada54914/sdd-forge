## Problem Evidence

The traceability template placed `Layer Spec` in the fourth column while the
validator read the third column. The validator also treated every
requirement-keyed Markdown table as the traceability table, so an unrelated
supporting table could produce a false `invalid Layer Spec` failure.

## Root Cause Hypothesis

The template and validators encoded the table shape independently. No test
locked the canonical header to the column selected by both validator
implementations, and row selection was based only on a `REQ-NNN` first cell
instead of the table header.

## Proposed Change

1. Use the six-column canonical header `Requirement | Design | Layer Spec |
   Code Target | Test ID | Status` in the template.
2. Make both validators locate the table containing the `Layer Spec` header
   and derive the column index from that header.
3. Add parity and negative-control tests covering an unrelated
   requirement-keyed table.

## Expected Effect

A document authored from the template validates without manual reshaping,
supporting tables no longer cause false failures, and future column drift is
detected by tests in both validator implementations.

## Verification Plan

Run `tests/bootstrap-cross-layer-index.tests.sh`. It asserts the exact
six-column header, validates the template-shaped fixture with both validators,
and verifies that a second requirement-keyed table is ignored. Changing only
the template or only one validator must fail the suite.

## Rollback-Plan

Revert the template, both validator changes, and the drift-lock tests together.
Existing six-column traceability documents require no migration.

## Result

Applied. The template and both validators now share the same header-derived
contract, and the regression suite covers the prior false-positive case.
