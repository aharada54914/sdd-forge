## Problem Evidence

The spec-review round state machine cannot process a finding whose cure
lives in `investigation.md`, even though `investigation.md` is one of the
spec reviewers' hash-bound allowed inputs and the calibration's Amendment
Re-Review Context rules explicitly direct reviewers to judge it.

Observed on 2026-09-03 during `epic-193-a5-capability-resolver` spec
attempt 14 (post-Done provenance re-bind):

1. Round 1's only Critical (reviewer A, seq0877, CONSTRAINTS-EXPLICIT) was
   that `investigation.md`'s Ruling (G) entry cited two later-phase
   verification artifacts as bare paths, violating the calibration's
   element 4. The cure is an `investigation.md`-only edit (add each
   artifact's SHA-256 and the binding commit). `requirements.md` and
   `acceptance-tests.md` were both correct as reviewed.
2. Re-invoking round 2 after that cure was rejected:
   `spec-review-precheck.sh` line 333 requires
   `requirements_sha256 != prior || acceptance_sha256 != prior` and fails
   with `reviewed inputs are unchanged from the prior round`. The
   round-transition predicate does not consult `investigation.md`.
3. `--reset` was also rejected: `reset requires a terminal PASS or BLOCKED
   contract`, and a round-1 NEEDS_WORK is non-terminal. There is therefore
   NO lawful transition out of the attempt: round 2 demands a change to
   two documents that need none, and reset demands a terminal verdict the
   state machine will not produce before round 3.
4. The session escaped only because a *legitimate* `requirements.md`
   companion edit happened to exist (the Ruling Annotations mirror
   enumeration had gone under-inclusive after ruling (G)); committing it
   changed `requirements_sha256` and unlocked round 2, which then passed
   clean (seq0879/0880). Had no such edit existed, the only options would
   have been an artificial requirements edit (gaming the predicate) or
   burning rounds 2 and 3 as unreachable and re-reviewing from a fresh
   attempt only after round 3's BLOCKED — two full reviewer cycles wasted.

## Why-Why Chain

- Why did round 2 refuse to start? Because the precheck's
  changed-inputs predicate compares only `requirements_sha256` and
  `acceptance_sha256` against the prior round's contract.
- Why does it compare only those two? Because the state machine models
  "human edits between rounds" as edits to the two review-subject
  documents, the shape every pre-amendment attempt had.
- Why is that model now wrong? Because the Amendment Re-Review Context
  mechanism (added for post-Done re-binds) made `investigation.md` a
  first-class review subject: reviewers are instructed to FAIL a round on
  its evidence-bar nonconformance, so its bytes must be able to change
  between rounds.
- Why was this not caught earlier? Every prior amendment attempt happened
  to edit `requirements.md`/`acceptance-tests.md` in the same round-fix,
  masking the gap; attempt 14 was the first whose sole defect lay in the
  amendment record itself.

## Proposed Change

In `plugins/sdd-review-loop/scripts/spec-review-precheck.sh` (and the
`.ps1` twin), extend the round>1 changed-inputs predicate to include
`investigation.md`: record `investigation_sha256` in
`spec-review-contract.json` (the reviewers' manifests already carry it, so
the orchestrator can copy it the way `requirements_sha256` is copied), and
change line 333's disjunction to
`requirements != prior || acceptance != prior || investigation != prior`.
No other enforcement changes: a round with zero changed inputs is still
rejected, and `--reset` semantics are untouched.

## Expected Effect

A finding whose cure is an `investigation.md` edit becomes fixable in the
next round like any other finding, measured by: re-running the attempt-14
round-2 transition with ONLY the `investigation.md` pin-fix applied (no
`requirements.md` edit) exits 0 instead of failing with
`reviewed inputs are unchanged from the prior round`.

## Verification Plan

1. Regression fixture: a spec-review attempt directory whose round-1
   contract is NEEDS_WORK, with `requirements.md`/`acceptance-tests.md`
   byte-identical and `investigation.md` changed — precheck round 2 must
   exit 0. Mutation check: revert the predicate extension and confirm the
   fixture fails again (non-vacuity).
2. Counter-fixture: all three documents byte-identical — precheck round 2
   must still fail with the unchanged-inputs error (the guard's original
   purpose survives).
3. `review-prompt-calibration.tests.sh` untouched (no role/ID change).
