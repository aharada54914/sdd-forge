## Problem Evidence

When a suite copies a plugin wrapper into a temporary fixture directory and
executes it there, it must also copy the wrapper's runtime dependencies. Nothing
enforces that, so the omission is found one suite at a time — each time by a
failing run rather than by a check.

Commit `d478775c` (2026-08-22) routed 28 wrappers — 14 `.sh` and 14 `.ps1` under
`plugins/*/scripts/` — through the shared dispatchers `lib/py-dispatch.sh` and
`lib/py-dispatch.ps1`. Every one of those wrappers now fails closed with exit 3
when the library is not beside it, which is the designed behaviour and is exactly
what a fixture directory without `lib/` reproduces.

Seven suite files stage those wrappers. All seven needed the same one-line
addition, and they were found in **four** separate rounds spread over four hours
on 2026-08-22:

|---|---|---|---|---|

| 2 | 13:01 | PR #328 external review | `generate-registry-digest.tests.ps1` | `5aadb5de` |
| 3 | 13:12 | CI (`version-gates`, all three runners) for `capability-registry-parity`; `facet-manifest-parity` was swept in the same commit, since that suite is registered only in `tests/run-all.{sh,ps1}` and runs in no CI job | `capability-registry-parity.tests.{sh,ps1}`, `facet-manifest-parity.tests.{sh,ps1}` | `30449b41` |

The diagnostic in every round was `exit 3` from every context of the affected
suites — the dispatcher's fail-closed token, correct and uninformative about the
cause. Round 4 was reached only after round 3 stopped masking it: the
`ownership-digest` ps1 resolver reaches the canonicalize wrapper indirectly, so
the missing `lib/` did not surface until the direct callers were fixed. A grep
performed after round 3 missed it because it searched for `.sh` wrapper names
only, while the failing staging list named `.ps1` files.

### The invariant is unstated and unchecked

`plugins/*/scripts/lib/` holds the shared dispatchers; the 28 wrappers reference
them by a path relative to their own directory. Nothing in `tests/`, in
`plugins/`, or in `docs/contributor/` says that staging a wrapper means staging
its `lib/` sibling. The knowledge exists only as seven now-correct staging lists,
and a suite added tomorrow inherits none of it.

## Root Cause Hypothesis

The wrappers acquired a shared runtime dependency, and the fixtures that execute
them acquired an obligation to carry it — but the obligation lives only in each
suite's hand-written staging list, with no source that can be compared against
the wrappers' actual requirements. The dependency is resolved at run time from
the wrapper's own directory, so it is invisible at the point a suite decides what
to copy; the only feedback is the dispatcher's fail-closed exit, which arrives
when the fixture runs and names the symptom rather than the omission.

This is the same shape WFI-039 recorded for human-copy mirrors: a coupling with
no owner, enumerated only by the union of the places that happen to break.

## Proposed Change

| Target File | Change Description |
|---|---|
| `tests/fixture-staging-completeness.tests.sh` (new, with `.ps1` twin per repo convention) | Derive the requirement instead of hand-listing it. For every `plugins/*/scripts/*.{sh,ps1}` that references a `lib/` sibling (grep for `lib/py-dispatch` and for the `lib/` source/dot-source forms), record the pair. Then, for every suite under `tests/` that names one of those wrappers in a staging context (a `cp`/`Copy-Item` argument, or a member of a staging array), assert the same suite also names the wrapper's `lib/` sibling. Report every offending (suite, wrapper, missing library) triple in one failure, so a future dependency change is one round rather than three. |
| `tests/run-all.sh` and `tests/run-all.ps1` | Register the new suite. |
| `.github/workflows/test.yml` | Register the new suite in the matrix, so the check runs where rounds 2 and 3 were discovered. |
| `docs/contributor/shared-file-mirrors.md` | Add a short section stating the invariant from the authoring side: a fixture that executes a plugin wrapper must stage the wrapper's `lib/` siblings, and the suite above enforces it. This document already carries the sibling "editing a shared file has non-local consequences" knowledge for mirrors, so the class belongs with it rather than in a new file. |

**Mirror obligation.** `.github/workflows/test.yml`, which row 3 edits, is
mirrored in five human-copy bundles (`epic-159-pillar-c`, `epic-159-pillar-d`,
`epic-190-a2-capability-registry`, `epic-192-a4-facet-manifest`,
`quality-loop-fixes`) plus a drafts candidate. All five classify `pending` today,
so `sync-human-copy-mirrors.py --check` stays green and none may be synced —
`epic-159-pillar-c` is the bundle `docs/contributor/shared-file-mirrors.md` marks
"Leave it alone." Applying this WFI widens the divergence between live
`test.yml` and five un-applied bundles of reviewed human work. That is accepted
here, not overlooked.

**Alternatives weighed.** (1) *Extend WFI-039's shipped enumeration* rather than
writing a parallel one — `scripts/human_copy_mirrors.py` already implements the
"derive one enumeration, report every offending site at once" pattern this WFI
reproduces, and `## Root Cause Hypothesis` itself calls this "the same shape".
A separate suite is preferred only because the two enumerations walk different
trees (`specs/*/human-copy/` vs `tests/`) and share no traversal; that is a thin
reason and should be revisited if a third coupling class appears. (2) *Declare
the coupling instead of deriving it* — a manifest, or routing fixture staging
through a shared helper (`tests/lib/` exists, and `tests/lib/loop-driver.sh:244-252`
already stages a wrapper with its `lib/` sibling correctly). This is immune to
every false positive listed in the verification plan, and is the retreat if the
derivation proves unstable. (3) *WFI-039's own "why a test and a tool rather than
only a tool" argument* — no remediation half is proposed here because the fix for
a flagged suite is a one-line addition to a list the failure already names, which
is not the multi-file manual operation WFI-039's tool exists to avoid.

**Not proposed.** Making the wrappers locate their library outside their own
directory (an absolute path, or an environment variable). The directory-relative
probe is what makes the wrappers work identically in an installed plugin tree, in
a fixture, and in a vendored copy; loosening it to make fixtures easier would
trade a test-authoring cost for a runtime-resolution hazard in every consuming
project.

## Expected Effect

A dependency added to a wrapper is caught by one static check before any suite
runs, instead of by successive runtime failures across the suites that stage it.

Concretely: the rounds needed to make fixture staging complete after a wrapper
dependency change fall from 4 (measured on `d478775c`'s 28-wrapper change,
2026-08-22) to 1, and the suites needing a fix are named together in that one
round rather than one subset per round.

## Verification Plan

1. Build the derivation and assert it finds, against the current tree, exactly
   the **32** wrapper/library pairs that exist: 28 for `lib/py-dispatch.{sh,ps1}`
   (14 `.sh` + 14 `.ps1`), 2 for `lib/panelist-common.sh`, 2 for
   `lib/review-precheck-common.sh` — and **zero comment-derived pairs**. The
   dependency must be extracted only from executable `source`/dot-source
   statements and the probe form `[ ! -r "$dir/lib/NAME" ]`, never from prose: a
   line-based grep derives four false pairs from comments in
   `domain-review-precheck.ps1:8`, `spec-review-precheck.ps1:9`,
   `impl-review-precheck.ps1:45` and `task-review-precheck.ps1:74`, and those
   produce false findings against the current green tree. A hand-written
   expectation is acceptable only as a cross-check; the suite must derive the
   list.
2. Replay `d478775c`'s tree and assert the suite names **six** staging sites in
   one failure — this is the headline metric, measured rather than argued. Seven
   is not measurable at any tree; see `## Verification Metric`.
3. Non-vacuity: with the tree green, delete the `lib/` entry from each of the
   seven staging lists in turn and assert the suite fails naming exactly that
   site. Seven single-site mutations, seven exact failures.
4. **False-positive control — the suite must be green on today's tree before
   anything else.** Assert zero findings for each verified shape: (a)
   *deliberate-omission fixtures* — `tests/canonicalize-sdd-yaml.tests.sh:234-256`
   and its `.ps1` twin at `:280-285` copy the canonicalize wrappers into a
   `dispatch-only` directory **with the library intentionally absent**, to prove
   the wrapper fails closed; a naive check flags these and the suite goes red on
   a green tree on day one; (b) *non-staging name arrays* —
   `tests/collection-layer.tests.ps1:126-131` is a `Test-Path` presence check
   that copies nothing, and `tests/generate-gate-capabilities.tests.sh:533` is a
   grep self-check in the same shape; (c) *`cp` inside string test input rather
   than as a command word* — `tests/guard-parity.tests.sh:428,462` and
   `tests/guard-r10-port.tests.ps1:233,239`. State how each is discriminated (an
   explicit opt-out marker for (a), requiring the array to feed a copy for (b),
   requiring `cp` to be a command word for (c)). Any shape that cannot be
   discriminated must be reported as an informational skip, per the
   Rollback-Plan's graduated retreat — never as a failure.
5. Negative control — must be a genuine one. The obvious candidate,
   `tests/guard-parity.tests.sh`, is **not** usable as written: at `:654-655` it
   stages with `cp -R` of the entire `plugins/sdd-quality-loop/scripts`
   directory, so `lib/` arrives incidentally and the suite has no per-file
   staging list to inspect. A check that skipped it would prove nothing about
   discrimination. Use instead a fixture suite that copies a named
   `plugins/*/scripts/` file which genuinely has no `lib/` dependency, and
   assert zero findings. Otherwise the check would pass by flagging everything.
6. Recursive-copy blind spot, tested rather than assumed. The `cp -R` shape satisfies the invariant without declaring it — and the tree
   has at least three such sites, not one: `tests/guard-parity.tests.sh:654`,
   `tests/task-layer-full-profile.tests.sh:22` and `:24`, and
   `tests/hook-guard-epic-a1-boundary.tests.sh:98-99,380` with its `.ps1` twin at
   `:79-80,367`. Symlink staging is a fourth shape the check must not misread:
   `tests/lib/loop-driver.sh` uses `ln -s`, `tests/lib/loop-driver.ps1` uses
   `New-Item -ItemType SymbolicLink` with a copy fallback. The assertion
   so the check must classify such a suite as *satisfied*, not as *missing a
   dependency*. Assert that the whole-directory copy is not flagged, and record
   the limitation plainly: a suite that later narrows that `cp -R` to a file list
   drops the dependency silently and this check catches it only if the narrowed
   list is what the check inspects. State this in the suite's header comment so
   the blind spot is documented where a future author will read it, rather than
   discovered as a fifth round.
7. Twin parity: run both legs, with a `pwsh` capability probe and a visible
   `skip -` line when the shell is absent.
8. The next retrospective records discovery rounds per dependency change against
   the baseline of 4 recorded here, in the Improvement Verification Plan table —
   creating the first row for this metric, which does not yet exist.

## Rollback-Plan

Roll back by removing the named artifacts, not by a message-grep revert: delete
`tests/fixture-staging-completeness.tests.{sh,ps1}`, remove their entries from
`tests/run-all.{sh,ps1}`, remove the step from the `version-gates` job in
`.github/workflows/test.yml`, and remove the added section from
`docs/contributor/shared-file-mirrors.md`. WFI applications here routinely span
several commits (WFI-039: `f5184a47` plus `d53c4123`; WFI-041: three), and the
WFI document's own commit message also contains the ID.

Where an existing suite must carry an opt-out marker for a deliberate omission
(the `canonicalize-sdd-yaml` dispatch-only fixture), that marker is part of this
change and must be removed on rollback — so the claim that "no staging list is
modified" holds only if the check lands green. The new suite, its two
`run-all` registrations, its CI step and the documentation section are removed
together; no staging list is modified by this WFI, so no fixture changes
behaviour and nothing needs re-staging.

If the staging-context detection proves fragile — suites that build paths
dynamically rather than naming wrappers literally — the proportionate retreat is
to narrow the check to suites whose staging list is a literal array or `for` list
and to report unanalysable suites as informational skips, rather than to remove
the check.
