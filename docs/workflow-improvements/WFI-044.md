## Problem Evidence

`AGENTS.md:232-246` carries the WFI-012 case-sensitivity sweep rule. Its scope
sentence binds a task type:

> Any full-parity translation port must be swept before it is reported
> Implementation Complete.

On 2026-08-22/23 three case-parity defects were shipped in `.ps1` files that have
`.sh` twins, in changes that were **not** port tasks — so the rule never became
applicable, and nothing else looked. All three were caught by an external review
bot on PR #336, not by this repository's own process:

| # | Site (pre-fix tree) | Defect | Layer (per the rule's own split) | When the `-match` was written | Fixed in |
|---|---|---|---|---|---|
| 1 | `plugins/sdd-quality-loop/scripts/check-task-state.ps1:115,121` | annotated-approval validity and gating used `-match`; a mis-cased `approved (alice …z)` passed on PowerShell hosts while the awk twin and the MCP parser rejected it | (a) operator-level | in-window, 2026-08-23 | squashed into `409449f0` |
| 2 | `plugins/sdd-lite/scripts/check-task-state-lite.ps1:89,94` | the same two sites in the sibling checker | (a) operator-level | **pre-existing** — `708a6362`, 2026-06-15, *"add check-task-state-lite.ps1 mirroring sh + ps1 tests"* | squashed into `409449f0` |
| 3 | `plugins/sdd-review-loop/scripts/task-review-precheck.ps1` `Test-TasksStatusesMixed` | `Sort-Object -Unique` folds case, so a `Done`/`done` plan classified uniform on PowerShell and mixed under the sh twin's `LC_ALL=C sort -u` — host-dependent precheck evidence | (b) cmdlet-level | in-window, 2026-08-23 | squashed into `409449f0` |

**Precision on the window.** Two of the three operators were written in-window;
defect 2's `-match` predates it by two months. The in-window change at that site
replaced the *pattern* the operator matched against without re-examining the
operator itself. That distinction matters for the proposal: a
changed-lines-only check does catch defect 2, because the in-window edit
modified those exact lines — but it would not have caught the site in June
either, since `708a6362` *was* a port task ("mirroring sh") where the rule was
applicable and the sweep evidently was not produced. The rule's trigger scope
and its enforcement are two separate gaps; this WFI addresses the first, and
`## Expected Effect` states plainly what it does not address.

The rule enumerates both layers that failed here — `-match` in list (a),
`Sort-Object` in list (b) — and requires a mis-cased negative fixture per layer.
None of that was performed, because the work was a WFI application, not a port
task, so the trigger condition was never met.

Recorded as FP-02 (Confidence: High) in
`reports/retrospective/2026-08-23T125111Z-wfi-application-horizon-check.md`.

**Commit provenance.** PR #336 was squash-merged, so the per-fix commits
`cf1deb88` (defects 1 and 2), `4d43dae0` (defect 3) and `146debb2` exist only in
the pre-merge branch history and are **unreachable from `main`** — they were
collapsed into `409449f0`. Verified 2026-08-23: `git merge-base --is-ancestor`
reports each as not an ancestor of HEAD. Every "Fixed in" cell above therefore
names `409449f0`, and the pre-fix line numbers are given relative to
`cf1deb88^`, which is reachable only while a clone retains the branch. Any
reader reconstructing this evidence later should diff `409449f0` against its
first parent rather than resolving the branch SHAs.

### The authoring decision shows the gap is structural, not inattention

Defect 1 was not an oversight in one direction: the site was *deliberately*
written as `-match`, to match the lite twin's pre-existing `-match` at the same
sites — recorded in the code comment the amendment later removed ("the lite
twin's identical sites use `-match`, and the cross-checker parity fixtures
require the two ps1 legs to agree"). Aligning two `.ps1` files to each other is a
defensible instinct; the rule that says the alignment must instead be to the
`.sh` semantics existed, and was not consulted, because nothing in the editing
path pointed at it.

### Scale check: why the fix cannot be a blanket sweep

The 51 `.ps1` files under `plugins/*/scripts/` that have `.sh` twins contain
**1,077** bare case-insensitive operator tokens today (589 `-eq`, 271 `-ne`, 77
`-match`, 47 `-notmatch`, 43 `-replace`, 32 `-contains`, 9 `-notcontains`, 5
`-like`, 4 `-notlike`; measured 2026-08-23 by a word-boundary token scan over
those files that excludes the `-c`-prefixed variants).

This is an upper bound on live operator sites, not an exact count: the scan is
textual, so it also counts the handful of occurrences inside comments that
*name* an operator rather than use it (for example
`plugins/sdd-quality-loop/scripts/check-task-state.ps1:114`, which is the
comment explaining why that site is now `-cmatch`). An earlier draft of this
section reported 1,079 with 79 `-match`; that figure additionally counted two
prose hyphenations, of which `resolve-component-paths.ps1:5`
("excluded-match evidence") is one. The number is used here only for scale, and
the proposal's scope does not depend on its exact value.

Whatever the exact figure, it is three orders of magnitude larger than the
defect set. Requiring every one of those sites to be re-justified would be a
larger and riskier change than the defect class it prevents. The proposal below
is therefore scoped to lines a change actually adds or edits.

The chain terminates at a controllable mechanism — an authoring rule scoped to a
task type and unbacked by any check — which is what `## Proposed Change` acts on.
It stops there rather than at "the author should have remembered": the author
consulted a sibling `.ps1` and reasoned from it, and the rule that would have
redirected that reasoning was, by its own wording, not in force.

## Root Cause Hypothesis

The `AGENTS.md:232-246` case-sensitivity rule (WFI-012) is scoped to the *unit of
work* that first exposed the defect class — a `.sh`→`.ps1` port task — not to the
*edit* that can create it. That scope is why the three PR #336 defects at
`check-task-state.ps1:115,121`, `check-task-state-lite.ps1:89,94` and
`task-review-precheck.ps1`'s `Test-TasksStatusesMixed` received no coverage: all
three landed in WFI-application amendments, not port tasks. A port task is one way to
write a case-insensitive comparison into a twin `.ps1`; every other kind of
change is another, and those are unguarded. Because the rule is prose with no
executable counterpart, an edit outside its scope receives no coverage at all,
so the class recurs exactly where the rule stops — which is where this window's
three defects landed.

## Proposed Change

| Target File | Change Description |
|---|---|
| `AGENTS.md` (rule 1, `:232-246`) | Rebind the scope from the task to the edit: the two-layer sweep applies to **any change that adds or modifies a comparison, matching, sorting or splitting site in a `.ps1` file that has an `.sh` twin**, whether or not the change is a port task. Keep both layer lists and the mis-cased-negative-fixture requirement verbatim; state that the fixture requirement attaches to the change's own test evidence when there is no port acceptance evidence to attach it to. Add one sentence naming the deterministic check below as the enforcement point, so the rule and its check cannot drift apart the way `review-context-boundary.md` and `path_is_authorized` did (WFI-037). |
| `tests/ps1-case-parity.tests.sh` (new, with `.ps1` twin per repo convention) | Diff-scoped check. Resolve the diff basis in this order, and **print which form ran**: (1) `$GITHUB_BASE_REF` fetched to a resolvable merge base; (2) `git merge-base origin/main HEAD` when `origin/main` resolves and a merge base exists; (3) the working tree when it is dirty. If none resolves, print `skip - no diff basis available (shallow clone?)` and exit 0 — a **visible skip, never a silent empty-diff pass**. This matters concretely: the parity suites run in the `loops-routing` and `version-gates` jobs, and neither sets `fetch-depth`, so both check out at actions/checkout's default depth 1, where `refs/remotes/origin/main` is absent and `git diff origin/main...HEAD` exits 128. A silent working-tree fallback there inspects zero lines and reports green on every PR. The repository has both the prior art (`975f37f3` recorded exactly this failure in `version-gates`; `d7551291` fixed it) and the convention (`tests/human-copy-mirror-freshness.tests.sh:45-51` probes `origin/main` and prints a visible skip). For every line **added or modified** inside a `.ps1` under `plugins/*/scripts/` that has an `.sh` twin, fail when the line contains a bare `-match`/`-notmatch`/`-eq`/`-ne`/`-contains`/`-notcontains`/`-replace`/`-like`/`-notlike`, `Sort-Object -Unique`, `Select-String` without `-CaseSensitive`, `-split`, `[regex]::Match`/`IsMatch`/`Replace`, or `switch -wildcard`/`-regex`, **unless that occurrence** uses the `-c`-prefixed variant, passes an explicit case argument, or is covered by a marker comment naming the operator it exempts (`# case-insensitive: <operator> — <reason>`) on the same or preceding line. **A `-c` variant elsewhere on the same line exempts nothing.** A line-granular escape would have exempted the very lines this WFI's evidence is built from: `check-task-state.ps1:116` carried `-cmatch` alongside two bare `-eq "Draft"` / `-eq "Approved"` comparisons that were still case-insensitive against the awk twin's case-sensitive `==`. That divergence was live in the tree until it was fixed separately on 2026-08-23 — a mis-cased `Approval: approved` satisfied the approval gate on PowerShell hosts and failed it on POSIX. The 1,077 pre-existing sites are untouched by construction: only changed lines are inspected. |
| `tests/run-all.sh`, `tests/run-all.ps1`, `.github/workflows/test.yml` | Register the new suite in **all three** surfaces. This repository treats them as one registration unit — `tests/loop-inventory.tests.sh:302-317` asserts exactly that triple — and `tests/run-all.sh` already lists 117 suites. Registering only in CI leaves the suite absent from every local run. Add `fetch-depth: 0` to the checkout of whichever job hosts it, since neither `loops-routing` nor `version-gates` sets it today. |

**False-positive narrowing, measured.** Replayed over `git diff 409449f0^
409449f0 -- 'plugins/*/scripts/*.ps1'` (175 added lines across 5 twin `.ps1`
files), the token list as first drafted produces **21 findings and 0 true
positives**: 2 are comment lines that merely name an operator — one of them the
comment written to satisfy this very rule — and 14 are `[regex]::Match/IsMatch/
Replace`, whose .NET default is already case-*sensitive* and which has no `-c`
variant to move to. Every one of the 21 would have to be answered with a marker
comment to land that commit, which is precisely the reflexive-marker outcome this
WFI says it wants to avoid. The list must therefore (a) exclude occurrences
inside `#` comments, (b) exclude `-eq`/`-ne` whose comparand is a numeric literal
or `$null`, and (c) drop `[regex]::` or restrict it to calls passing
`RegexOptions::IgnoreCase`. Acceptance: the narrowed rule must produce zero
findings on lines that are already correct in that diff.

**Alternative weighed: a frozen-inventory ratchet.** Enumerate the existing sites
into a tracked inventory under `contracts/` (24 machine-readable registries
already live there) and fail on any site absent from it — removals allowed,
additions requiring review. That design needs no `git diff`, no `origin/main` and
no clone-depth assumption, so it removes the shallow-clone failure mode outright;
it makes the grandfathered set explicit and monotonically shrinking; and it turns
each exemption into a reviewable diff rather than an inline self-service comment.
`tests/constant-parity.tests.sh` is existing precedent for a whole-file scanner
built on pure grep/sort/diff. It is *not* chosen here because the diff-scoped form
is materially smaller to land and does not require enumerating and committing
~1,000 sites up front — but that is a cost trade, not a safety argument, and if
the false-positive narrowing above proves unstable the ratchet is the retreat.
A PSScriptAnalyzer custom rule was also considered and rejected: no such
infrastructure exists in this repository today.

**Not proposed.** Auditing the 1,077 existing sites, or requiring the `-c`
variant unconditionally. Many of those sites compare values the `.sh` twin also
compares case-insensitively, or compare non-textual values where the distinction
is void; a blanket rewrite would be a large diff with its own regression surface
and no measured defect behind it. The marker comment is deliberately an escape
hatch rather than a prohibition: the goal is that the choice be *made and
recorded* at edit time, which is exactly what did not happen in defect 1.

## Expected Effect

Case-parity defects in twin `.ps1` files stop reaching external review, because
the check that governs them fires on the edit rather than on a task type that
may never occur.

Concretely: case-parity findings raised by external review fall from 3 findings
in 1 such change (PR #336, all three fixed in-window) to 0 over the next 3
changes that add or modify a comparison site in a twin `.ps1`, and every new or
modified comparison site in those changes carries either a case-sensitive
operator or a recorded reason.

**What this does not address.** Branch 2b of the Why-chain: a site written by a
port task where the rule *is* already in force but nothing enforces it, which is
how defect 2's operator entered in June. Rebinding the scope makes the rule
applicable to more edits; it does not make it enforced on the edits it already
covered. The new suite narrows that second gap only where a change touches the
line — a port that introduces a bare operator is caught, but a pre-existing
untouched one is not, by the diff-scoping this proposal deliberately chose. Left
open and stated here rather than claimed as covered.

against unchanged lines, asserted by running the suite over a diff that touches
none of them.

## Verification Plan

1. Land the suite first and confirm it **fails** on a committed fixture that
   reproduces the three defect sites, naming each one. The fixture ships in the
   suite's own directory as three minimal `.ps1`/`.sh` twin pairs carrying the
   pre-fix lines verbatim (`-match $namedApprovalPattern` at the two
   annotated-approval sites, and `Sort-Object -Unique` in the status-mixing
   helper), together with a synthetic diff that marks those lines as added. This
   is the discriminating order: a suite that cannot reproduce the measured
   defects proves nothing.

   The fixture is committed rather than pinned to a commit **because the pre-fix
   commits are unreachable from `main`** (see **Commit provenance** above):
   `146debb2` and `4d43dae0` were squashed into `409449f0` and will disappear
   from any fresh clone, so a plan that checks them out is unrunnable by
   definition on CI. The fixture is derived from `cf1deb88^` while that history
   is still present locally, and the derivation is recorded in the fixture's
   header comment.
2. Confirm the suite passes over the same fixture pairs with the fix applied
   (`-cmatch` and an Ordinal `HashSet[string]`), so the assertion is satisfiable
   by the fix that was actually made and the pass is not a false negative.
3. Non-vacuity on the grandfathered set: run the suite over a diff that modifies
   an unrelated line in a twin `.ps1` and assert zero findings, proving the
   check is diff-scoped rather than whole-file.
4. Escape-hatch check: add a fixture line using a bare `-eq` with the
   `# case-insensitive: <reason>` marker and assert it passes; remove the marker
   and assert it fails. Otherwise the marker could be unread and the check would
   pass for the wrong reason.
5. Twin parity: run both legs, with a `pwsh` capability probe and a visible
   `skip -` line when the shell is absent.
6. Shallow-clone form: run the suite inside `git clone --depth 1` **and** inside
   an actions/checkout-shaped depth-1 fetch with no `origin/main` ref. Assert it
   prints the visible skip line or runs its fetched-base form, and never reports
   a silent pass over zero inspected lines. Record both runs.
7. Marker discipline: assert the suite emits a machine-readable count of
   marker-exempted occurrences per run, and record it in the retrospective row
   beside the finding count — so an implementation that answers every finding
   with a marker is visible rather than indistinguishable from a clean tree.
8. Assert the suite flags the residual bare `-eq "Draft"` / `-eq "Approved"`
   occurrences on the PR #336 post-fix lines. A suite that passes that tree
   unchanged is passing for the wrong reason.
9. The next retrospective records external-review case-sensitivity findings per
   twin-`.ps1` change against the baseline of 3.0 recorded here, in the
   Improvement Verification Plan table.

## Rollback-Plan

WFIs land here in squash-merged batches — `409449f0` applied five WFIs across 55
files in one commit — so there may be no commit that contains only WFI-044.
Roll back by reverting the named hunks: restore the port-task scope sentence at
`AGENTS.md:232-246`, delete `tests/ps1-case-parity.tests.{sh,ps1}` and their
fixtures, and remove the entries from `tests/run-all.sh`, `tests/run-all.ps1` and
`.github/workflows/test.yml`. If WFI-044 lands in a batch, `git revert` of the
batch commit is **not** the rollback — it would revert the other WFIs too. The AGENTS.md rule returns to
its port-task scope, the new suite and its CI registration are removed with the
same revert, and no source file changes behaviour — the suite only inspects
diffs, so nothing it flagged was rewritten by this WFI.

The marker comments added by changes made while the rule was in force stay in the
source and remain accurate as documentation; they are inert once the check is
gone.

If the diff-scoped check proves noisy — for example flagging mechanical
reformatting that moves untouched comparison lines — the proportionate retreat is
to narrow it to lines whose comparison operator or compared token actually
changed, rather than to remove the check.
