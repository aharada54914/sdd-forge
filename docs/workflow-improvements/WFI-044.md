## Problem Evidence

agci T-007's implementation attempt was interrupted by a provider quota
limit; the orchestrator resumed the work in the SAME session via
file-backed handoff and completed it. The implementation report
nevertheless declares `Isolation Mode: fresh-agent` with
`Fallback Reason: none` — the `same-session-file-reload` markers and the
reload evidence hash REQ-006 mandates were never recorded, and nothing in
the toolchain forced them. Found at the 2026-08-21 gate wave
(RT-20260821-016); disposition: maintainer waiver of 2026-08-23
(docs/review-tickets/RT-20260821-016-waiver-isolation.md), contingent on
this WFI.

## Why-Why Analysis

1. Why was the isolation declaration false? The report template defaults
   to fresh-agent and nothing re-derives the mode from what actually
   happened.
2. Why did nothing re-derive it? The isolation fields are free prose to
   every validator; the report validator checks field PRESENCE, not
   consistency with the narrative or the session record.
3. Why is presence-only checking the design? The fields were added
   (REQ-006) with the assumption that the implementing agent records its
   own interruption honestly — but a quota interruption by definition
   ends the recording agent's turn; the RESUMING orchestrator is a
   different actor with no prompt-level obligation to update the fields.
4. Root gap: the actor who knows about the interruption (the resumer) is
   not the actor the recording duty was assigned to (the interrupted
   agent).

## Root Cause Hypothesis

Fallback-marker recording is assigned to the wrong actor and enforced by
no validator, so every quota-interrupt-then-resume produces a
structurally false `fresh-agent` declaration.

## Proposed Change

1. validate-implementation-report gains a consistency rule: if the report
   body (any section) matches interruption/resumption vocabulary
   (quota/interrupt/resumed/handoff/reload), then `Isolation Mode` MUST
   be `same-session-file-reload` with a non-`none` `Fallback Reason` and
   a `Handoff Reload Evidence Hash`, else
   `IMPLEMENTATION_REPORT_FIELD: isolation narrative contradicts declared mode`.
   (Heuristic, fail-closed; a false positive is corrected by making the
   declaration truthful, never by deleting narrative.)
2. The orchestrator skill (implement-tasks) gains an explicit
   post-interruption step: on resuming any task from a handoff file,
   update the report's isolation fields BEFORE continuing implementation.
3. Negative coverage in tests/turn-first-workflow.tests.sh for the new
   rule (narrative-with-fresh-agent fixture must fail; truthful
   same-session fixture must pass), mutation-verified.

## Expected Effect

A resumed-after-interruption attempt can no longer ship a fresh-agent
declaration; the next RT-016-class contradiction is caught at report
validation, not at a gate two months later.

## Verification Metric

## Result

Applied 2026-08-23 on this branch (Status moved from the maintainer's approval
to Applied; the implementation below is what landed).

- `plugins/sdd-implementation/scripts/validate-implementation-report.sh` — the
  consistency rule. It fires ONLY on a `fresh-agent` declaration, and only
  when ONE sentence carries both an interruption term (quota, rate limit,
  interrupt*, ran out of context, context limit/window hit or exhausted) and a
  resumption term (resum*, took over, picked up, orchestrator
  completed/finished/continued). The conjunction is what separates "this run
  was interrupted and resumed" from the framework's ordinary talk of handoffs
  and reloads. Diagnostic:
  `IMPLEMENTATION_REPORT_FIELD: isolation narrative contradicts declared mode`.
- `plugins/sdd-implementation/skills/implement-tasks/SKILL.md` — the
  orchestrator step: on resuming an interrupted task from a handoff file,
  update the report's isolation fields to what is now true BEFORE continuing,
  and fix a contradiction by making the declaration truthful rather than by
  deleting the narrative.
- `tests/turn-first-workflow.tests.sh` — three cases: the contradiction is
  rejected with the exact diagnostic; the SAME narrative under a truthful
  `same-session-file-reload` declaration passes; and ordinary handoff/reload
  prose does not trip the rule (explicit false-positive guard).

**Verification.** Corpus ratchet `203 reports checked, 203 ok, 0 failing` —
zero false positives across the historical corpus, so the baseline pass set is
unchanged. Four-polarity probe on v2 fixtures: control OK; fresh-agent +
narrative REJECTED; truthful same-session + same narrative OK; ordinary
handoff prose OK. Mutation-verified on a clone-based scratch tree: rule
disabled, conjunction neutered, and interruption vocabulary gutted are all
KILLED, each failure naming the case; control and restored control green.

**Known limit, recorded not papered over.** The originating artifact
(`reports/implementation/agent-cost-context-isolation/T-007.md`) is a LEGACY
report with no schema marker, so it takes the legacy validation path and this
rule never reaches it. The rule is forward-looking by design — WFI-017
grandfathers legacy reports — so it prevents the next RT-016-class
contradiction rather than retroactively catching the first one. The 2026-08-23
maintainer waiver (`docs/review-tickets/RT-20260821-016-waiver-isolation.md`)
covers that historical attempt and is conditioned on this WFI being on file.

Open: none for the implementation. Status moves to Verified after two gate
