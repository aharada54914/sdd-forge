## Problem Evidence

Measured on 2026-08-20 while attempting to gate `agent-cost-context-isolation`.

WFI-017 extended the implementation-report contract to accept a SECOND
serialization of a task's output declaration. `validate-implementation-report.sh`
says so in its own words at lines 113-119:

> the v2 outputs contract accepts EITHER (or both) of two forms -- the current
> template's "## Outputs" two-column table, and the legacy
> "## Output Paths And Hashes" bullet list retained solely so previously
> committed bullet-only and dual-form v2 reports remain valid.

That acceptance landed on one surface and not the other:

| Script | references to `Output Paths And Hashes` |
|---|---|
| `plugins/sdd-implementation/scripts/validate-implementation-report.sh` | 5 (`:27`, `:115`, `:121`, `:125`, `:173`) |
| `plugins/sdd-quality-loop/scripts/validate-review-context-set.sh` | **0** |

`evaluator_output_is_declared` read only `## Outputs`. So a report the repository
formally considers valid could declare its artifacts in a form the authorization
boundary could not read, and every artifact that report declared was rejected as
`REVIEW_CONTEXT_PATH … role-unlisted`. The task became ungateable through no
fault of its own, and no diagnostic anywhere named the real cause: the message
says the path is unlisted, when in fact it is listed in a section the validator
never opens.

Observed in `agent-cost-context-isolation`, whose T-006 and T-008 reports declare
7 and 8 artifacts respectively in exactly the ratified legacy form.

## Root Cause Hypothesis

A contract change was applied to the producer's validator and not to the
consumer's, and nothing compares the two.

WFI-017's own `## Result` records the change as landing in
`validate-implementation-report.sh` plus a template-parity test. The parity test
it added compares the template against that one validator. No test compares the
set of declaration grammars the report validator accepts against the set the
review-context validator can read, so the divergence was invisible from the
moment it was introduced.

This is the same shape as WFI-036 (a rule and the mechanism that must implement
it drifted apart) and WFI-037 (guidance names an artifact the allowlist forbids
reading). Three instances in three different mechanisms suggests the missing
control is generic: **when two surfaces must agree on a contract, something has
to assert that they do.**

## Proposed Change

| Target File | Change Description |
|---|---|
| Review-context validator (generic workflow surface, sh and ps1 twins) | Read the ratified legacy `## Output Paths And Hashes` section in addition to `## Outputs`, using a byte-for-byte mirror of the pattern the report validator already enforces. Scope it to the implementation report; the gate report's post-fix channel keeps its own table form and gains no legacy grammar. |
| Review-context isolation tests (generic workflow surface) | Pin the boundary to the ratified grammar: an artifact declared only in the legacy section is authorized; a path in neither section is still role-unlisted; a legacy row whose hash disagrees authorizes nothing; and a near-miss serialization that the report validator would also reject is refused, so the change cannot be read as a licence to invent further formats. |
| Declaration-grammar parity test (generic workflow surface) | Assert directly that the two validators accept the same set of declaration grammars, so a future addition to one is a red test rather than a silently ungateable feature. This is the control whose absence allowed the drift. |

## Expected Effect

A report the repository accepts can always be gated. Today acceptance by
`validate-implementation-report.sh` does not imply the evaluator can be given
what the report declares, and the failure surfaces as a misleading
"role-unlisted" diagnostic on a path that is, in fact, listed.

The trust model is unchanged: the path/hash pair is still matched by exact
equality and the live file is still re-hashed afterwards. Only the
serialization the boundary can parse widens, to a form the repository already
ratified.

## Verification Metric

Target-Metric: metrics.reports_valid_but_unreadable_by_boundary
Expected-Direction: decrease
Horizon: within the next 10 quality-gate launches
Baseline: 2 of 2 legacy-form reports in agent-cost-context-isolation (T-006, T-008) declared artifacts the boundary could not read
Target: 0 of 10, with every evaluator launch able to read every declaration its own report validator accepts

## Verification Plan

For each of the next ten evaluator launches, record whether the manifest's
declared artifacts were authorized from the report's own declaration, and
whether `validate-implementation-report.sh` accepts that report. The WFI is
verified when acceptance by the report validator implies readability by the
boundary in all ten cases.

Two controls are required, because this widens what the boundary will parse:

1. **Negative control.** A real file the declaration does not name must still be
   rejected as role-unlisted. If it is not, the change removed the boundary
   rather than extended it.
2. **Grammar control.** A near-miss serialization -- one the report validator
   would also reject -- must authorize nothing. Without this the change reads as
   "accept any bullet that mentions a path and a hash", which is not what was
   ratified.

## Rollback-Plan

Revert the commit whose message contains `WFI-038`. That restores
`evaluator_output_is_declared` to reading only `## Outputs`, removes the added
isolation cases and the parity test. No stored artifact changes shape: no
manifest, evidence bundle, gate report or ledger record is written or read
differently by either the change or its rollback. Reverting re-blocks the
legacy-form reports, which is the pre-change behaviour.

## Result

Applied on 2026-08-20 on branch `claude/gate-sweep-20260820`.

Both twins now scan the legacy section in an independent pass -- necessary
because the `## Outputs` loop stops at the next `## ` heading and the two
sections may appear in either order, or the legacy one alone.

**What this did NOT unblock, stated plainly.** It was applied while trying to
gate `agent-cost-context-isolation`, and it does not make that feature gateable.
7 of its 8 implementation reports lack the `- Task ID: T-NNN` line the evaluator
boundary requires for identity, and fail before any declaration question is
reached. The declaration gap was real and is fixed; it was not the only gap.

**Third target now implemented** (2026-08-20, branch
`claude/wfi-038-grammar-parity`). `tests/review-agent-isolation.tests.sh` gained
a declaration-grammar parity block that is driven BY the report validator's own
declaration rather than by a list maintained in the test: it extracts every
section name that script consults for the outputs contract
(`^[a-z_]+_sections = sections\.get\("..."`) and requires the boundary to read
each one, on both twins.

Add a grammar to one validator without teaching the other and the test goes red
naming the grammar. Proven non-vacuous by mutating the *report* validator to
ratify a third section the boundary does not know:

```
not ok: declaration-grammar parity: the report validator ratifies
'## Declared Artifacts' but this suite cannot write it -- teach both the
boundary and this control, do not delete the case
```

That mutation is detectable by nothing else in the suite, which is the point:
it is the exact shape of the drift this WFI documents.

A non-vacuity case accompanies it -- a section name the report validator does
NOT ratify must stay unreadable by the boundary, or the parity claim would be
satisfied by a boundary that reads everything.

One defect was found and fixed while writing it: the grammar loop originally
used `while read ... done <<HEREDOC`, which hands its stdin to every command in
the body. `pwsh` binds inherited stdin as pipeline input and fails with "the
input object cannot be bound to any parameters" **while the suite still exits
0** -- so the PowerShell leg was silently not exercised. Grammars are now
collected into an array first, and the pwsh call redirects stdin explicitly.
