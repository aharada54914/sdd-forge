## Problem Evidence

An agent cannot run a gate script and look at its output. Running it is
allowed; piping it, redirecting it, or capturing stderr is denied — and the
redirect never points anywhere near a protected file.

Paired measurement on `aa179f33`, each row the same operation twice, bare and
decorated, decided by the guard's own `main()`:

| Case | bare | with redirect | the redirect writes to |
|---|---|---|---|
| `bash <check-workflow-state.sh>` | ALLOW | **DENY** | stdout (`2>&1`) |
| `bash <check-workflow-state.sh>` | ALLOW | **DENY** | a pipe (`2>&1 \| tail -3`) |
| `bash <check-workflow-state.sh>` | ALLOW | **DENY** | `/tmp/ws.log` |
| `bash <spec-review-precheck.sh>` | ALLOW | **DENY** | stdout |
| `bash <spec-review-precheck.sh> --help` | ALLOW | **DENY** | a pipe |
| `bash tests/gates.tests.sh` | ALLOW | **DENY** | a pipe |
| `bash tests/gates.tests.sh` | ALLOW | **DENY** | `reports/gates.log` |
| `grep -c runs-on <path>` | ALLOW | ALLOW | `/dev/null` |
| `sed -n '1,5p' <path>` | ALLOW | ALLOW | a pipe |

**7 of 10 pairs flip on the decoration alone.** In every flipped row the only
write expressed is to stdout, a pipe, `/tmp`, or `reports/` — never to the
protected path, which appears solely as the script being executed.

Controls, same run: `echo x > <protected>`, `echo x | tee <protected>` and
`rm <protected>` all stay **DENY**. The gate still does its job; it also
refuses seven things it should not.

### The discriminator is not the redirect

The last two rows identify the mechanism. `grep` and `sed` carry the same
`2>/dev/null` and the same pipe against the same protected path, and are
allowed. `bash` and `python3` are not.

`grep` is not in `shell.indirect_cmds`; `bash` and `python3` are. For an
indirect verb, `_shell_write_targets_are_safe` cannot model what the command
will do, so it fails closed over the **whole command** — including a redirect
whose target it could otherwise resolve, as it demonstrably does for `grep`.

The predicate is therefore:

> protected path mentioned **AND** any redirect present **AND** the verb is in
> `indirect_cmds`

Not "deny on execute". Bare execution is allowed on every runtime measured.

### It is main's behaviour, not one installed version's

A peer session reported this as a 1.15.0 → 1.16.0 regression. Measured across
four guards on the same payloads:

| | 1.15.0 | 1.16.0 | main | main + WFI-048 |
|---|---|---|---|---|
| `bash <gate script> 2>&1 \| tail -3` | ALLOW | DENY | DENY | DENY |
| `echo x > <gate script>` (a real write) | **ALLOW** | DENY | DENY | DENY |

1.15.0 allows the false positive **and** allows a real write to the same file,
because it predates WFI-037's suffix widening. Reverting is not available: it
would trade seven false denials for an open enforcement hole. The behaviour
arrived with WFI-037/040 widening `indirect_cmds` from 8 to 20 verbs, which
closed 15 real bypasses and made this class reachable at the same time.

WFI-048 changes none of these verdicts — 0 of 11 execution shapes moved.

### Cost

A peer session is blocked from opening a spec review because
`spec-review-precheck.sh` cannot print its usage line through a pipe. The
workaround — drop the redirect — is not discoverable from the denial message,
which says *"agents must not modify gate scripts"* about a command that modifies
nothing. Every previous encounter with this class was diagnosed as something
else: WFI-022 attributed a related denial to the tokenizer failing closed on
backslashes, which is a different mechanism reached through the same message.

## Why-Why Analysis

| # | Why (question) | Because (answer) | Evidence |
|---|---|---|---|
| 1 | Why is `bash <gate script> 2>&1 \| tail -3` denied? | The write-target analysis cannot prove the command's writes avoid the protected path, so it denies. | 7 of 10 paired rows flip on the decoration alone |
| 2 | Why can it not prove that, when the redirect target is a pipe or `/tmp`? | The verb is in `indirect_cmds`, so the analysis abandons the whole command rather than the one operand it cannot model. | `grep`+`2>/dev/null` ALLOW, `bash`+`2>&1` DENY, same path |
| 3 | Why does an indirect verb taint the redirect too? | The check answers one question for the entire command — "are all write targets provably safe" — and an unmodellable verb makes the answer no, regardless of what else it resolved. | `_shell_write_targets_are_safe` returns a single verdict per command |
| 4 | Why is one verdict per command the shape? | It was built for `cp`/`mv`/`tee`/`rm`, where the verb IS the write. A verb that merely *might* write was not a case it had to separate. | WFI-037 measured the original vocabulary at five verbs |
| 5 | Why did widening the vocabulary not surface this? | WFI-040 measured the change against true positives — 13 real bypasses closed, 0 false denials — and its corpus contained no read-only command carrying a redirect. | WFI-040 `## Verification Metric`: 13/13 ALLOW → 0/13, read corpus without redirects |

The chain ends at one controllable mechanism: **the analysis conflates "this
verb might write somewhere I cannot see" with "this redirect writes somewhere I
cannot see", and lets the first veto the second.**

## Root Cause Hypothesis

`_shell_write_targets_are_safe` returns a single boolean for a whole command.
That is right for the vocabulary it was designed against, where the verb is the
write: `cp SRC DST` writes `DST` and nothing else.

An indirect verb is different in kind. `bash <script>` might write anywhere, and
the guard is correct to refuse to guess. But the redirect beside it is a
*separate* write, with a target the guard can read straight off the command line
— and does read, correctly, whenever the verb happens not to be indirect.

One unresolvable component vetoes every resolvable one. The result is a denial
that is right about the verb and wrong about the command, reported with a
message describing a modification that was never expressed.

## Proposed Change

| Target File | Change Description |
|---|---|
| `plugins/sdd-quality-loop/scripts/sdd-hook-guard.{py,js,ps1}` | Separate the two questions in `_shell_write_targets_are_safe`. Judge redirect targets on their own: a redirect whose target resolves to a non-protected path is safe whatever the verb is, exactly as it already is for a non-indirect verb. An indirect verb keeps failing closed on **its own** operands, so `bash <script>` with a protected operand stays denied. This narrows one veto; it adds no allowance. |
| `plugins/sdd-quality-loop/references/guard-invariants.json` and `generate-guard-invariants.py` | No new vocabulary. Recorded so a reader does not expect one — the fix is in the analysis, not the data, which is why it cannot be staged as a JSON-only patch the way WFI-040b was. |
| `tests/guard-parity.tests.sh` (and its ps1 twin) | The paired corpus above as parity cases: each operation bare and decorated, asserting the pair agrees. Include the three controls (`>`, `tee`, `rm` onto a protected path) and the `grep`/`sed` rows that already pass, so a regression in either direction fails. |

**Not proposed.** Removing the indirect verbs from the vocabulary. That is the
one-line fix and it reopens the 15 real bypasses WFI-037 measured — `git
checkout`, `sed -i`, `dd`, `python3` and the rest writing to a protected path.
False positives are the price of a fail-closed default; the fix is to make the
default apply to the operand it cannot model rather than to the whole command.

**Also not proposed.** Reverting to 1.15.0's guard. Measured above: 1.15.0
allows `echo x > <gate script>`, a real write to a protected file. It has fewer
false positives because it has a smaller protected list, which is the defect
WFI-037 existed to close.

**Recorded, not fixed here.** The denial message names modification for a
command that modifies nothing, which is why this class has been misdiagnosed
before. A message naming the unresolvable component would have made three
separate investigations unnecessary. That is a diagnosability change and belongs
in its own ticket.

## Expected Effect

An agent can run a gate script and read its output. The review machinery becomes
usable through the sanctioned path — `ship` and `bootstrap` delegate to skills
that drive these scripts through Bash, so every delegated stage is affected, not
only manual invocations.

Concretely: the seven flipped rows return to ALLOW, and the three controls stay
DENY.

Target-Metric: of the paired corpus (10 read-only operations, each measured

number of pairs whose decorated form is denied while the bare form is allowed
Expected-Direction: decrease
Horizon: at application
Baseline: 7 of 10 (measured 2026-08-27 on `aa179f33` against the guard's own

Target: 0 of 10

Secondary, and the one that matters more because this change REMOVES denials:
every real write to a protected path stays denied. Baseline: `>`, `tee` and
`rm` onto a protected path all DENY (3/3), plus the 13 shapes WFI-040 closed
and the 14 WFI-048 closed. Target: unchanged, 30/30 still denied. A single
regression here fails the change outright regardless of the primary metric.

Secondary (twin parity): all rows decided identically by the Python,
JavaScript and PowerShell guards. Baseline: 0 divergences. Target: 0.

## Verification Plan

1. Record the baseline with the paired probe, not a reimplementation: the 7/10
   figure is what the corpus computes, and each row's target is asserted
   protected by `_is_protected_gate_file` first so no row is vacuous.
2. Assert the defect before the change: the seven pairs disagree. These are the
   assertions the fix must make agree.
3. Assert the fix: all ten pairs agree, and both members are ALLOW.
4. **Re-run the WFI-040 and WFI-048 corpora unchanged, before and after.** This
   change subtracts denials, so the only way to know it subtracted the right
   ones is to re-run every corpus that added them. A pass on the new corpus
   alone would be satisfied by disabling the analysis entirely.
5. Mutation, in the direction that matters here: make the redirect-target
   resolution return "safe" unconditionally and confirm the controls go red. A
   fix that cannot fail on `echo x > <protected>` is not a narrowing, it is a
   hole.
6. Twin parity: every case through the JS, Python and PowerShell guards in the
   same `parity_check`, asserted per case rather than as a separate pass, with
   ps1 behind a capability probe and a visible `skip -` line.
7. Re-run the recorded baseline after application and put the number, and the
   30/30 control tally, in `## Result`.

## Rollback-Plan

Revert the commit whose message contains `WFI-056`. The guard returns to denying
the seven shapes, which is today's behaviour; the added parity cases are removed
by the same revert.

Nothing on disk needs migrating — the change alters only which commands are
admitted.

If separating the two questions turns out to have an edge the corpus missed and
a real write becomes allowed, the retreat is immediate and total: revert, and
narrow instead to an explicit allowance for redirect targets under `/tmp`,
`/dev/null` and `reports/`, with the indirect-verb veto otherwise intact. That
covers the measured cost with a much smaller blast radius, at the price of not
generalising.
