## Problem Evidence

Specification review attempt 4 round 1 returned `NEEDS_WORK` with one Critical
finding. Reviewer B found that two later-phase references in the Amendment
Re-Review Context lacked the commit or SHA-256 binding required by the
calibration's all-or-nothing evidence rule
(`reports/spec-review/epic-196-a8-integration/attempt-4/round-1/spec-review-report.md:3-18`).
The references were the T-002 implementation report and T-005 verification
directory.

Commit `dcba8112b62216eabdec2926d61ad09f6a66252b` fixed the finding correctly
and minimally: its only changed path was
`specs/epic-196-a8-integration/investigation.md`. The resulting text binds the
T-002 report to both a SHA-256 and commit
(`specs/epic-196-a8-integration/investigation.md:141-157`) and binds every file
in the T-005 evidence directory to its commit and SHA-256
(`specs/epic-196-a8-integration/investigation.md:511-529`).

Round 2 was then refused with:

> ERROR: spec-review-precheck: reviewed inputs are unchanged from the prior round

The round-advance check reads only the prior `requirements_sha256` and
`acceptance_sha256`, then requires one of those two values to differ
(`plugins/sdd-review-loop/scripts/spec-review-precheck.sh:337-346`). It does
not compare `investigation.md`, even though both reviewers read that file and
the Critical finding was against it. The PowerShell twin has the same two-input
predicate (`plugins/sdd-review-loop/scripts/spec-review-precheck.ps1:480-492`).
An attempt reset is not an escape hatch: reset accepts only a prior terminal
`PASS` or `BLOCKED`, while this contract is `NEEDS_WORK`
(`plugins/sdd-review-loop/scripts/spec-review-precheck.sh:349-358`).

This is not stale-branch behaviour. At drafting time, `origin/main` was
`3749a252af31c504387c4cb8855342261c41dbbd`, 250 commits ahead of merge base
`c7dfac2010713153bcb966cc3a4f72c38ca72241`. The entire shell precheck file on
`origin/main` and this branch resolved to the identical Git blob
`15bddd97a86787d4bacfa1ff1eb5b7b6c9cdf8f5`; therefore the same omission is
live repository-wide.

WFI-052 is a near miss, not a duplicate. WFI-052 concerns the live-hash demand
on `investigation.md` at `spec-review-precheck.sh:249`. This proposal concerns
the later round-advance predicate at lines 343-346 omitting a reviewed input.
The defects share a file but have different predicates, failure modes, and
fixes (`docs/workflow-improvements/WFI-052.md:38-79`).

## Why-Why Analysis

1. Why could a valid finding remediation not advance? Because the changed file
   was absent from the round-advance comparison.
2. Why was it absent? Because the comparison models the two frozen decision
   documents as the complete reviewed-input set.
3. Why is that model false? Because reviewer calibration also consumes and may
   reject claims in the investigation record.
4. Why does the mismatch deadlock? Because a nonterminal round cannot reset,
   while the only accepted proof of change ignores the file the finding names.
5. Why is a workflow change required? Because rewording or making an unrelated
   frozen-document edit would create false provenance instead of demonstrating
   that the actual finding was fixed.

## Root Cause Hypothesis

The round transition owns a narrower input model than the reviewer contract.
The reviewer can issue a blocking finding against three inputs, while the
transition can observe changes to only two. This makes remediation closure
impossible whenever the third input is the sole correct edit.

## Proposed Change

| Target File | Change | Evidence |
|---|---|---|
| `plugins/sdd-review-loop/scripts/spec-review-precheck.sh` | Include the investigation record's prior and current hashes in the round-change predicate. | Current predicate compares only two hashes at lines 343-346. |
| `plugins/sdd-review-loop/scripts/spec-review-precheck.ps1` | Implement the identical three-input predicate with case-sensitive hash comparison. | Twin predicate is at lines 488-492. |
| Contract producer and validator for specification-review rounds | Persist `investigation_sha256`, or derive the prior value from one canonical manifest entry, and fail closed if it is absent or ambiguous. | The reviewer already consumes this input, as demonstrated by the attempt-4 finding. |
| Shell and PowerShell tests | Add no-change, investigation-only, requirements-only, acceptance-only, and unrelated-file fixtures. | The current campaign supplied the investigation-only regression case. |

Concrete shell-side sketch:

```diff
 prior_requirements_sha="$(jq -r '.requirements_sha256' "$prior_contract")"
 prior_acceptance_sha="$(jq -r '.acceptance_sha256' "$prior_contract")"
+prior_investigation_sha="$(jq -r '.investigation_sha256' "$prior_contract")"
-if [[ "$requirements_sha" == "$prior_requirements_sha" && "$acceptance_sha" == "$prior_acceptance_sha" ]]; then
+if [[ "$requirements_sha" == "$prior_requirements_sha" && "$acceptance_sha" == "$prior_acceptance_sha" && "$investigation_sha" == "$prior_investigation_sha" ]]; then
   fail "reviewed inputs are unchanged from the prior round"
 fi
```

If the contract instead derives the value from its manifest, it must select
exactly one canonical path and reject missing or duplicate entries. The change
must preserve the original property: **some reviewed input actually changed**.
It widens which reviewed inputs count; it does not admit an unchanged round.

## Expected Effect

A reviewer finding against any declared reviewed input has a mechanically
reachable remediation round. Unchanged rounds remain rejected, unrelated-file
edits do not count, and no artificial edit to a frozen decision document is
needed to make a real investigation-record fix visible.

## Verification Metric

Baseline (Epic 196 attempt 4): 1 of 1 investigation-only Critical remediations
was refused as “reviewed inputs are unchanged,” leaving no reset path.

Target: 0 round refusals after a sole, hash-verified change to a declared
reviewed input; 100% refusal for genuinely unchanged inputs and for changes
confined to unrelated files.

## Verification Plan

1. Reproduce attempt 4 with the two prior contract hashes unchanged and only
   the investigation hash changed; both twins must permit round 2.
2. Leave all three reviewed hashes unchanged; both twins must emit the existing
   unchanged-input error.
3. Change each input alone in three independent fixtures; each must advance.
4. Change only an unrelated file; the round must remain refused.
5. Remove or duplicate the prior investigation hash source; validation must
   fail closed rather than silently ignore the input.
6. Mutation-test both twins by restoring the two-input predicate and show the
   investigation-only fixture fails.

## Rollback-Plan

Revert the three-input predicate and contract field together. This restores the
current stricter-but-incomplete transition and does not mutate any feature's
review artifacts. A rollback reintroduces the documented deadlock, so it must
be accompanied by an operator warning for investigation-only findings.
