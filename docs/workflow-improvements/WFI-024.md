## Root Cause Hypothesis

`plugins_hash_matches` treats "the pin-fallback lookup could not be performed"
and "the pin-fallback lookup was performed and found no justification" as the
same outcome: reject. Those are not the same claim. A release artifact built by
excluding `.git` (exactly what `repository-release-validation.tests.sh` does to
model real packaging) has no commit history to consult at all — the assertion
"does this manifest-recorded hash match some legitimate point-in-time content
of this shared reference doc" is not evaluable there, because there is no
history to search. Failing it anyway silently redefines "not evaluable" as
"failed," which is indistinguishable, from the diagnostic's perspective, from
an actual provenance violation — so every `plugins/*` reference doc that has
legitimately evolved since a past feature's review (the exact scenario
`plugins_pin_commit`'s own docstring says it exists to tolerate) fails closed
in a git-less checkout, with no way to reach the tolerance logic that already
handles it correctly wherever git history is present.

## Proposed Change

The change described below has already been implemented in this worktree
(uncommitted; see Result) rather than merely proposed, because the task that
produced this WFI record specified the fix directly.

| Target File | Change Description |
|---|---|
| `plugins/sdd-quality-loop/scripts/check-workflow-state.sh` | Added `plugins_git_history_available()`, returning success only when the `git` binary exists and `SCRIPT_ROOT` is a git work tree — checked independently of `plugins_pin_commit`'s own exit status, because that function also fails for reasons other than "no history exists" (e.g. an evidence path outside `REPO_ROOT`, or a path with zero commits touching it), and only the true absence of history should relax the check. `plugins_hash_matches` now returns success (accepted, not evaluable) immediately after a live-hash mismatch when `plugins_git_history_available` reports no history — before ever calling `plugins_pin_commit`. The file must still exist, be readable, and not be a symlink (unchanged, enforced earlier in the same function and by the caller). When git history IS available, every line of the prior logic runs unchanged. |
| `plugins/sdd-quality-loop/scripts/check-workflow-state.ps1` | The identical change: `Test-PluginsGitHistoryAvailable()` and the same early-return in `Test-PluginsHashMatches()`, so the two runtimes stay behaviourally identical. |
| `tests/workflow-state.tests.sh` | A new `reference-doc-forged-no-git` fixture, placed immediately after the existing `reference-doc-forged` fixture it is paired with. Both fixtures forge the SAME `risk-gate-matrix.md` manifest hash (`"f" * 64`, matching neither the live file nor any historical content — i.e. a hash the pin fallback cannot justify under any circumstance). `reference-doc-forged` (unmodified by this change) proves that input is REJECTED when git history is available, by running the checker from its normal location (`$ROOT`, which has `.git`). The new fixture proves the SAME input is ACCEPTED when git history is not available: it embeds a standalone copy of both checker twins plus `contracts/workflow-state-registry.schema.json` at the canonical relative depth inside the fixture root, asserts (as a non-vacuity precondition) that the fixture root is genuinely not inside a git work tree, then runs the embedded checkers directly and expects success on both runtimes. |
