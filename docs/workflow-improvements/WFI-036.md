## Problem Evidence

Measured in `sdd-domain-concept-contract` on 2026-08-19, during T-004's
quality-gate cycle 2 (evaluator run `RUN-…-qg-T-004-seq0794`, ledger 794).

A `quality:sdd-evaluator` manifest may carry a changed file only through
`evaluator_output_is_declared(path, hash, report)` in
`plugins/sdd-quality-loop/scripts/validate-review-context-set.sh`, which requires
the exact ``| `<path>` | `<hash>` |`` row in the **implementation report's**
`## Outputs` table. That report is frozen: its own Snapshot Notice states it
"is not edited after the fact to reconcile."

So when a gate cycle produces a fix, the fixed bytes are declared nowhere, and
the next cycle cannot authorize the artifact it is supposed to review.

The evaluator did not assert this — it built a manifest naming the shipped ps1
twin and ran the real validator:

```
REVIEW_CONTEXT_PATH: sdd-evaluator contains a real but role-unlisted path:
plugins/sdd-domain/scripts/validate-domain-contract.ps1
exit 1
```

Drift measured across this one feature, all of it unbound:

| Artifact | declared in Outputs | shipped at cycle 2 | intervening commits |
|---|---|---|---|
| `validate-domain-contract.ps1` | `ab0ee183…` | `2de062d7…` | `0f29c754` (RT-20260819-001), `72e79d56` (RT-20260819-002) |
| `contract-v2-schema.Tests.ps1` | `02450c0e…` | `0349f523…` | `daa7d35a`, `0f29c754`, `3a5ced4d`, `72e79d56` |
| `CHANGELOG.md` | `eea844ff…` | `3cd30b93…` | every task appends |

Grepping `reports/`, `specs/` and `docs/` for the shipped suite hash returns
nothing. The shipped ps1 hash appears only inside the fix's own
`rt-20260819-002-green.log`, which is itself undeclared — circular, so it
authorizes nothing.

The scope of the exposure is wider than one task. T-002 and T-003 both reached
`Done` in this session on cycle-2 verdicts whose evaluators reached the changed
artifact through `git show` at the orchestrator's instruction. Those verdicts
rest on the same undeclared channel this evaluator refused. That refusal is the
correct reading of the skill's own rule — "reject a missing manifest, unlisted
path, hash mismatch, chat-only input" — and it means the two earlier PASSes are
weaker than they appear.

## Root Cause Hypothesis

Two rules are individually correct and jointly unsatisfiable.

The declaration rule exists so an evaluator cannot be handed arbitrary bytes: a
reviewable artifact must be named, hashed and frozen by the party that produced
it. The immutability rule exists so an implementation report cannot be
retro-fitted to match whatever shipped. Both are sound.

But the only declaration channel the validator consults is a document that, by
the second rule, can never describe anything produced after it was written. A
gate cycle that finds a defect and fixes it therefore invalidates its own
reviewability, and every subsequent cycle inherits the problem. The more
effective the gate is at finding defects, the more artifacts it renders
unreviewable — the same self-inflicting shape as WFI-035, in a different
mechanism.

Instructing the evaluator to reach the file another way does not resolve it.
Authorization is meant to come from the persisted, validator-checked manifest,
not from the launching agent's prose; a launcher that can widen the evaluator's
reachable set by asking has removed the boundary the machinery exists to
enforce.

## Proposed Change

| Target File | Change Description |
|---|---|
| Review-context authorization rule (generic workflow surface, sh and ps1 twins) | Let `evaluator_output_is_declared` consult a per-cycle declaration in addition to the implementation report — for example the current cycle's gate report, which is already the designated authority for gate-time state and is already produced by the gate itself. |
| Quality-gate report contract (generic workflow surface) | Require a gate report that applies an in-gate fix, or that follows a review-ticket fix, to carry a post-fix artifact table in the same two-column backtick-quoted form the implementation report uses, so the validator has a machine-readable row to match. |
| Quality-gate skill (generic workflow surface) | State explicitly that an evaluator must not be directed to reach an undeclared artifact through git or the live tree, and that a launcher discovering it needs one must declare it rather than instruct around it. |

The immutability of the implementation report is preserved untouched. What
changes is that a second, append-only, gate-authored channel exists, so the
declaration set can grow forward in time without any frozen document being
rewritten.

## Expected Effect

A gate cycle that fixes a defect can review its own fix. Today it cannot, and
the workaround in use — instructing the evaluator to read undeclared bytes —
silently removes the authorization boundary rather than satisfying it.

Secondary effect: the two earlier `Done` verdicts in this feature become
re-verifiable. With a per-cycle declaration channel they can be re-gated on an
authorized manifest, converting an unbound review into a bound one.

## Verification Plan

For each of the next ten gate cycles that follows a fix, record whether the
evaluator's manifest contains the shipped artifact hashes and whether the
validator accepted it without the launcher naming an out-of-manifest path. The
WFI is verified when ten consecutive fix-following cycles are authorized purely
from persisted declarations.

Two controls are required, because this WFI widens an authorization set and an
unverified widening is indistinguishable from removing the check:

1. **Negative control.** Offer the evaluator a path that is in neither the
   implementation report nor the gate report and confirm the validator still
   rejects it as role-unlisted. If it does not, the change has removed the
   boundary rather than extended it.
2. **Positive control.** Declare a post-fix artifact in the gate report with a
   deliberately wrong hash and confirm the validator rejects it. The new channel
   must be hash-checked exactly as the existing one is.

## Rollback-Plan

Revert the commit whose message contains `WFI-036`. That restores
`evaluator_output_is_declared` to consulting only the implementation report,
removes the post-fix table requirement from the gate report contract, and
removes the added skill guidance. No stored artifact changes shape: gate reports
that already carry a post-fix table stay valid markdown and are simply no longer
consulted, and no manifest, evidence bundle or ledger record is touched by
either the change or its rollback.
