## Root Cause Hypothesis

The task-review state machine assumes findings are resolvable by editing
tasks.md ("Round < 3 … edit specs/<feature>/tasks.md. Then re-invoke"). In a
post-implementation provenance re-review that assumption is inverted: the
content is review-frozen and the re-review's own boundary forbids content
changes ("it does not license content changes to frozen artifacts"), while
findings waivers are equally forbidden ("never … a findings waiver"). TYPE-H
checks are heuristic judgments re-drawn by a fresh model instance each
round, so on unchangeable content every round is an independent lottery for
new Major findings; round 3 is terminal (BLOCKED) and `--reset` is
structurally unavailable once tasks carry approved/advanced states
(check-workflow-state's pending-review rule permits only Draft/Planned).
The procedure is therefore non-convergent by construction whenever a TYPE-H
instance disagrees with a predecessor about frozen, previously-passed
content.

## Proposed Change

Add an explicit TYPE-H convergence rule to three documents (git-apply-ready
patch:
`reports/implementation/epic-189-a1-project-context/wfi-018-provenance-convergence.patch`,
verified with `git apply --check` at preparation time):

1. `plugins/sdd-review-loop/agents/task-reviewer-a.md` — new paragraph at
   the end of `# Finding Calibration`: in a declared post-implementation
   provenance re-review, a TYPE-H check that would raise a NEW finding
   against content byte-identical (modulo human-authorized
   status/approval/pointer lines) to content already bound by a prior
   attempt's persisted task-review PASS evidence records `status: PASS`
   with the observation carried as an advisory in the check's `finding`
   text (citing the prior PASS evidence path); no `findings` entry is
   emitted. TYPE-D checks unaffected.
2. `plugins/sdd-review-loop/agents/task-reviewer-b.md` — same rule with
   `result: PASS` (this role's canonical field name).
3. `plugins/sdd-review-loop/skills/task-review-loop/SKILL.md` — same rule
   stated in the Post-Implementation Provenance Re-Review section (inserted
   immediately before the "Controlled re-binding boundary" paragraph), with
   the non-convergence rationale.

Design constraint honored: the rule must set the CHECK to PASS (advisory in
finding text), NOT downgrade to a Minor FAIL — the role verdict rules
("PASS: findings is empty") and STEP 5 (no PASS branch with minors>0 before
round 3) mean a Minor-based rule would still not converge at round 1.

## Expected Effect

- A declared provenance re-review over byte-identical previously-passed
  content converges at round 1: TYPE-D checks (coverage, traceability,
  format, risk-matrix, dependency) still gate deterministically; TYPE-H
  re-judgments of frozen passed content become recorded advisories instead
  of round-consuming Majors.
- The two recorded epic-189-a1 deviations (TASK-SIZE on T-001,
  OBSERVABLE-DONE wording) surface as advisories with citations, preserving
  the observations without falsifying or re-opening landed evidence.
- Epics A2–A8 inherit the same convergence behavior for their own
  post-implementation re-bindings.
