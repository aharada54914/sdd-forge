## Root Cause Hypothesis

Edits that record a decision are applied at the site the decision text names —
the open-question table, the REQ that absorbs the answer — and nowhere else,
because nothing in the workflow demands enumeration of the other sites. The
feature's artifact set restates the same facts many times over (a design.md that
quotes the requirements, four layer specs that each restate the boundaries, an
investigation that froze the original state), and every restatement is a copy
that goes stale the moment the original changes. The author's attention is on
the site of the change; the reviewer's calibration explicitly directs attention
to cross-artifact consistency; so the defect is systematically produced by one
role and systematically caught by the other, one round later than necessary.

This is the same failure geometry WFI-013 addressed for shared *repository*
state (a claim true when written, stale when read). The unshared, feature-local
variant was left uncovered: a claim true when written and falsified by the
author's own later edit to a sibling file.

## Proposed Change

Add item 6 to AGENTS.md's `### Author-time sweeps that replace case-by-case
vigilance` (the WFI-012..015 section), in their established form:

> 6. **A recorded decision is propagated by identifier sweep, not by memory.**
>    Whenever an edit changes a recorded fact that other artifacts of the same
>    feature restate — resolving an open question, adding or amending a
>    constraint, changing a membership or status claim — the author must, before
>    submitting any review round that reads those artifacts: (a) grep the
>    feature's full artifact set (`requirements.md`, `design.md`,
>    `acceptance-tests.md`, every layer spec, `tasks.md` if present) for the
>    changed fact's identifiers (`OQ-N`, `BL-N`, `REQ-N`, the list or field
>    name); (b) resolve every hit to either the updated state or an explicit,
>    dated supersession note; and (c) for hash-frozen inputs that cannot be
>    edited without invalidating a round in progress (`investigation.md` during
>    spec review), place the supersession note in the governing artifact,
>    naming the stale span and stating the precedence rule. A sibling document
>    that still asserts the superseded state at review time is an authoring
>    defect of this class, not a reviewer discovery to wait for.

Rationale for form: (b)'s "explicit, dated supersession note" and (c) codify the
exact mechanism that survived spec-review scrutiny twice this session
(`mcp-readonly-preflight` requirements.md:160, judged "a genuine resolution
rather than a relocation" independently by three reviewers). The sweep is
mechanical — one grep per identifier — which is what qualifies it for this
section: a property easy to state once and easy to miss per case.

## Expected Effect

- Review rounds spent on stale-sibling findings drop to zero for features
  authored after the rule lands. Baseline from this session: five of seven
  NEEDS_WORK rounds across two features.
- The supersession-note mechanism for frozen inputs becomes a named, reusable
  pattern instead of an invention each author must rediscover under a
  CONTRADICTION finding.
- Reviewer attention shifts to defects only reviewers can find (this session's
  push-failure gap and the dangling REQ-014 citation are the counterexamples
  that prove the class distinction: neither is reachable by an identifier
  sweep, and both were found in rounds not consumed by propagation noise).

## Rollback-Plan

executes it, no gate enforces it, and no artifact format depends on it. Existing
supersession notes remain valid prose either way.
