基準は `d24368af68ecbe157705810a51043fa212844830`。対象はローカルの仕様生成・テンプレート・トレーサビリティ・デザインシステム契約。

## 検証前に定めた対応

| 記録する値 | 対応する成果物 | 不一致を検出する反例 |
|---|---|---|
| Core が宣言する出力と未決事項の記録先 | bootstrap、sdd-core-spec、配布テンプレート | 出力の欠落・行先の不一致 |

### 配布中の同意ポリシーと TEST-003

`c1cce46b1` を基準に、同じ許可記録で機能とセッションを両方維持すると resolver が `proceed`、いずれか片方を変えると `prompt` を返すことを検証した。配布スキルの `per-feature` 項目が未同意の場合に送信前の明示同意を求めることも検査する。Markdown の折返しは許容し、別の設定や同じインデントの共通説明にしか同意が書かれていない場合は検査が失敗した。

両言語の通常入口で TEST-003 が成功した。macOS の sh 全体は65成功・57失敗から66成功・56失敗になり、pwsh は既存の DS-006 で停止した。Python の同意スイートは21/21件成功した。TEST-002 は後続送信の説明が配布文に不足している。TEST-004 の移植案は、旧仕様にある選言の実例を見逃し、再同意を求める正しい補足を拒否したため採用を見送った。002・004 はどちらも元の検査を保持し、sh と pwsh で失敗を確認した。pwsh はこの2件を個別に実行した。

### 配布手順を再送時の動作に合わせた TEST-002

機能・セッション・送信先が一致し、前回の同意が有効な再送は、同意を再取得せず送信前検査に進む。この手順を配布スキルの `per-feature` 項目に明記した。公開 resolver の初回の許可記録を2回目・3回目に入力し、いずれも再質問や追加の監査記録が発生しないことを確認した。設定が off、外部送信禁止、機能未解決、プロバイダー不在の各ケースは手動手順へ戻った。

両シェルの TEST-002 は修正前に失敗し、修正後は macOS の sh・pwsh とも成功した。Python は22件成功。sh 全体は67成功・55失敗、pwsh は既存の DS-006 で停止した。独立レビューでは説明を削除する、共通段落へ移す、再送を常に再質問に変えるという3つの変更を個別に試し、すべて検出した。外部への送信は実施していない。

### 初回同意を求める際の開示

配布手順の Claude Design 向けの質問に、モックアップの由来と機密性、Pull で選択した送信先、外部で保持され得ること、再送と再生成を含む同意範囲、利用者が送信権限を有する旨の表明を明記した。TEST-005・006・007・008・048・050 はこの質問の中にある開示を個別に検査する。対象のプロバイダー・送信先が一致し、判定が `prompt` のときに表示する。同じ許可記録で送信先だけを変更すると再び `prompt` になる。

独立レビューで、Pull の際に利用者指定の名前が外部に渡るという説明は現行の配布手順から確認できなかった。TEST-049 の移植案を取り下げ、両シェルの従来の検査を維持した。macOS の sh・pwsh 通常入口で移植した6件がそれぞれ成功した。sh 全体は73成功・49失敗（TEST-049 を含む）。pwsh は従来の DS-006 で停止し、TEST-049 には到達しなかった。Python の同意テストは29件すべて成功し、6つの開示を1つずつ改変したときは対応する検査だけが失敗した。外部への送信は行っていない。

### ローカル設計の作成手順と送信同意の履歴

DS-006 のシード生成、Figma DTCG の取り込み、手動フォールバックの記録を配布手順に戻した。ローカルの `ui-ux-pro-max` を一時ディレクトリで実行し、`--design-system --persist -p "Example Project"` で `design-system/example-project/MASTER.md` が生成された。ページ別の上書きは任意で、生成したシードは承認後にプロジェクト側の3ファイルに反映する。独立レビューでは既存の7条件と実際の生成先を確認した。

TEST-041〜047 は辞退・送信先の変更・撤回をそれぞれ配布手順と同意判定 CLI で検査する。一度の辞退で継続的な禁止を記録せず、撤回後の次回は改めて同意を求める。独立レビューで、別サービスが同じプロジェクト ID を使うと、ID だけでは送信先を区別できないと分かった。判定器に渡す文字列は実サービスと対象 ID の組を一意に識別するものと定め、出所が分かる履歴のみ同じ表記に揃える。旧来のプロジェクト ID 単独の監査項目は Claude Design 向けに限定した。CLI で同じ ID の別サービスに切り替えると再同意が必要となった。

macOS の両シェルの通常入口で TEST-041〜047 と DS-006 が成功した。sh は全体で83成功・39失敗（変更前73成功・49失敗）、PowerShell は DS-007 を通過し、DS-008 の旧テンプレート読み込みで停止した。Python は35件すべて成功。移植した7件では説明を削る変更と判定の動作を壊す変更を各1件検出し、送信先を区別する3つの追加の負対照も検出した。外部のデザインサービスに接続する操作は実行していない。

### 結果の範囲

4スイートのカタログ登録と通常の終了判定を維持した。各失敗モードの ESM 同等性、Windows での検出結果、廃止承認を示す証拠は今回取得していない。SELF-AC-006 に基づく廃止対象は0本。
