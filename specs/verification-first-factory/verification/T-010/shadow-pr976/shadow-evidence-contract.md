# T-010 Shadow CI の証跡契約

2026-11-26、実装前に [Shadow リリース受入条件](../approved-shadow-release.md) と照合した。下記を CI の実際の収集ステップに対する回帰テストで検証する。

| 永続化する項目 | 照合対象・判定条件 | 不一致時に失敗するテスト |
|---|---|---|
| base、head、両スキャナーの秒数 | レビュー範囲のコミット SHA と各実行の非負整数秒 | SHA または秒数が不正な入力を拒否する |
| gitleaks の位置と件数 | 単一の JSON 配列。終了値 0 は空、42 は1件以上。各項目にルール、コミット、ファイル。本文所見は正の整数行番号、ファイル名だけの一致は4座標0と一致メッセージを照合し、旧形式と同じ `line: 0` に `location: "file"` を付す | 空出力、型違い、終了値と件数の逆転、不正な位置情報を拒否する |
| semgrep の位置と件数 | 正常終了、単一の JSON オブジェクト、空の errors 配列、results 配列。各項目にルール、ファイル、正の整数行番号 | errors・results が欠落、不正またはエラーを含む出力、および不正な位置情報を拒否する |
| 両ツールのパスと開始列 | 改行・タブ・空白だけの名前を含む相対 Git パスを JSON 文字列として保持する。開始列がある本文所見は正の整数の `column` を出力し、省略時は既存形式を保つ | 同じ行の別の列が別々に残る。パスの往復を照合し、NUL を含むパスや不正な列を拒否する |
| 公開する shadow-findings.json | レビュー範囲の確定と両スキャンの検証完了が前提。無関係な先行失敗後も計測し、キャンセル時は中止する。公開項目は上記のみ | CI ステップの実行条件とアップロード対象を検査し、両方が正常なときだけ許可項目が出力されることを照合する |

## ローカル検証

追加した2テストは修正前に失敗した。スキャナーに先行失敗時の実行条件がなく、空の Gitleaks 出力で公開先に空ファイルが残った。修正後、同じ2テストが成功し、`node --test tests/v2-hooks-and-ci.test.mjs` の全21件が成功した。テストはワークフローのシェルを実行し、ダミーのスキャナーで正常・異常出力を与えた。保存済みの実スキャナー出力でも各1件の位置を抽出できた。候補 SHA の完走判定には実 PR CI の証跡を使う。[Semgrep の JSON フィールド](https://docs.semgrep.dev/semgrep-appsec-platform/json-and-sarif)

独立レビュー後にファイル名だけの一致・開始列・特殊なファイル名を追加すると、修正前の検証は終了値5で失敗した。修正後は同じ全21件が成功した。Gitleaks v8.30.1 の実バイナリにも、Markdown のファイル名だけを選ぶ検証用ルールで `5e7ba6cc4..d4fbfe2ef` を渡した。`--redact=100` の終了値は42で、全3件が `line: 0`、`location: "file"` として残った。両ツールの本文について、同じ行の3列目と9列目がそれぞれ保存され、列を持たない従来形も読めることを回帰テストで確認した。[Gitleaks のファイル名ルール](https://github.com/gitleaks/gitleaks/blob/v8.30.1/detect/detect.go#L363-L383)・[マスク処理](https://github.com/gitleaks/gitleaks/blob/v8.30.1/report/finding.go#L73-L81)
