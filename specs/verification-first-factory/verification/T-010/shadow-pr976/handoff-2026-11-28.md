## 所有者に確認したい点

1. **設計同期の push 失敗時の規則**: v2 の design-sync-loop には、push に失敗したときの規則がない。v1 の規則を戻すか、v2 で新たに定めるかを決めてほしい。
2. **`required-checks-posix.tests.py`**: v1 の CI ジョブ `posix-regression` に紐づくだけで、どちらのローカルプロファイルにも入っていない。main（`4876b04e`）でも、この PR でも、`setUpClass` で同じように失敗する。そのため T-010 の範囲外とした。退役するか v2 へ移行するかを決めてほしい。
3. **更新案ワークフローの設定**: 既定のトークンで PR を作るには、リポジトリ設定の「Allow GitHub Actions to create and approve pull requests」を有効にする必要がある。CI を通常どおり起動させたい場合は、`SDD_SESSION_PR_TOKEN` を登録する。
4. **PowerShell プロファイルに残る v1 の検査3件**: `validate-repository.ps1`、`scripts.tests.ps1`、`workflow-state-repository-integration.tests.ps1`。main（`4876b04e`）でも同じように失敗する。T-010 の受入条件は local-posix だけを対象にしているため、範囲外とした。
   - 3件とも、v1 に固定された `validate-repository.ps1` が原因である。
     - リリース見出しを v1.26.0 に固定している。
     - 退役した `generate-evidence-bundle` を呼んでいる。
     - 検証の順序が v1 の構成を前提にしている。
   - 推奨は次のとおり。v1 固有の部分は退役台帳に登録して外す。現行版の検査は v2 に移行する。
5. **`tests/structural-compatibility.tests.ps1` の文字コード**: BOM のないファイルに日本語のリテラルが2か所ある。main にも同じ状態で存在し、この PR で入ったものではない。Windows PowerShell 5.1 では誤読するおそれがある。共有フィクスチャへ移すかどうかを決めてほしい。

1. この PR の head をクリーンにチェックアウトする。
2. root 以外のユーザーで、プロファイルごとに別のクローンを用意して実行する。`--jobs` は 1 にする（上記の競合のため）。

   ```bash
   python3 tests/verification.py --profile local-posix --run --jobs 1 --receipt <出力先>
   ```

   ```bash
   python3 tests/verification.py --profile local-powershell --run --jobs 1 --receipt <出力先>
   ```

   - 形式スイートには `TLA2TOOLS_JAR` と `SDD_FORGE_REAP_CHILDREN=1` が要る。
