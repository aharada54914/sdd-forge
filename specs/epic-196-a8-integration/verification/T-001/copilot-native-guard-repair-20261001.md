## Defect and evidence boundary

PR #513 head: `ef97fd9d275780cacb82c69884ac6a34ee8bae54`. The lower-case `preToolUse` command hook in `plugins/sdd-quality-loop/hooks/copilot-hooks.json:4-8` invokes `sdd-hook-guard.sh --emit copilot` (PowerShell uses its twin). The Python/JS/PowerShell guards require legacy `tool_name` and `tool_input` at `sdd-hook-guard.py:1865-1871`, `sdd-hook-guard.js:1815-1823`, and `sdd-hook-guard.ps1:1831-1834`. Existing Oct 1 consumer evidence shows the malformed-payload denial. GitHub's [hooks reference](https://docs.github.com/en/copilot/reference/hooks-reference) defines native lower-case `preToolUse` as one `toolName`/`toolArgs` call, while PascalCase `PreToolUse` is snake_case. The [CLI tutorial](https://docs.github.com/en/copilot/tutorials/copilot-cli-hooks) documents a JSON-string `toolArgs`; the reference types it as unknown. One output decision object is required. The internal `hook.start.data.input.toolCalls[]` event is **not** captured command-hook stdin, so batch input is unproven and out of scope.

`create` is a write, not a read. A [GitHub Copilot CLI issue's CLI tool-schema dump](https://github.com/github/copilot-cli/issues/556) shows `create` requires `path` and `file_text` strings; this is supporting primary-source evidence, not a capture of the Oct 1 installed version's stdin. The Oct 1 attempt never reached `create`, so the exact live write payload remains unverified. Consequently the candidate accepts only `file_text`, not a guessed `content` alias; any drift fails closed pending fresh evidence. This supersedes the earlier provisional `content` mapping in `reports/verification/a8-live-handoff-20261001.md`'s read-only diagnosis.

## Minimal design

Change only the Copilot-mode input boundary in `sdd-hook-guard.py`, `.js`, and `.ps1`. Preserve the existing snake_case route and all downstream kill-switch, Approval, SDD_SUDO, R10, and agent-role checks. If either native key occurs, require the five documented fields (`sessionId`, numeric `timestamp`, `cwd`, `toolName`, `toolArgs`); GitHub's hook reference explicitly types the camelCase timestamp as a number and the PascalCase timestamp as an ISO string. Allow unrelated metadata fields, but deny mixed legacy fields (`tool_name`, `tool_input`, `hook_event_name`, `session_id`) and any `toolCalls` key. Independently deny `toolCalls` even when accompanied only by a valid-looking legacy call, so a batch cannot hide behind that route. Parse `toolArgs` only if it is a JSON object or JSON text decoding to an object. Require exact lower-case native `view` or `create`, a nonempty `path` string, and no unsupported argument keys. `view` may additionally carry a two-integer `view_range`; normalize to legacy `read` and `file_path`. `create` must carry `file_text: string`; normalize to legacy `write`, `file_path`, and `content` so every existing write protection runs. Unknown tools, absent/wrong types, ambiguous forms, and batch-only envelopes deny. Emit **one** Copilot decision object; do not add a batch adapter without real stdin evidence.

Regression requirements, across Python, JS fallback, and PowerShell: safe native `view` with object and JSON-string args; native `create` targeting an R10-protected path; `create` containing an Approval increase; safe `create` after write checks; missing/non-string `path` or `file_text`; `content` without `file_text`; unknown/miscased tool name; unrelated metadata allowed but native/legacy mixing denied; malformed string/array args; `toolCalls[]`-only and legacy-plus-`toolCalls` envelopes denied; legacy valid read/write unchanged and legacy malformed denied. Check that each output is one parseable decision and an unsafe input is never allowed. Do not infer a batch PASS from the internal event. Existing `tests/hooks.tests.ps1` and `tests/guard-r10-port.tests.ps1` remain mandatory parity lanes after human application.
