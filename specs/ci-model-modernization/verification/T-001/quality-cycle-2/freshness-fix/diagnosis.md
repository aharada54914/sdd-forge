# Activation-definition freshness diagnosis

A local fixture adds package.json to the trusted base after the recorded baseline, making an omitted npm build depend on the classified document. The baseline build exits 0; after only the document changes it exits 1, while the planner still emits affected and omits that build (reproduction.json). This is a wrong selection, classified Critical under the evaluation rubric. Current live categories are inactive; no hosted omission occurred.

Cause: activation validation binds baseline blobs and current catalog/workflow definitions but does not examine other changes from the baseline to the trusted base. A newly introduced dependency definition can escape the old proof without changing the catalog.

Bounded correction: inspect that Git diff and reject unknown/shared definition changes. Permit only declared ordinary category inputs, unchanged catalog definitions with activation metadata differences, and exact hash-bound proof artifacts. Add an optional supporting_evidence reference array for passive verification records in reports/verification or specs/<feature>/verification so legitimate new collected evidence is explicit rather than a blanket directory exemption. Supporting records cannot disguise executable/configuration definitions. Existing proof records remain valid without this optional field. No requirement, architecture, authorization, launcher, workflow or frozen specification changes.

Persisted-field preflight: supporting_evidence[].path maps to a contained committed passive evidence file; supporting_evidence[].sha256 maps to its bytes. ProofTests.test_supporting_records_are_bound_and_cannot_hide_definitions supplies matched records and wrong digest, duplicate and executable/definition-path mutations. ProofTests.test_changed_base_definition_invalidates_activation reproduces the omitted real failing build and other new definitions. ProofTests.test_ordinary_base_input_change_preserves_activation guards the approved ordinary-product exception. Tests are captured Red before product correction; old implementation/report and actual reviewer PASS remain preserved.
