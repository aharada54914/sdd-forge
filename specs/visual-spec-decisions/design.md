## Data and callers

`src/dashboard/decision-reader.ts` collects optional
`specs/<feature>/decisions.json` before task reads. `decisions.js` is the bounded
plain-text validator shared with the page and mirrored into the installed
Sites build. `DashboardReader` adds optional `data.decisionSets` to v1; old
snapshots omit it. The existing parent-owned common page exposes `#decisions`.
See `contracts/sdd-dashboard.v1.schema.json` for data shape and
`plugins/sdd-ship/skills/status/references/spec-decisions.md` for authoring.

## State and safety

Sibling Markdown hashes bind each projection. Drift is visibly stale and cannot
be selected. Invalid data retains last-good content without freshening it.
Periodic freshness and click-time checks disable selection during stale data,
source/transport failure and pause. Choices stay in browser memory, keyed to
snapshot revision. Conversation response contains feature, decision, option and
revision. No write endpoint or automatic approval is added.

Render diagrams, tables and response text through DOM text/value APIs. Native
controls support keyboard use. Narrow layouts stack diagrams; comparison cells
remain readable through bounded table scrolling. Important specification changes
follow existing amendment/re-review rules rather than silently replacing basis
hashes. Domain choices without an owning feature specification use conversation
fallback until a real feature specification exists.

## Validation limits

Acceptance scenarios are in `acceptance-tests.md`; actual local results are in

isolated model behavior are unverified. Do not turn these limitations into gate
