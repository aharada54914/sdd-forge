# 仕様検討の視覚的意思決定 — B案承認済み

## 目的
仕様検討で長文を読んで選択肢を頭の中で比較する負担を減らす。
提示画像は情報配置の参考。画像内の保存率などの数値は本件の根拠ではない。

## 調査した問題
| ID | 観察・根拠 | 改善 |
| --- | --- | --- |
| P1 | full の interviewer は不明点の記録を要求するが、質問前の図解・選択肢比較の提示を規定していない | 判断前の視覚提示を共通化 |
| P2 | lite-spec の Process 4 は UI モックを希望時のみ実行 | 任意の製品モックと、仕様判断のための図表を区別 |
| P3 | claude-design-workflow は画像未提供時に optional visualization skipped と記録 | 画像がなくても判断の図解は生成 |
| P4 | 現状の承認は仕様・タスクに基づく。表示上の選択の承認への対応は未規定 | 選択と承認を分離し、決定を仕様へ反映 |

## 方式比較
| 方式 | 判断のしやすさ | ホスト互換性 | 追加負担 |
| --- | --- | --- | --- |
| A: 図と比較表のみ | 並べて比較できる | 高い | 小 |
| B: 対応ホストでは Artifacts 相当の視覚表示、非対応では図と表（推奨） | 選択肢の見た目・影響を比較できる | 代替表示で維持 | 中 |
| C: 独立した常設インボックスアプリ | 状態を一覧できる | サーバーと状態管理が必要 | 大 |

## 提案仕様（B）
1. 対象は full/lite の仕様策定、および domain の仕様判断。重要な仕様選択・承認前に適用する。単純な事実確認は簡潔な質問を維持。
2. 一度に一つの判断を提示する。問題 → 現状/変更後の図 → 選択肢比較 → 推奨理由 → 回答、の順。未決事項一覧には現在位置を示す。
3. 比較は通常2〜3案。同じ軸（得られる効果・不利益・影響範囲）を用い、推奨の理由を明記。「別案」「保留」も受け付ける。実在しない案で数を埋めない。
4. UI 判断には簡易画面図、処理にはフロー図、状態には状態遷移図を使う。提示画像の3列配置は参考とし、狭い表示では縦に並べる。
5. ホストで実際に利用可能な Artifacts/インライン表示を優先。非対応時は Mermaid と Markdown 比較表、レンダリングも不可なら番号付きフローと表に切り替える。利用できないツール名やホスト API を実行可能と仮定しない。
6. 表示内の選択は仮選択。選択のみ・ローカル保存のみでは承認しない。明示的な会話上の回答を確認し、決定 ID・選択肢 ID・理由・関連する要件を仕様に記録する。
7. 表示は仕様の投影。正本は既存の Markdown 仕様。仕様を変更したら図表を更新し、承認対象の版と残る未決事項を示す。重要変更は再承認。
8. 未確認事項は未確認と表示し、架空の効果値を作らない。キーボード操作、文字での選択肢識別、狭い画面、図のテキスト代替を確保。
9. 既存のタスク承認・レビュー・品質ゲートを維持。外部公開や外部サービスへの転送は視覚表示の前提にしない。新規サーバーや必須依存は追加しない。

## 変更予定箇所
- full interviewer: 視覚提示の手順と参照を追加。
- lite-spec: 同等の軽量手順を追加。lite 固有の出力契約は維持。
- domain interviewer: 判断提示の規則を適用。
- 各プラグインに独立インストール可能な参照資料を配置し、必要な配布索引・ミラーを確認。
- 既存の optional design workflow と混同しない説明、ユーザー向け利用例、回帰チェックを追加。

## 受け入れ条件・検証計画
| ID | 条件 | 検証 |
| --- | --- | --- |
| AC1 | full/lite/domain の重要な判断前に図と比較が出る | 隔離 verify-codex で各経路の合成依頼を実行し、実際の応答を保存 |
| AC2 | 表示対応・非対応・図レンダリング不可でも選択できる | 各ホスト能力条件の応答を確認 |
| AC3 | 仮選択・保留では承認や実装に進まない | 仮選択→保留→明示回答の経路と差分を確認 |
| AC4 | 決定が正本仕様と図表に一致し、変更時に更新される | 選択変更と重要変更のシナリオを確認 |
| AC5 | 操作がキーボードで可能、狭幅で読める | 対話表示の操作・320px表示を確認。未実施なら明記 |
| AC6 | 既存の承認・配布・品質契約を壊さない | 関連回帰チェック、ミラー整合性、差分レビュー |

## 実行順序
この提案の明示承認 → 実装 → 関連チェックと隔離動作検証 → PR → 必須CIとレビュー結果を確認 → 通常マージ。
マージは今回の依頼で認可済み。保護ルールの迂回はしない。
承認: ユーザーの「Bで承認」。追加条件: 既存Artifacts/Sites進捗可視化へ追加する。
既存の `sdd-ship:status`、共通スナップショット、HTML画面、Sites Workerを拡張し、独立アプリは作らない。
投影は optional な `specs/<feature>/decisions.json`、表示は既存画面の第7ビュー。読み取り専用を維持し、回答は会話を経由する。
