# Acceptance tests: verification-measurement

## Acceptance Criteria

| AC | Requirement | Observable outcome |
|---|---|---|
| AC-001 | REQ-001 | Measurements are a separate `sdd-run-measurement/v1` sidecar joined by late-bound artifact references produced in the same execution; run-record v1/v2 goldens, emitters and referenced artifacts are unchanged. |
| AC-002 | REQ-002 | Durations are monotonic-ns differences within one clock domain; mismatch/negative → null + reason; UTC steps do not alter durations. |
| AC-003 | REQ-003 | Elapsed, effort, per-phase, human-wait and human-active values are separate and arithmetically correct on the fixed timeline; unobserved is null, never 0; nested spans are not double-counted. |
| AC-004 | REQ-004 | Every terminal outcome and open spans are counted; nothing missing becomes success. |
| AC-005 | REQ-005 | Identity/reproduction fields are recorded, invocation counts are derived from launch attempts, and semantic retries return the original record. |
| AC-006 | REQ-006 | No environment, argv or secret content appears in any record; missing tokens/cost are null + reason. |
| AC-007 | REQ-007 | Owners gain only an opt-in flag; under identical controlled state no-flag outputs are byte-identical apart from the named volatile fields; only pre-execution configuration errors change an exit code. |
| AC-008 | REQ-008 | Existing fixture verdicts/diagnostics are identical per case with and without measurement; overhead is reported from paired outer timing. |
| AC-009 | REQ-009 | A frozen manifest with executable recipes, a fixed primary statistic and a comparison fingerprint runs the matrix with 5 trials against an explicitly selected code-under-test revision; every trial stays in `n` and every attempt in `attempts_started`; never in normal CI. |
| AC-010 | REQ-010 | Three lead times are independent; missing/cross-domain/reversed milestones give null + reason; linked attempts form a deterministic chain with decision changes. |
| AC-011 | REQ-011 | All tests run offline without model calls or credentials. |
| AC-012 | REQ-012 | New suites are catalog-registered; docs updated; unexercised hosts are labelled unverified. |
