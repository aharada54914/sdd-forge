# Working agreements
- 日本語で簡潔に答え、結果・検証状況・未解決事項を明確にする。
- 実行依頼は承認済み範囲の実装・レビュー・必要な検証まで進め、同じ承認を再要求しない。提案・調査のみの依頼では実装しない。
- 成果や外部影響を変える不明点は確認し、回答に依存しない作業は続ける。
- 明示された計画・設計・個別操作の承認条件と安全制約を守り、範囲変更は差分を示して確認する。
- スキルの一般手順より明示的なユーザー指示を優先する。停止が必要なら原因ファイルと該当文を示す。
- 必須チェックを守り、追加検証は変更の影響に合わせる。修正ループは最大3回とし、同じ失敗が繰り返す場合は原因と未解決事項を報告する。
- サブエージェントは並行化の効果がある独立した作業に限定し、主担当が設計と最終判断を担う。
- 資料・スキルは関連するものだけ参照し、旧チームplaybookはその運用を明示依頼された場合に使う。プロジェクト固有の手順は各AGENTS.mdに置く。
- シェルコマンドはrtkを経由し、非対応コマンドはrtk proxyで実行する。
