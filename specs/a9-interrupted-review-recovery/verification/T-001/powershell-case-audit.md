# Native PowerShell case audit

Scope: newly added recovery functions only. Existing own-stage validators were reused unchanged.

Operator sweep: string contracts use -ceq/-cne/-cmatch/-cnotmatch/-ccontains/-cnotcontains with explicit string type guards at literal trust boundaries; -eq/-ne/-in uses are numeric, null, bool, type or exit-code comparisons. Dictionaries/sets used for contract members and pins have ordinal comparers. No string whitelist relies on an insensitive default.

Separate cmdlet/language sweep: no new Select-String or Get-ChildItem filter/include/exclude call is used; filesystem enumeration uses .NET and exact ordinal entry comparison. -split only separates CR/LF, without letters. Regex Escape constructs the literal feature segment; its matching operator is -cmatch with a strict end-of-input anchor. Switch branches handle JsonValueKind or integer character codes, not case-bearing policy strings. Canonical object keys and reference order use ordinal comparison. Sort-Object is used only when reusing the existing raw reviewer validator on the already-exact five lowercase canonical path entries; it does not admit paths. String StartsWith/EndsWith/Equals explicitly use Ordinal, except the source-alias rejection check intentionally uses OrdinalIgnoreCase to detect an ambiguous alias and then requires exact -ceq. Replace/Split/Contains operate on exact characters/substrings.

Negative evidence for the operator/schema layer is TEST-055 uppercase keys and TEST-054 schema literal mismatch. Negative evidence for the method/path attribution layer is TEST-080::aliased-B-source-miscased-precheck, independently rejected by Bash and native PowerShell with complete re-pinned correlation. The same fixture had genuine exit-0 Red before the attribution repair. TEST-080::aliased-B-source-newline-precheck additionally records the PowerShell dollar-anchor discrepancy and strict end-of-input correction. Final unfiltered runtime logs provide outcomes.
