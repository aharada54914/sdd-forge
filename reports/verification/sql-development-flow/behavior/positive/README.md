# SQL implementation and independent gate: real PostgreSQL acceptance

This is one synthetic, approved query-only fixture. The feature changes an exclusive minimum comparison to an inclusive comparison. No schema migration or production operation is authorized. Initial `Approved` is a fixture condition, not a claim of a real operational approval.

The real authenticated `verify-codex` CLI performed the public `ship` path, changed one SQL comparison, ran the supplied project test against PostgreSQL 18.6, and reached Done with a gate report. Because the CLI's collaboration events omitted receiver identities, a separate fresh CLI session independently ran the complete `lite-gate` procedure, including fresh handshake, common project-check runner, real database check, and final task-state validation. The two thread IDs and distinct DB run IDs are recorded in `acceptance.json`. The reviewer changed no SQL, check, fixture, schema, runtime configuration or package script.

The original private Unix-socket case correctly stopped Blocked. A named profile without the network-proxy feature allowed too much access and was rejected by the evaluator before any model was resumed. With the proxy enabled, Linux seccomp blocked Unix sockets despite the path allow entry. Neither all-Unix-socket permission nor unrestricted filesystem access was granted.

The successful fixture instead starts its own PostgreSQL inside each sandbox command's network namespace, listens on that namespace's loopback TCP only, uses a SELECT-only application role, verifies exact synthetic keys/values/schema/permissions, and stops only its owned PID. The run-only permission profile extends `:workspace`, enables the official network proxy, leaves allowed domains and Unix sockets empty, and disables host-local binding. Boundary observations show own-namespace DB connectivity, refusal of a live host-loopback listener, direct external curl failure with exit 7 at connect (not TLS), and proxy external denial with HTTP 403/exit 56. No global profile or hook trust was changed.

`input-project` and `final-project` preserve actual source and report bytes. The recorded host paths and binary paths are evidence, not a portable installer. Native PostgreSQL was built in a temporary prefix from the official tarball, checked against its published SHA256; no system packages or Docker images were installed for this behavioral test. Build records and negative environment probes are under `environment`.

`runs` contains natural task requests, responses, command excerpts, and authentic hook denial records. `runs.json` records source identities, input/output hashes, and original raw-evidence hashes. Large command/output excerpts are explicitly marked or hashed; full raw model sessions and profile/authentication files are excluded. Runtime cache file changes are omitted from the displayed project hashes. Model identity is CLI-default, not independently attested. The evidence is for this one real-engine query and the workflow boundary; it does not certify cloud services or statistical reliability.

The gate execution records truthfully report dirty source and `reuse_allowed:false`; they are not reusable clean-commit certificates. Initial failure and subsequent environment correction are retained. Per-check databases reported cleanup true. The original task-owned Unix-socket server was also stopped after its PID, UID and data-directory identity were verified; its pidfile and socket disappeared, while a non-running zombie awaited parent reaping. Build binaries, source and evidence were retained.

The first namespace fixture had a provided-check defect: its generic subprocess client cap was 45 seconds despite the written psql limit of 10 seconds. It is preserved as limited evidence under `prior`. The evaluator corrected only the fixture's psql subprocess cap to 10 seconds (cluster setup/stop retains its own limits), added server timeout observations, then created a new initially failing fixture and reran public ship plus a fresh independent gate. The main acceptance record refers to that corrected fixture. The task-owned original synthetic datadir was removed only after stopped-state and ownership verification, with its log and removal proof retained.

For compact paths on Windows, `prior/` contains the earlier limited evaluation and `ic/` preserves the observed Implementation Complete checkpoint before gate reports existed. These packaging aliases do not alter the original captured files or historical paths recorded inside them.
