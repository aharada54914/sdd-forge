The original private Unix-socket case correctly stopped Blocked. A named profile without the network-proxy feature allowed too much access and was rejected by the evaluator before any model was resumed. With the proxy enabled, Linux seccomp blocked Unix sockets despite the path allow entry. Neither all-Unix-socket permission nor unrestricted filesystem access was granted.

The successful fixture instead starts its own PostgreSQL inside each sandbox command's network namespace, listens on that namespace's loopback TCP only, uses a SELECT-only application role, verifies exact synthetic keys/values/schema/permissions, and stops only its owned PID. Boundary observations show own-namespace DB connectivity, refusal of a live host-loopback listener, direct external curl failure with exit 7 at connect (not TLS), and proxy external denial with HTTP 403/exit 56. No global profile or hook trust was changed.
