# Public-contract native diagnostic, separate epoch

After freezing the original failed comparison, three cases gained a public
output grammar. Their expected values, strict grading and source-preservation
checks did not change. The public schema offers alternative values rather than
the expected verdict; actual task evidence selects the correct one. No grading
metadata or incident origin was provided to candidates.

Thirty new native trials ran on the same model, low effort, tool restrictions,
alternating order and 75-second per-trial limit, with new case/input/config pins.
A uses main `0535c3c1`; B uses `4ac41d51`. Both sides received the same revised
inputs. All trials completed: **15/15 exact passes per side**, including 3/3
per case, and no budget excess. Median duration was 21.140 s and 17.691 s,
respectively. Native turn token usage is retained; currency cost is unavailable.
The comparison still has `adoption_eligible: false` and a pending human decision.

This is evidence that both stage contexts can satisfy the explicit contract,
not a framework improvement over the earlier 6/15 epoch. The original failed
results remain in the separate `golden-native-20261027` packet. All five cases
were already observed; original split names remain historical, and the frozen
protocol and result explicitly reject any unseen/held-out performance claim.
No prompts or rubric were changed during collection. A fresh independent set
is required before generalizing or selecting a framework from these results.

The original protocol, manifests, every synthetic project and native trace,
source configs and case snapshot are retained with hashes. Native profile
directories and credentials are excluded. The same filesystem/PID namespaces
excluded the private rubric and map. This remains a bounded stage-context
diagnostic, not a full product lifecycle, human UX evaluation or gate verdict.
