# Current cross-runtime Copilot consumer contract

This addendum updates the executable handoff contract in the Bash and PowerShell drivers. Historical A8 design and approval records remain unchanged.

An explicitly supplied `Auto` selection is accepted case-insensitively and passed to Copilot as `auto`. Missing, whitespace, or malformed selections remain errors. The trace separates the requested selection from concrete models observed in native `model.call_final_result` events. Routing announcements alone are insufficient. Missing, malformed, duplicate-field, or non-concrete model evidence fails validation. An explicit fixed model must match the observed model.

The canonical generated output is UTF-8 `COPILOT-CONSUMED:<nonce>` followed by exactly one LF byte. There is no BOM, CR, or additional byte. Missing or extra LF fails the exact SHA-256 comparison. The previous no-LF choice was confined to the harness oracle; no external consumer depends on it. This single canonical text form permits the native patch tool to write the output without granting shell execution. Producer fixtures and their exact byte contracts are unchanged.

The consumer receives the input path and extraction instruction, never the nonce value. The native tool profile exposes `view,apply_patch` and grants writing the exact output path. This is an additive host permission, not an exclusive filesystem sandbox. Native permission probes showed that treating that grant as an exclusive boundary would be incorrect. No shell fallback or unrestricted permission is added.

Acceptance independently compares an isolated workspace snapshot before and after the consumer. Exactly the expected output file may be added; its bytes must match the canonical hash. Existing file bytes and directories must remain unchanged. Unexpected files or directories, deletions, symlinks, and Windows reparse points fail validation. This detects persistent changes within the isolated workspace; it does not claim to constrain the host outside that workspace or detect transient changes restored before inspection.

Executable CLI doubles exercise both actual drivers with independent nonce reads, valid Auto/fixed selection, missing and malformed selections, wrong first-consumer output, absent output, wrong nonce, missing/extra LF, producer tampering, workspace additions/deletion/link, and missing or inconsistent native model events. These deterministic tests do not constitute native-host evidence. The separate authenticated native runs and handshake evidence remain subject to their own admission checks; this change does not declare T-005 or the aggregate handoff complete.

Validation: the original drivers reject explicit Auto in both Bash and PowerShell (RED). Updated drivers pass their existing self-tests and 23 executable-double cases per runtime on a POSIX host with real PowerShell. Removing the workspace-comparison check in isolated copies makes the unexpected-file negative fail in both runtimes. The consumer-tampering regression also exposed the former false success before the producer-hash recheck was added. Native Windows execution remains a CI obligation; local PowerShell results do not claim Windows coverage.
