## Summary

Authored `plugins/sdd-quality-loop/scripts/evaluate-predicate.{py,sh,ps1}`
implementing ADR-0020 in full: the closed 8-operator grammar; the general
fail-closed rule for `equals`/`not_equals`/`contains`/`in` (missing path,
`null` value, or type mismatch -> `false` + `WARN`, never an exception);
the `exists` exception (presence -> `true` regardless of value including
`null`; absence -> `false` + `WARN`; type never inspected); `all`
(empty->`true`)/`any`(empty->`false`) with no short-circuit (every child
is evaluated and recorded before the boolean combination is computed);
`not`'s strict unary arity (a list value under `not` is rejected as
`PREDICATE_SCHEMA_ERROR` regardless of length) and its documented truth
table, including the AC-012 special case that a `WARN`'d child under
`not` yields `false` (not naive boolean negation) while the child's own
`WARN` reason is preserved on the child's own Evidence entry; a single
shared `evaluate()`/`validate_predicate()` code path for `trigger` and
`conditional_facets[].when` (AC-010 -- the CLI has no concept of which
context invoked it, so this is structurally the only possible code path).

The 8-entry field allowlist (AC-011) is a module-level constant mirroring
`contracts/capability-registry.schema.json`'s own list. Because Epic A1's
Project Context schema does not exist in this repository yet
(investigation.md INV-004a -- confirmed by a repository-wide search,
consistent with T-001's own earlier finding that no `epic-189`-numbered
Epic A1 spec directory exists), the drift-check obligation is implemented
as a `--check-field-allowlist <path>` CLI mode comparing the allowlist
against a `{"fields": [...]}`-shaped fixture, proven correct by two
fixtures (`project-context-fixture-match.json`,
`project-context-fixture-drift.json`) rather than against A1's real,
not-yet-existing schema file.

TDD Red->Green was followed literally: the full 63-check suite (both
runtimes) was authored and run first against a deliberately permissive
stub (`{"result": true, "evidence": []}` regardless of input) -- RED
showed 50/63 meaningful failures (the remaining 13 were incidental
vacuous passes: an empty-evidence array trivially conforms to the Evidence
JSON Schema, and two identical-stub-output fixtures are trivially
byte-identical to each other). The stub was then replaced by the real
implementation above -- GREEN shows 63/63 passing, both runtimes.
