## Summary

`evidence_deep_verify` now says out loud, at the top level of every ok
response, which two checks it structurally cannot perform. Issue #131 Finding
B-13: the tool already computed both facts —
`invariants.gitCommit.reason` ("git ancestry is host-deferred") and
`signature.note` ("the signature is echoed, never verified") — but buried them
two levels down inside objects a consumer reading `verdict: "pass"` has no
reason to open. The new `hostRequiredChecks` array promotes exactly those two
strings, verbatim, to the top level, with `verified` pinned to `false` in both
the TypeScript type and the schema, and carries issue #131's requested
"critical tasks require host-side verification" policy as schema `description`
TEXT — with zero lines of enforcement, zero cryptographic calls, and zero git
subprocess invocations added.

## Specification Differences

- **`signature` was hoisted into a local, which design.md did not anticipate.**
  design.md's API/Contract Plan states that `gitCommit` and `signature` "are both
  already local variables before the function's final `ok({...})` call". That is
  true of `gitCommit` but was NOT true of `signature`: the pre-change code called
  `signature: echoSignature(bundle)` inline inside the response object. The
  implementation therefore adds `const signature = echoSignature(bundle);` and
  changes that property to the shorthand `signature,`. This is semantically
  identical (one call, same value) and is the minimal way to reuse

  would have reintroduced exactly the duplication requirements.md's DRY rule
  forbids. Disclosed as a deliberate, minimal deviation from design.md's
  description of the existing code, not from its intended design.
