## Summary

Extended both validator twins with REQ-004 steps (d) through (i) -- the
referential integrity a draft-07 schema cannot express (design.md DD-1,
INV-003), which is the entire reason this validator exists rather than a
plain JSON Schema run. Six checks were added: duplicate concept `id`
(`V2-DUP-CONCEPT-ID`), dangling `concepts[].context`
(`V2-DANGLING-CONTEXT`), dangling `distinguished_from[].concept_id` including
the self-reference case (`V2-DANGLING-DISTINCTION`), dangling
`contexts[].terms[].concept_id` (`V2-DANGLING-TERM`),
`responsibilities` / `must_not_own` self-contradiction
(`V2-SELF-CONTRADICTION`), and duplicate concept `name` within one context
(`V2-DUP-NAME-IN-CONTEXT`). The pattern check for the two reference fields
that share the concept-id pattern (AC-022) is implemented here as well, which
is where T-003 deliberately left it.

Everything is appended through T-002's existing accumulator only, inside the
`check_cross_references` / `Invoke-CrossReferenceCheck` extension points
T-003 handed over. No second output path, no new `exit` site, no change to
the argument handling, the fail-closed acquisition, the parse, the `schema`
dispatch, or the structural pass. The `.ps1` twin keeps both properties the
seam requires: no `exit` inside `try` (every status still returns to the one
top-level `exit $exitCode`), and both extension-point calls stay
`[void]`-wrapped.

Three design decisions are load-bearing and were chosen deliberately rather
than fallen into:

1. **Pattern before reference resolution.** A reference value that does not
   match the concept-id pattern is a MALFORMED reference; a well-formed value
   that matches no declared id is an UNRESOLVABLE one. These are different
   defects, and AC-022's `### Done When` demands they stay textually
   distinguishable from AC-008 / AC-009. The malformed case is reported as
   `V2-PATTERN` -- in the exact wording the structural pass already uses --
   and is then excluded from resolution, so neither value is ever reported
   twice and no fixture can produce both rule ids. This is REQ-004(c)'s
   type-before-pattern precedence extended one level down: type, then
   pattern, then resolution. The same rule applies to `concepts[].context`:
   when its value fails the kebab-case pattern the structural pass has
   already reported `V2-PATTERN`, so the dangling check skips it rather than
   piling a derived failure on top of the real one.
2. **Referent indexes are built only from arrays that really are arrays.**
   When `concepts` or `contexts` is absent or mistyped, the structural pass
   has already named that root cause; resolving references against an index
   that could not be built would emit a cascade of dangling errors against
   fields the author did not get wrong. Each index is therefore `None` /
   `$null` in that case and its dependent check does not run. The contract is
   still rejected -- fail-closed is preserved by the structural violation
   itself.
3. **Duplicate names are keyed by the (context, name) pair.** That pairing is
   precisely what makes the same name in two DIFFERENT contexts legal
   (requirements.md Edge Cases, INV-012) while a repeat inside one context is
   not. It is not a special case bolted on afterwards; it falls out of the
   index key, which is why the permissiveness cannot regress independently of
   the check itself.

Membership everywhere is raw, case-significant string equality:
`HashSet[string]` uses the ordinal comparer on the `.ps1` side and Python
`set` is exact on the `.sh` side, so the two twins agree. REQ-004(h)'s
self-contradiction check is likewise exact -- not case-folded, not trimmed,
not otherwise normalized -- which the accepted near-duplicate control
contract proves rather than merely asserts.

One hazard specific to this pass was found by probe and is guarded in the
`.ps1` twin: a `HashSet` is enumerable, so returning one plainly from a
PowerShell function unrolls it to its elements. Both set-returning helpers
comma-wrap their return, the same guard `Get-ContractValue` already carries
for empty arrays.

Every negative fixture asserts the shared shape: exit 1, empty stdout, no
stack trace or raw interpreter error anywhere in stderr, and stderr carrying

## Quality Gate Focus

- **The malformed-versus-unresolvable discrimination is the load-bearing
  claim.** Verify it on AC-022 (1) and (2), which must report `V2-PATTERN` on
  `concepts[0].distinguished_from[0].concept_id` and
  `contexts[0].terms[0].concept_id` with no `V2-DANGLING-DISTINCTION` or
  `V2-DANGLING-TERM` line anywhere, and on AC-008 / AC-009, which must report
  the dangling rule ids with no `V2-PATTERN` line anywhere. The single choke
  point is `reference_well_formed` (`.sh`) / `Test-ReferenceWellFormed`
  (`.ps1`): if a future change resolves a reference by any other route, the
  discrimination is lost even though these fixtures may still pass. Note that
  AC-022 (2)'s value `concept-order` is case-insensitively equal to the real
  id `CONCEPT-ORDER`; a case-insensitive resolution would silently accept it,
  which is why the index comparer is ordinal on both sides.
- **Cross-context permissiveness is proved negatively here and must not be
  read as the capability proof.** The control contract shows the AC-011 check
  does not fire; T-005's AC-005 owns the proof that such a contract is a
  usable representation. Both matter, and only the first is in this task.
- **Fixture non-vacuity depends on a check this task did not author.** The 8
  negatives are mutations of the base contract whose acceptance is asserted
  by T-003's base-acceptance check. If that check is ever weakened or
  removed, these negatives stop proving that the mutation is what caused the
  rejection.
- **The strict total-line-count assertion is deliberate and will be load
  bearing for T-005.** It is what proves no cross-reference check fires on a
  value the mutation did not touch. A future change that legitimately adds a
  violation to one of these contracts must update the expectation rather than
  relax the count.
- **`concepts[]` ordering is assumed to be document order.** Both duplicate
  checks report at the LATER occurrence and name its index, so a validator
  that reordered concepts would change which index is named. Neither twin
  reorders, and JSON arrays are ordered, but the messages are index-bearing
  and a reviewer comparing them across twins should know the assumption.
