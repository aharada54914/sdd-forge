## What held up -- and where the evaluator beat the report

I asked for the security boundary to be attacked rather than read, and it was.
Using a real `git submodule add` (gitlink mode 160000) and real symlinks (mode
120000): a dirty submodule with modified tracked and added untracked content
inside produced `changed_paths: []` with no descent and no inner path leaked;
a pointer bump produced exactly the gitlink path, even when combined with
dirty inner content. Escape attempts failed to break it -- a symlink pointing
outside the repository, with the outside referent modified, produced `[]`, and
writing *through* an in-repo symlink was correctly attributed to the real
owning component rather than smuggled into the linking one.

Twice the evaluator established more than the report claimed:

- The report called end-to-end invalid-UTF-8 untestable because APFS rejects
  such filenames. The evaluator bypassed the filesystem via
  `git update-index --add --cacheinfo`, and the real CLI failed closed with
  `invalid UTF-8 in a git-reported path`. The report's substitution was more
  conservative than necessary; its behavioural claim is sound.
- Specification Difference #2 recorded rename-limit-exceeded as "not
  achieved". With 1400 renamed files (2800 candidates) git emitted its real
  warning and the collector exited 1 with the pinned-limit diagnostic in both
  runtimes -- which also proves the pinned limit is applied at runtime, the one
  thing the source-grep test could not show.

TOCTOU was induced as a genuine concurrent-writer race: over 8 runs, 5
recovered via the single retry and 3 failed closed with the snapshot-mismatch
diagnostic. All four unresolvable-rev classes fail closed with distinct
diagnostics in both runtimes.
