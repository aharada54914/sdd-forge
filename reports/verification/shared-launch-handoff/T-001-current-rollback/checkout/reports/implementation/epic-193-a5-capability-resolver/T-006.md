## Gate Cycle 1 Remediation (2026-08-27)

The independent quality-gate evaluator returned NEEDS_WORK with one Major:
AC-028 (`requirements.md:840`; design.md:1996-2007) pins "three
installed-standalone-plugin-layout discovery fixtures, one per runtime
(`.py`/`.sh`/`.ps1`)," but the delivered `run_installed_layout_case` only
ever ran for `kind in ("sh", "ps1")` -- the `py` dispatcher (a direct
`python3 resolve-project-context.py` invocation, never routed through
either shell wrapper) was never exercised anywhere in this suite, even
though nothing structurally blocked it (`resolve-project-context-parity-
check.py`'s own `_run_kind` helper already establishes the exact `kind ==
"py"` invocation shape in the same helper family, unstubbed). This
misstatement also propagated into this report's own original "Summary"
bullet (now corrected above), this driver's own `run_installed_layout_case`
docstring, and `CHANGELOG.md`'s T-006 entry (now corrected there too).

Fix: added `_installed_layout_argv(kind, scripts, tail)`
(`tests/resolve-project-context-discovery-check.py`), mirroring the parity
driver's own `_run_kind` branch (`kind == "py"` invokes `[sys.executable,
resolve-project-context.py] + tail` directly; every other kind still uses
`block_check.launcher_args`). `run_installed_layout_case` now loops over
`("py", "sh", "ps1")` internally, independent of `main()`'s own
`--launcher` argument -- `python3` is available regardless of which
top-level launcher (`.sh` or `.ps1`) is running this shared driver, so
BOTH this suite's own sh-invoked and ps1-invoked runs now demonstrably
execute the `py` dispatcher case (an `installed-layout-py-*` label
appears in either run's own output, confirmed below). Also reworded the
`installed-layout` assertion label per the evaluator's own Minor: it
previously said step 5 "resolved and validated correctly," which
overclaimed -- `validate-capability-registry.py` is an unconditional-
success stub in this fixture (Specification Differences, item 1); the
label now says "resolved correctly" / "discovery+version-check," and
names the stub explicitly, never claiming this fixture validates Registry
CONTENT.
