## The Major

**The ps1 twin resolves JSON object members case-insensitively, so a key spelled
with a different case makes the twins disagree — fail-open on the ps1 side.**

`validate-domain-contract.ps1:143` and `:167` read members with
`$Object.PSObject.Properties[$Name]`, which is case-insensitive in PowerShell;
the sh twin uses ordinal Python dict lookup. T-004's cross-reference pass
consumes those helpers at `Get-JsonStringMember` (`:412`),
`Get-DeclaredStringValueSet` (`:432`) and ten call sites.

Reproduced by the gate itself, independently of the evaluator, on a contract
whose `contexts[0]` declares `"Name"` instead of `"name"` so that
`concepts[0].context` refers to a context never declared:

```
$ bash …/validate-domain-contract.sh casekey-Name.json
V2-DANGLING-CONTEXT: concepts[0].context: context order-taking is not declared in contexts
exit=1
$ pwsh -NoProfile -File …/validate-domain-contract.ps1 casekey-Name.json
exit=0
```

The evaluator measured the class more broadly, and the polarity inverts as well:
`"ID"` for `"id"` gives sh exit 1 / ps1 exit 0; `"Must_Not_Own"` gives sh exit 0 /
ps1 exit 1 `V2-SELF-CONTRADICTION`; a term's `"Concept_Id"` gives sh exit 0 / ps1
exit 1 `V2-DANGLING-TERM`. All six of T-004's checks emit a different RULE-ID
across twins for this class, breaking DD-7's machine-consumable output contract.

**Attribution was measured, not assumed.** The same contracts run against the
T-003-state twins at `cdfd7f60` show both twins agreeing (exit 0 / exit 0) for
the `"Name"`, `"Must_Not_Own"` and term-`"Concept_Id"` cases. The helper is
T-002-authored but was inert until T-004's checks consumed it; T-004 is what
converts it into an exit-code divergence.

**This is not the already-adjudicated `ConvertFrom-Json` key class.** That one
over-rejects — a document carrying both `id` and `ID` yields ps1 `V2-PARSE`
exit 1 versus sh exit 0. These cases parse cleanly on both twins and diverge at
property lookup, with under-rejection polarity: the ps1 twin returns 0 on a
contract REQ-004(e) requires rejected. The distinction matters and is recorded
explicitly, per the evaluator's own request.

It will not be caught downstream — no fixture in the feature uses a case-variant
key, so T-005's AC-013 parity corpus does not cover it.

Recorded in `docs/review-tickets/RT-20260819-002.yml`.
