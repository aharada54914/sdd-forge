## Friction Patterns

### FP-01: Report artifacts carry human-readable identity but not the machine-readable identity their deterministic consumers require — one root cause, three separate failures in one feature

- **Evidence:**
  1. `check-evidence-bundle.sh:201,228` rejected all 5 evidence bundles (`quality_report missing Task ID: T-001`, `quality_report must contain exactly one Feature line`). Fixed only by retrofitting header lines into 4 reports — commit `7b7faa23`.
  2. The evaluator launch boundary reads the changed-source set from the implementation report's `## Outputs` `| path | sha256 |` rows. Three reports had authored that section as prose bullets, so the evaluators could not have read the production diff at all. Fixed only by retrofitting hash tables — commit `9e82fa5b`.
  3. `emit-run-record.sh:125` selects gate files by `^Feature: <slug>$` and `:129` associates a task by `Task: T-NNN`. `reports/runs/RUN-20260729T235825Z-epic-136-phase4-mcp.json` therefore records `gate_reports.total: 1` and `first_pass_gate.passed_first_try: 1` against a manual count of 5 gates over 5 tasks. Note the compounding: file *selection* only worked at all because retrofit (1) had already added the `Feature:` lines; without it the count would have been 0.
- **Frequency:** 3 distinct consumer failures, 8 artifacts affected (4 gate reports + 3 implementation reports + 1 run record), spanning all 5 tasks.
- **Phase:** implementation-report authoring → evaluator launch → Done gate → retrospective measurement.
- **Confidence:** High — three independent evidence types, mechanically reproduced, each traceable to a named script and line.
- **Do Not Overfit:** This is not one agent forgetting a field. Four different authoring agents (the T-001/T-002/T-003/T-005 evaluators) and three different implementation agents all produced artifacts that a human reads correctly and a script cannot, because no template or checklist states the machine-readable contract. It is also not new: it is the registered recurrence condition of WFI-005, itself Verified on 2026-07-12 — see the Retention Check.

### FP-02: 16 Minor findings, 0 Critical / 0 Major — and the largest single class is "the report describes a tree that no longer exists"

- **Evidence:** T-001 2 of 3 Minors (placeholder count disclosed as 2, measured 5; manifest binds none of the 4 declared Outputs because T-002/T-004 legitimately moved them). T-002 2 of 3 (Outputs snapshot mismatch on 3 of 10 rows; placeholder disclosure undercounts 2 vs 5). T-003 QG-002 (report prose and `red.log` quote a TEST-006 case name that commit `d55ed3ef` renamed). T-005 1 of 2 (`T-005.md:398` asserts `design.md:3` still reads `Impl-Review-Status: Pending`; it reads `Passed` and had since before task-review — a claim inherited across three reports without re-checking).
- **Frequency:** 7 of 16 Minors, in 4 of 5 gate reports.
- **Phase:** implementation-report authoring, read at gate time.
- **Confidence:** High — 4 tasks, and every instance is a quoted file:line the evaluator re-measured.
- **Do Not Overfit:** The structural cause is specific and repeatable: T-001..T-004 all edit `src/tools/evidence.ts`, `contracts/sdd-forge-mcp-tools.v1.schema.json` and the committed `dist/index.js`, so each landing invalidates the previous task's recorded hashes by construction. The reports' Snapshot Notices anticipated this in the abstract; what they did not do is stop the *narrative* counts and claims from being restated as current. The evaluators handled it correctly (recording current values in the gate report rather than editing the frozen report, per SKILL.md:179-185) — the cost is Minor-noise volume, not a wrong Done.

### FP-03: The orchestrator invalidated a persisted review-context manifest by re-running the reservation step, costing a full high-risk gate cycle

- **Evidence:** `qg_driver.py … reserve` was executed more than once for sequences 382 and 384 while its output was being inspected. Each run rewrote the persisted manifest against an already-advanced identity ledger, making `previous_record_sha256` self-referential and the manifest unreplayable by `validate-review-context-set.sh`. T-001's first gate returned NEEDS_WORK for exactly this reason; the T-003 evaluator independently detected the same defect and filed it as its QG-004. Resolved by reserving sequence 387 exactly once, confirming `previous_record_sha256` equalled record 386, and re-running — PASS.
- **Frequency:** 2 sequences affected, 1 wasted high-risk gate cycle.
- **Phase:** quality-gate evaluator launch.
- **Confidence:** Medium — 2 occurrences within one session, one root cause, one actor.
- **Do Not Overfit:** The reservation step is atomic and stateful by design; the failure is that nothing in the driver or the skill marks it as non-idempotent, so "run it again to see the output" is a natural and destructive action. Two independent detectors caught it, which is the gate working — but the detection was downstream of a wasted cycle.

### FP-04 (recorded for visibility, no WFI — harness/environment)
