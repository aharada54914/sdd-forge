## Problem Evidence

Evidence class: LIVE INCIDENT REPORT, not retrospective-backed friction. The
incident (2026-09-03) postdates the most recent retrospective
(`reports/retrospective/2026-08-14T034801Z-pillar-a-wave-session.md`), which
explicitly excludes epic-193's still-in-flight tasks from measurement; the
next retrospective run covering epic-193-a5's spec-review attempts is where
this incident becomes a citable metric row. Primary sources until then are
the persisted attempt artifacts named below
(`reports/spec-review/epic-193-a5-capability-resolver/attempt-14/round-1/`)
and the gate script's own code.

The spec-review round state machine cannot process a finding whose cure
lives in `investigation.md`, even though `investigation.md` is one of the
spec reviewers' hash-bound allowed inputs and the calibration's Amendment
Re-Review Context rules explicitly direct reviewers to judge it.

Observed on 2026-09-03 during `epic-193-a5-capability-resolver` spec
attempt 14 (post-Done provenance re-bind):

1. Round 1's only Critical (reviewer A, seq0877, CONSTRAINTS-EXPLICIT) was
   that `investigation.md`'s Ruling (G) entry cited two later-phase
   verification artifacts as bare paths, violating the calibration's
   element 4. The cure is an `investigation.md`-only edit (add each
   artifact's SHA-256 and the binding commit). `requirements.md` and
   `acceptance-tests.md` were both correct as reviewed.
2. Re-invoking round 2 after that cure was rejected:
   `spec-review-precheck.sh` line 333 requires
   `requirements_sha256 != prior || acceptance_sha256 != prior` and fails
   with `reviewed inputs are unchanged from the prior round`. The
   round-transition predicate does not consult `investigation.md`.
3. `--reset` was also rejected: `reset requires a terminal PASS or BLOCKED
   contract`, and a round-1 NEEDS_WORK is non-terminal. There is therefore
   NO lawful transition out of the attempt: round 2 demands a change to
   two documents that need none, and reset demands a terminal verdict the
   state machine will not produce before round 3.
4. The session escaped only because a *legitimate* `requirements.md`
   companion edit happened to exist (the Ruling Annotations mirror
   enumeration had gone under-inclusive after ruling (G)); committing it
   changed `requirements_sha256` and unlocked round 2, which then passed
   clean (seq0879/0880). Had no such edit existed, the only options would
   have been an artificial requirements edit (gaming the predicate) or
   burning rounds 2 and 3 as unreachable and re-reviewing from a fresh
   attempt only after round 3's BLOCKED — two full reviewer cycles wasted.

## Root Cause Hypothesis

The round>1 changed-inputs predicate compares only the two review-subject
document hashes because it was written before the Amendment Re-Review
Context mechanism made `investigation.md` a first-class review subject; a
finding curable only by an `investigation.md` edit therefore has no lawful
transition path out of a non-terminal round.

## Why-Why Analysis

1. Why did round 2 refuse to start? Because the precheck's changed-inputs
   predicate compares only `requirements_sha256` and `acceptance_sha256`
   against the prior round's contract. — Evidence:
   `plugins/sdd-review-loop/scripts/spec-review-precheck.sh:331-334` (the
   disjunction and its `reviewed inputs are unchanged from the prior round`
   failure), reproduced verbatim in the 2026-09-03 incident.
2. Why does it compare only those two? Because the state machine models
   "human edits between rounds" as edits to the two review-subject
   documents, the shape every pre-amendment attempt had. — (hypothesis,
   inferred from the same script's round-transition design; no counterexample
   attempt exists before the amendment mechanism.)
3. Why is that model now wrong? Because the Amendment Re-Review Context
   mechanism made `investigation.md` a first-class review subject: reviewers
   are instructed to FAIL a round on its evidence-bar nonconformance, so its
   bytes must be able to change between rounds. — Evidence: the
   spec-review calibration's Amendment Re-Review Context evidence-bar rules,
   and the attempt-14 round-1 Critical persisted at
   `reports/spec-review/epic-193-a5-capability-resolver/attempt-14/round-1/reviewer-a.json`
   (run seq0877), whose sole cure was an `investigation.md` edit.

Terminal cause = the Root Cause Hypothesis above (level 3's mechanism).

Subordinate note (detection latency, not a cause): the gap surfaced only at
attempt 14 because every prior amendment attempt happened to edit the two
review-subject documents in the same round-fix, masking the missing third
hash; attempt 14 was the first whose sole defect lay in the amendment record
itself. — Evidence: attempt-12 round-2/3 artifacts under
`reports/spec-review/epic-193-a5-capability-resolver/attempt-12/`.

## Proposed Change

| # | Target File | Change Description |
|---|---|---|
| 1 | `plugins/sdd-review-loop/scripts/spec-review-precheck.sh` (+ `.ps1` twin) | Extend the review gate plugin's specification-review round-transition check so the round>1 changed-inputs predicate also consults the investigation document: change the two-way hash disjunction (requirements, acceptance) into a three-way disjunction that includes the investigation document's hash. A round with zero changed inputs is still rejected, and reset semantics are untouched. |
| 2 | `plugins/sdd-review-loop/scripts/spec-review-precheck.sh` (+ `.ps1` twin) | Record the investigation document's hash in the round contract the same way the two existing hashes are recorded (the reviewers' manifests already carry it, so the orchestrator copies it identically), giving the next round's predicate a prior-round value to compare against. |

## Expected Effect

Reduce the count of specification review gate attempts with no lawful
round-2 transition (an attempt whose only curable defect lies in the
investigation document) from 1 observed (the 2026-09-03 incident) to 0 over
the next 3 amendment-triggered specification review attempts. Mechanically:
a finding whose cure is an investigation-document edit becomes fixable in
the next round like any other finding — re-running the attempt-14 round-2
transition with ONLY the investigation-document pin-fix applied (no
requirements edit) exits 0 instead of failing with
`reviewed inputs are unchanged from the prior round`.
