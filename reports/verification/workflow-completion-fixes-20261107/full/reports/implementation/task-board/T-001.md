## Summary

Implemented typed JSON snapshots, Unicode title trimming and code-point limits, UUID validation and uniqueness, explicit completion assignment, deletion, and detached return values. One TaskStore instance serializes operations with a thread lock. Each operation validates disk contents again so a corrupt file blocks reads and valid mutations instead of being overwritten from cached state. Missing files remain absent until a successful save.

Each mutation builds an independent candidate, writes UTF-8 JSON to a unique file in the target directory, flushes, fsyncs, closes, and atomically replaces the target before publishing the candidate in memory. Precommit failures preserve the original file and remove only that operation's temporary file; cleanup failure itself is surfaced as StorageError. No filesystem action follows the successful replace commit point.

## API Handoff

`TaskStore(path: str | os.PathLike[str])` constructs a lazy store. Share one instance among HTTP request threads. `snapshot() -> list[Task]`, `add(title: object) -> list[Task]`, `set_completed(task_id: object, completed: object) -> list[Task]`, and `delete(task_id: object) -> list[Task]` return detached full saved lists in creation order. Task is a TypedDict with id:str, title:str and completed:bool. Persistence envelope is version=1/tasks; HTTP code wraps the returned list as `{tasks: ...}`.

ValidationError means invalid mutation argument (HTTP adapter 400); TaskNotFoundError means valid absent UUID (404); StorageError means read/schema/write failure (500). Exception messages are Japanese and omit task text and filesystem paths; the adapter must not expose chained exceptions. Construction does not load disk, allowing request-time StorageError handling. No success return occurs before replacement.
