# 今日のタスク

日本語のローカル個人用タスクページです。追加、完了切替、確認付き削除を行い、保存済みのタスクを SQLite に保持します。

## 起動と再起動

Python 3、SQLite 対応の標準ライブラリ、書き込み可能なローカルディスクと JavaScript 対応ブラウザーが必要です。アプリの追加パッケージは不要です。リポジトリ直下で実行してください。

```sh
python3 -B app.py --db data/tasks.sqlite3 --port 8000
```

ブラウザーで `http://127.0.0.1:8000/` を開きます。タイトルは前後の空白を除いて1〜200 Unicode コードポイントです。Enter または「追加」で保存します。「削除」は確認後に反映されます。

停止はターミナルの Ctrl-C。再起動は同じディレクトリで上の同じコマンドを実行し、ブラウザーを再読み込みしてください。同じ `--db` パスを指定すると、保存済みの追加・完了・削除状態が復元されます。送信していない入力は保存されません。通信失敗時はエラーと入力を確認し、必要なら再読み込みしてから操作してください。自動で書き込みを再試行しません。

## 検証

標準ライブラリによる単体・実 HTTP 検証:

```sh
python3 -B -m unittest discover -s tests -p 'test_*.py' -v
```

実ブラウザー検証だけは別途 Playwright と Linux Chromium (`/usr/bin/chromium`) が必要です。本検証環境は Playwright 1.62.0 を使用しています。専用のテスト環境にインストールする例:

```sh
python3 -m venv /tmp/task-board-browser-tools
/tmp/task-board-browser-tools/bin/pip install playwright==1.62.0
# OS のパッケージ管理で Chromium をインストールし、/usr/bin/chromium を確認
/tmp/task-board-browser-tools/bin/python -B tests/browser_task_board.py --output /tmp/task-board-browser-results --screenshots /tmp/task-board-browser-screenshots
```

この検証は毎回新しい一時 SQLite ファイルと空きループバックポートを使い、実際の追加・切替・削除、Unicode 境界、デスクトップ／モバイル、キーボード、エラー復帰を確認します。実サーバーを停止し、同じ一時 DB パスで異なる PID のプロセスを起動して、保存状態を照合します。`observations.json` にコマンド、PID、状態、ブラウザー通信、スクリーンショット関連の計測を記録します。読み書きの障害・不正な成功応答・タイムアウトの検証ではブラウザーの通信差し替えを明示的に使用します。通常 CRUD と再起動は実サーバーです。

## 安全な停止・ロールバック

起動後のロールバックは Ctrl-C でアプリを止め、DB ファイルを保持する操作です。既存 DB を削除・空ファイル化・置換しないでください。新規 DB は初期スキーマ作成成功後にのみ公開され、初回作成失敗なら指定先は未作成のままです。既存 DB の破損やスキーマ不一致で起動が失敗した場合はそのファイルを保持し、別途調査してください。自動移行、破壊的復旧、バックアップ復元は行いません。この保存・失敗時保護は上記の単体／HTTP 検証にも含まれます。

## 利用範囲

一人がローカル端末で使う使い捨て用途です。127.0.0.1 のみで待ち受け、実行時の外部アセット、分析送信、クラウド連携はありません。デプロイ、認証、共有、多人数利用は対象外です。DB は OS のファイル権限で管理され、自動バックアップ、暗号化、完全消去は提供しません。
