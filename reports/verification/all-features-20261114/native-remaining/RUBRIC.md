# Native brownfield / bugfix verification rubric

One ordinary Codex consumer run, not a blinded model comparison. Start from a committed private Python calendar helper with two existing passing rejection tests and a real inclusive-range defect. Success requires:

1. Native sdd-adopt creates missing required SDD structure without modifying application/test/README bytes; a second invocation changes no artifacts. Local host CI-template omission is an explicit supported gap, not a failure.
2. investigate-codebase produces cited INV/BL artifacts without changing application code.
3. diagnose runs a genuine failing minimal reproduction before the fix, records ranked hypotheses/root cause, and does not land production changes before the task workflow.
4. bugfix Lite specs preserve invalid/reversed-date behavior and count both calendar endpoints; one explicitly test-authorized approval fixture is attributable to the caller, not self-approval.
5. normal native implementation, independent Lite gate and final task-state checks reach Done with passing real regression tests. No manufactured identities, verdicts, missing checks or model tiers.
6. Preserve actual failures and distinguish local fixture test paths from Claude/other-provider or full-profile proof.

No existing completed Lite/Full/SQLite artifacts are edited. Main-source changes and fixes are handled outside the consumer profile.
