# Requirements: ローカルタスク管理

Spec-Review-Status: Pending

## Overview

ブラウザ UI で小型のタスク一覧を管理する。ユーザー提示要件から作成したレビュー待ち仕様。full SDD フローを適用する。

## Target Users

ローカル環境でタスクを管理する利用者。

## Problems

追加・完了切替・削除を簡単に行い、再読み込み後も状態を維持したい。

## Goals

- REQ-001: ブラウザ UI からタスクを追加できる。
- REQ-002: 各タスクの未完了・完了を双方向に切り替えられる。
- REQ-003: 選択したタスクを削除できる。
- REQ-004: タスクと完了状態をサーバー側の JSON ファイルに保存し、ブラウザの再読み込み後に復元する。
- REQ-005: アプリはローカルのみで動作する。
- REQ-006: 既存ライブラリを優先し、時間を優先した小規模構成にする。
- REQ-007: 通常 full SDD の承認・レビュー・品質ゲートを維持し、実行コマンドと各ゲートの結果を保存する。承認後に実ブラウザで主要ユーザー経路を検証する。

## Non-goals

外部公開、git push、Issue 登録。過去の別ディレクトリの診断アプリ・fixture の流用。

## User Stories

利用者としてタスクを登録し、完了と未完了を切り替え、不要なタスクを削除し、ブラウザ再読み込み後にも作業を続けたい。

## Acceptance Criteria

- AC-001 / REQ-001: ブラウザから「買い物」を追加すると一覧に未完了タスクが1件増える。
- AC-002 / REQ-002: そのタスクを完了にしてから未完了に戻すと、各状態が画面に反映される。
- AC-003 / REQ-003: 2件のうち1件を削除すると選択した1件だけが消える。
- AC-004 / REQ-004: 追加と完了切替後の再読み込みで同じ ID・本文・完了状態が復元される。削除後の再読み込みでは復活しない。保存先の実 JSON ファイルとも一致する。
- AC-005 / REQ-005: 起動時の待受アドレスがループバックに限定され、通常操作が外部サービスに依存しない。
- AC-006 / REQ-006: 採用依存と実行手順が明記され、空のこの作業場所に新規作成する。
- AC-007 / REQ-007: ゲート結果・コマンド・実ブラウザ検証証拠をファイルで確認できる。未実行は未実行と記録する。

## Roles and Permissions

ローカル単一ユーザー。認証・外部公開・共有機能は不要。

## Main Workflows

ブラウザを開く → 一覧を読む → 追加 → 完了切替 → 削除 → 再読み込みで状態確認。

## Edge Cases

空白のみは UI/API 双方で拒否。保存中の変更操作は無効。保存失敗時は成功表示せず入力を保持し再取得できる。破損 JSON は上書きせず起動失敗。未知 ID は404。具体的契約は contracts/task-board-api.md。

## Security Boundaries

| Trust Boundary | Auth/Authz Requirement | PII / Data Classification | Regulatory Constraints |
|---|---|---|---|
| ブラウザ → ローカルサーバー | ループバック限定。Origin/Host 検証 | 本文は任意入力。機密情報の入力は用途に含めない提案 | 指定なし |
| サーバー → JSON ファイル | 固定パスと入力検証 | 利用者のローカルデータ | 指定なし |

## Assumptions

新規プロジェクト。ソースコード・依存定義は存在せず、起動前からある cli.jsonl と cli.stderr はセッションファイルとして保持した。

## Open Questions

なし。UI・ローカル単一ユーザー・Python標準ライブラリ＋素HTML/JS・JSON保存は追加入力で確定。タスク承認は未取得。

## Confirmed Interview Decisions

- 日本語、トップページの単画面一覧。入力＋追加、各行に完了checkboxと削除button。
- 白背景＋青アクセント、モバイル対応、ds_profile: none。
- Python標準ライブラリ＋素HTML/JS。外部実行時依存なし。
- REQ-008: 空白のみの追加を防ぎ、保存中の重複変更操作を防ぐ。
- REQ-009: 日本語・白背景と青アクセントの単画面をモバイルとキーボードから操作できる。
- REQ-010: 不正入力、外部Origin、不正Host、保存失敗を安全に扱う。

## Additional Acceptance Criteria

- AC-008 / REQ-001,002,003,009: トップページから入力・追加・各行の完了checkbox・削除buttonへ到達できる。
- AC-009 / REQ-008: trim後0文字と201文字以上の本文は UI/API 双方で拒否し、保存中は変更操作が無効。
- AC-010 / REQ-004,010: 保存失敗で一覧を成功状態に進めず入力を保持し、明示エラーと再読込経路を出す。破損JSONは上書きしない。
- AC-011 / REQ-009: 日本語ラベル、白背景と青アクセント。320px/1280pxで横スクロールなし。Tab/Enter/Spaceで操作可能、フォーカスが見え、状態通知が読み上げ可能。
- AC-012 / REQ-005,010: 不正Host、他Originの変更、非JSON/不正型/8KiB超入力は拒否。本文にHTMLを入れても実行せず文字列表示。未知IDは404。
- AC-013 / REQ-004: 2件を続けて保存しても欠落せず、サーバー再起動後に同じJSON内容を復元する。保存失敗時は直前の確定内容が維持される。

## Risks

JSON 保存中断によるデータ破損、ローカルアプリへの他サイトからのリクエスト、未信頼本文の HTML 解釈。設計提案に対策と将来の検証を記載した。
