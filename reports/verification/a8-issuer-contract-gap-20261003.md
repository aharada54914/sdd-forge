# A8 issuer-ledger contract gap (read-only audit, 2026-10-03)

Scope: PR #513 checkout at `8fdfdb6ff84c4d0a4d4fc1ffb065e318cf5132d4`. This is a non-frozen verification observation, not a quality-gate verdict or a task-status change. No key, signature, nonce entry, live-host record, or validation run was produced here.

The A8 design names Epic A1's `check-hook-activation-handshake.{py,sh,ps1}` as the producer that appends an issuer-signed nonce-ledger entry *at issuance* (`specs/epic-196-a8-integration/design.md:602-627`; see also the artifact ownership table at line 101). T-008's HUMAN APPLY STEP expects a maintainer and independent reviewer to register separate signing identities, run that handshake against five semantic cells, and obtain `discharged` from `validate-live-host-proof` (`specs/epic-196-a8-integration/tasks.md:1620-1632`).

The current A1 Python implementation's `_fresh_nonce` explicitly says the nonce is never persisted by that script, and `run_emit_challenge` only prints the challenge (`plugins/sdd-quality-loop/scripts/check-hook-activation-handshake.py:199-239`). Its CLI exposes `--emit-challenge`, `--verify-response`, and `--confirm-cleanup`, with no matrix-cell, issuer-key, signing, or ledger argument (`:482-496`). The `.sh` and `.ps1` files are thin dispatchers to that Python implementation (`check-hook-activation-handshake.sh:1-20`; `.ps1:1-17`). A bounded search for `live-host-nonce-ledger/v1`, `issuer_signature`, and `:nonce-issuer` across the relevant plugin scripts and tests found only the A8 validator, the empty ledger, and synthetic fixture driver; it did not identify a separate live issuer writer. This does **not** rule out a human-held signing tool outside the repository, but such a tool would not make the named A1 challenge route append its contracted entry.

The A8 validator requires each ledger entry to contain a trusted issuer key and valid Ed25519 `issuer_signature` (`plugins/sdd-quality-loop/scripts/validate-live-host-proof.py:310-335`), then rejects a record whose nonce is absent from that ledger (`:480-488`). Thus the existing handshake command alone cannot satisfy the validator's issuance precondition. The validator itself can publish nonce consumption by writing the ledger for otherwise-valid records (`:498-525`); it is not a substitute for issuance. The checked-in trusted-signer registry has no signers and the checked-in nonce ledger has no entries (`plugins/sdd-review-loop/references/a8-trusted-signers.json`; `tests/hook-activation-live-proof/nonce-ledger.json`). The five draft SKIPs remain unproved native cells, not signed live records.

Task ownership makes this a scope issue, not merely missing human keys. Epic A1 T-008 is `Done` and specifies only the fixture-tested challenge/verify/cleanup contract, explicitly excluding real-host proof (`specs/epic-189-a1-project-context/tasks.md:1940-2055`); A1's design says its protected handshake never itself performs a write attempt and fixes the three-mode CLI (`specs/epic-189-a1-project-context/design.md:1080-1105`). A8 T-005 owns the validator and empty ledger seed but explicitly excludes modifying A1's handshake (`specs/epic-196-a8-integration/tasks.md:904-922,1092-1106`). A8 T-008 is `Approved`/`Planned` and owns the human registry/signing/live-session step, yet excludes agent modification of A1's artifacts (`:1435-1443,1620-1658`). The only repository signing helper located in this bounded trace is for disposable synthetic fixtures (`tests/fixtures/live-host-proof/run_cases.py:149-199`); the production validator verifies signatures but does not sign them (`validate-live-host-proof.py:201,310-335,400-413`).

Smallest candidate direction for separate scope/approval review: reconcile the frozen A1 no-write CLI contract and frozen A8 issuer-ledger contract by specifying a **separate human-run issuer command** for signed ledger entries, without reopening A1 T-008's already-Done handshake implementation. The existing A8 T-008 approval covers human key/record provisioning but does not identify or authorize implementation of that command. The admitted A8 documents specify Ed25519 and two-party custody, but name no concrete signing CLI; the security spec leaves the library choice to later implementation (`specs/epic-196-a8-integration/security-spec.md:168-181`). The synthetic test signer is not a production command. A proposed command needs an explicit owner/task and approval, with the applicable frozen-artifact amendment/re-review before implementation. Preserve independent human key custody and the validator's fail-closed checks. Do not generate ledger entries or sign draft records to paper over this mismatch. The separate Copilot native `apply_patch` refusal remains documented in `reports/verification/a8-post-update-live-20261002.md`; no native retry or refusal bypass was attempted in this audit. AC-015/AC-016 discharge and the five-cell real-host proof remain unverified.
