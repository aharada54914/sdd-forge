## The Two Criticals

1. **Identity uniqueness is bypassable with a trailing newline on BOTH
   runtimes.** `^...$` matches before a trailing `\n` in Python `re` and .NET
   `Regex`, so `"sess-1\n"` passes the id format gate and then compares
   unequal to `"sess-1"` in the dedupe sets. Measured: two manifests sharing
   physical `sess-1`/`agent-1`, the second with a trailing newline on both
   ids => `TASK_INPUT_OK` on bash --batch and pwsh -Batch. Realises the exact
   risk tasks.md:220-221 names ("identity reuse could silently defeat task
   context isolation"). Fix: `\A...\Z` / `\A...\z`, or reject control chars.
2. **PowerShell batch validation fails OPEN through the documented CLI.**
   With `pwsh -File ... -Batch a b c`, only `a` binds to `[string[]]$Batch`;
   `b` and `c` bind positionally and are discarded. Measured with three
   manifests all sharing `run-SAME`: bash CLI correctly rejects
   (`duplicate run_id`); pwsh CLI => `TASK_INPUT_OK` exit 0. The comma form
   errors, so no working CLI batch form exists for the ps1 twin. Caveat: the
   in-process array form is correct, and the orchestrator that chooses the
   form (implement-tasks SKILL) drifted and is excluded, so the unsafe path
   cannot be ruled out this cycle.
