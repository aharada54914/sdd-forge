### Required follow-up: task-stage re-bind

The `Done` flip this gate performs makes
`check-workflow-state.sh` report
`epic-193-a5-capability-resolver: stage-provenance: task plan hash is stale`
(exit 1). That check runs in CI (`.github/workflows/test.yml:50,55`), so the
branch must be re-bound **before** it is pushed.

This is structural, not a defect in the flip. `manifest_has_reviewed_hash`
accepts four canonical forms of `tasks.md`, and the attempt-5 re-bind
(`94594c51`) recorded only the raw one:

| Form | Hash after the flip | Recorded in attempt-5 |
|---|---|---|
| raw | `d30c0513db48b922a62f9e957b67c2820f43d477407bd8c5a451b8ed5e328476` | no — it recorded `9d88304142b01219ea4935a2753153af84ddc098edfd9a26e0dce2b2f51d26cc`, the pre-flip raw |
| `normalized_hash(task)` (all `Status:` → `Planned`) | `38770deaf590060af86a7043224e2c202bed13dfb6b84ee21d6e98885abd815c` | no |
| `rereview_normalized_hash("Implementation Complete")` | `7c530c16c849e93510036053e8f9a137251cbf275ca517c912373d0415a3156d` | no |
| `rereview_normalized_hash("Done")` | `57db682e54dd2030d4beff740e211f7eb7fca4bd17ee1cac5f248185fa1903bb` | no |

Root cause: this `tasks.md` holds mixed task statuses (T-001 `Done`, T-002
now `Done`, T-003..T-010 `Planned`), so no single
`rereview_normalized_hash(file, X)` can equal the live file, and the
re-bind's reviewer manifests — which must pin live hashes — could only
record the raw form. A raw binding is invalidated by the very next
lifecycle flip, by construction. The same sequence already played out in
this feature once: `ce02de2c`'s `Blocked` → `Implementation Complete` flip
was followed by the re-binds `77a7fb32` and `94594c51`.

Remedy: a task-stage re-bind at attempt-6, in the same shape as those two
commits. It is a separate gate with its own reviewer invocations and ledger
reservations, so it is deliberately not performed here — a quality gate does
not get to manufacture a task-review verdict as a side effect.
