## The Critical

**`prepare-task-snapshot.sh:139-147` inverts Win32 success semantics and
fails OPEN on collision.** The branch maps `MoveFileW` success to
`result = 1` and failure to `result = 0`, but the guard is `if result != 0:
fail`. On native Windows an attacker who pre-creates `snapshot_root` makes
`MoveFileW` correctly refuse (return 0) => `result = 0` => the guard is
skipped => `TASK_INPUT_OK`, and the orchestrator is handed an
attacker-controlled directory while the real tree is orphaned. The happy
path is simultaneously broken (success => `result = 1` => reports "already
exists"). Measured by executing the verbatim source under a stubbed Win32
platform. This is the exact round-1 Critical that green.log and
T-003-review-2 certify as remediated — but the remediation was reviewed on
macOS only, so this branch was never exercised. One-line fix, but it needs
a regression test that pins Win32 BOOL semantics.
