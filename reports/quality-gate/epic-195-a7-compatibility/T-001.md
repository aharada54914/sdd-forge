## Evaluator findings (verbatim)

- [Major] `tests/lib/fixture-matrix-builder.ps1:42` (+ covering assertion `specs/epic-195-a7-compatibility/verification/T-001/acceptance.ps1:33-35`) — The PowerShell twin does **not** satisfy the contract's "physical-path-normalization" clause (design.md:717-720; tasks.md Scope bullet 4; Done-When bullet 4), and the acceptance assertion that is supposed to cover that clause is tautological, so it can never detect the gap. The builder sets `$fixtureRoot = (Resolve-Path -LiteralPath $fixtureRoot).Path`; the harness then asserts `((Resolve-Path -LiteralPath $FixtureRoot).Path -ceq $FixtureRoot)` — re-applying the same idempotent function the builder already applied. — Observed by direct execution: for the same underlying temp root, bash returned `/private/var/folders/7z/.../T/sdd-fixture-matrix.rlrpJk` while pwsh returned `/var/folders/7z/.../T/sdd-fixture-matrix.384bef2c...`. `ls -ld /var` shows `/var -> private/var`, and pwsh `Resolve-Path`, `[IO.Path]::GetFullPath`, and `ResolveLinkTarget($true)` all leave the symlinked component unresolved (`/var/folders/...`), whereas `bash -c 'cd "$TMPDIR" && pwd -P'` yields `/private/var/folders/...`. Consequences: (a) the ps1 outside-repo guard is symlink-bypassable — a TMPDIR symlinked into the worktree would pass `StartsWith($repoRoot)` while files land inside the repo, defeating the Global Constraint "fixtures never touch the real working tree"; (b) the twins return different path strings for the same fixture on macOS, which is exactly the environment leakage REQ-001's byte-identical goal is sensitive to, and every Planned consumer (T-003/T-004/T-006/T-007/T-008) will inherit it. Mutation `M7` in `mutation-ps1.log`/`mutation-sh.log` only inverts the assertion sentinel, proving branch reachability, not detection power. The report's phrasing "12/12 roots matched the runtime's normalized path" hedges around this rather than disclosing it. Remedy: resolve symlinked path components in the ps1 twin so its root equals the bash physical path, and assert against an independently computed physical path rather than re-applying the builder's own normalizer.

- [Minor] `specs/epic-195-a7-compatibility/verification/T-001/acceptance.sh:231` — The "not registered as an independent suite" assertion is fail-open: `rg -F ... >/dev/null 2>&1` returns non-zero both on "no match" and on "command not found" (127), so the `else` branch passes vacuously where ripgrep is absent. — Observed: `command -v rg` and `type -P rg` both fail in a plain bash on this machine (`/opt/homebrew/bin/rg` does not exist), so assertion 112 in my own bash run passed vacuously.
