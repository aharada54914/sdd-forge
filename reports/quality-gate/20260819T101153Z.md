## The cycle-1 Major, and how it was closed

**Finding.** The twins anchor the three REQ-002 patterns with `\A…\Z` (sh,
`validate-domain-contract.sh:65,67,69`) and `\A…\z` (ps1, `:59,61,63`) rather
than `^…$`. That is correct — JSON Schema draft-07 `pattern` is ECMA-262
non-multiline, where `$` matches end-of-input only, while Python and .NET regex
also match immediately before a trailing newline, so a reverted anchor would
make the validator accept `"Order\n"` as a `concepts[].name` while
`contracts/domain-contract.v2.schema.json` rejects it.

**The gap.** Nothing tested it. Cycle 1 reverted the anchors one twin at a time
and the entire 269-check suite still passed 269 / 0 both times. Zero fixtures
carried a trailing newline.

**Classification.** `auto-fix-policy.md` lists "missing tests for clear
requirements" under Auto-fix Allowed. The requirement is clear and the
implementation already correct; only the test was missing. Fixed in-gate as
cycle 2 rather than deferred to a review ticket.

**The fix, and one non-obvious constraint.** 18 checks in three new `Describe`
blocks, in their own fixture list with its own constructor
(`New-AnchorRegressionCase`) **outside** the allocated
`New-StructuralFixtureCase` table. Adding them to the AC-018 entries — the
obvious placement, and the one cycle 1's remediation note suggested — would
have broken the AC-018 count of 3, T-003's total of 62 and T-005's grand total
of 73. Verified after the change: 62 call sites unchanged, AC-018 = 3,
T-004 = 8, grand total 73, AC-013 corpus 78. No cascade into T-005.

**Verification, three independent runs.** The gate ran its own mutation in an
isolated `git worktree`: reverting the sh anchors to `^…$` failed exactly 6 of
the new checks (3 sh-specific + 3 cross-twin parity) and moved zero pre-existing
tests. Cycle 2's evaluator reproduced both required mutations — 281 passed /
6 failed each, mirror-image sets — and added a third of its own devising:
`\z` → `\Z` in the ps1 twin, which in .NET *does* permit a trailing newline and
is exactly what a future "keep both twins textually identical" sync would
introduce. That mutation is caught too.

**Two subtleties confirmed rather than assumed.** First, the newline is a real
JSON `\n` escape, verified at byte level: zero raw 0x0A inside string values,
a literal two-character escape, and a decoded value genuinely ending in a
newline. A raw 0x0A would be invalid JSON and would have been caught at the
parse step, making the tests look like they bite while testing `V2-PARSE`
instead of the anchors. Second, exit code alone does not kill the mutation for
`concepts[].context` — a re-anchored twin still exits 1 there through a
downstream cross-reference violation — so the assertion matches the specific
`V2-PATTERN: <field>:` line. Cycle 2 confirmed the shipped assertion fails at
the line-matching check, not the exit-code check.

## Process Note — the cycle-limit check is a false positive here

`check-quality-gate-cycle-limit.sh T-003 sdd-domain-concept-contract` returns
`Escalate-Human`. It is wrong, and the override is recorded here rather than
taken silently.

The script counts any same-feature report whose **content** mentions the task
id, ignoring the `Task ID:` header that names each report's subject. The three
files it counts for T-003 are `20260819T042254Z.md` (subject T-001),
`20260819T052000Z.md` and `20260819T080750Z.md` (both subject T-002); each
mentions T-003 only in its Out-Of-Scope Waivers or drift table — sections the
report template mandates and which are filled in correctly by naming which task
owns each out-of-scope surface. Measured: T-003, T-004 and T-005 each return
count 3 with zero gate reports of their own.

The property the limit protects — at most three real gate cycles — is not at
risk: this report is T-003's cycle 2 of a maximum 3. Filed as **WFI-035**, whose
proposed fix counts a report only when its own `Task ID:` header names the task.
