## Major 1 -- STAGED, NOT LANDED: the ps1 twin accepts a lowercase `z`

`ConvertFrom-Json` maps `2026-08-24T10:00:00z` to `[datetime]` with
`Kind = Utc`, so the cycle-4 `DateTimeKind` check accepted it while the python
master's regex requires an uppercase `Z`. The cycle-4 report's claim that
`DateTimeKind` "distinguishes all four shapes exactly" was wrong: there is a
fifth shape mapping to `Utc`, and unparseable strings bypass the Kind branch
entirely.

Reproduced independently here, and the fix measured against the master over a
60-case matrix (12 timestamp shapes x 2 fields x 2 check positions, plus
empty/number/bool), driving identical JSON bytes through both runtimes:

| | divergences vs the python master |
|---|---|
| live PowerShell twin | **4** -- all four `lower z` cases |
| patched PowerShell twin | **0** |

Control: the conforming contract exits 0 on all three of python, patched ps1
and live ps1. An earlier run of this matrix scored 0 divergences for the
patched twin and 28 for the live one, and was VACUOUS -- the control fixture
itself failed python (`--repo-root` changed evidence resolution), so `py=1`
in every row and the comparison measured nothing. Re-run with a control that
actually passes.

**The fix stops using `DateTimeKind` at all.** `System.Text.Json.JsonDocument`
does not coerce, so the raw text is recoverable and the master's regex applies
byte-for-byte. This also closes the unparseable-string class in the same
change. Two implementation facts, both established by probe rather than
assumption: `TryGetProperty` cannot be called from PowerShell (`JsonElement` is
a struct and its `out` parameter will not bind), hence the enumeration; and a
JSON `null` must be treated as ABSENT, not as "present but wrong" -- the first
draft rejected the shipped template, which ships `started_at: null`.

That twin is a guard-protected path, so this is staged for human apply at
`docs/ci-staging/rt-20260821-005c-check-contract-ps1-raw-timestamp.patch`
(`git apply --check` OK). The patch bundles the ps1 regression fixtures
(`T-006.ps.7f` lowercase designator, `T-006.ps.7g` unparseable value)
deliberately: shipping the tests separately would redden the suite until the
human applies the fix.
