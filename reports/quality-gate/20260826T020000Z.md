## The Charge, Stated Plainly

Third consecutive break of the same fix. The evaluator's words: the heading
grammar "was tightened one character-class at a time instead of being
canonicalised or rejected outright." It also named a methodological error in
my own verification that mattered more than the parsing bug: my twenty-case
matrix scored `bypass = (report_ok AND boundary_ok)`, but the security
property is that the **boundary alone** must not authorize. A conjunction is
satisfied whenever either side refuses, so the matrix could never have
detected the defect it was built to detect.

Both charges are accepted. The remediation below changes the method, not just
the characters.

## The Critical: a NUL-padded heading still authorized a smuggled path

`## Outputs<NUL>` was rejected by the report validator and honoured by the
boundary. Per WFI-050, report validity is not a precondition of
authorization, so the rejection had no authorizing effect and
`plugins/SMUGGLED-SECRET.md` entered the evaluator's readable input set.

Mechanism, measured rather than reasoned about:

```
=== does the boundary eat NUL? ===
AWK MATCHED: NUL was dropped
```

**No matcher written in awk can close this**, because awk cannot see the
byte. That is why the previous two fixes -- both awk-side matcher tightenings
-- were structurally incapable of working.

**Fix.** The boundary now screens the report's BYTES before any matcher runs.
An implementation or gate report is a markdown text document; no C0 control
other than tab, newline and carriage return, and no DEL, belongs anywhere in
one. `report_bytes_are_clean` is called by both `evaluator_output_is_declared`
and `implementation_report_legacy_declares`, and fails closed on an absent or
unreadable file (the first draft returned "clean" for a missing file, because
`tr` wrote nothing and `wc -c` reported 0; caught and closed before landing).

## Major 2: 30 invisible characters still keyed distinct sections

`str.strip()` removes only characters where `str.isspace()` is true, which
excludes every Cf character. Rather than enumerate a thirty-first, the
validator now bans the CLASS: NFC-normalize, refuse control, format,
private-use, surrogate, unassigned and standalone-combining characters, and
strip every Unicode separator instead of the ASCII subset. The class is
checked on the RAW name as well as the normalized one -- NFC folds a trailing
U+0301 into the preceding letter, erasing the standalone mark, and that was
the single pad form of 23 that survived the first draft of this rule.
