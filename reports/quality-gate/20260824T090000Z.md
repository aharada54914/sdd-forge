## The Critical — a one-byte authorization bypass

`validate-implementation-report.sh` captured section headings with a GREEDY
`^## ([^\n]+)\s*$`, so the trailing `\s*` absorbed nothing and `## Outputs `
keyed as the section name `"Outputs "`. That section was therefore never
found, never row-parsed, never path-checked, and never added to
`seen_paths`. Meanwhile `evaluator_output_is_declared` in
`validate-review-context-set.sh` matched headings by PREFIX
(`index($0, heading) == 1` plus trailing whitespace), so it *did* treat
`## Outputs ` as an Outputs section.

Measured, on a passing v2 fixture differing by exactly one 0x20 byte:

- `## Outputs` (second section)  → `duplicate ## Outputs`, exit 1
- `## Outputs ` (second section) → `IMPLEMENTATION_REPORT_OK`, exit 0
- `## Outputs ` carrying `| \`../../etc/passwd\` | \`d…\` |` →
  `IMPLEMENTATION_REPORT_OK`, exit 0 (the identical row inside the real
  table is rejected as `invalid output path`)

End-to-end on a scratch clone: a report with a padded second heading
declaring `plugins/SMUGGLED-SECRET.md` was accepted by the boundary —
`REVIEW_CONTEXT_OK` — i.e. an arbitrary file becomes an authorized
evaluator input. The trick is invisible to human review because GitHub
renders both headings identically, and it defeats the very
declaration-smuggling guard this task delivered at cycle 3.

  captures headings non-greedily (`^## ([^\n]+?)[ \t]*$`), so a padded

  authorization boundary now requires an EXACT heading match, so the two
  can no longer disagree. Measured after the fix: trailing space, trailing
  tab, and the traversal payload are all rejected as
  `duplicate ## Outputs`; a clean report still passes.
- Both whitespace forms pinned in `tests/turn-first-workflow.tests.sh`;
  reverting to the greedy capture is KILLED, naming the padded-heading case.
- `tests/template-validator-parity.tests.sh` pinned the OLD matcher
  construct literally, so it fired on the fix. Re-pinned to the exact-match
