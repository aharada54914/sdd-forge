## Specification Differences

Three deliberate, disclosed design decisions, each forced by the genuine
external gap recorded in "Dependency Preflight" above (Epic A4's own
`capability-summary.schema.json`/`context-projection.schema.json` are not
yet landed on this branch), plus one necessary, minimal edit to a
T-002-owned code block:

1. **Step 12's output schema self-validation is a single, uniform,
   in-process draft-07-subset engine for all four governing schemas
   (Facet Manifest, Capability Summary, Context Projection, Resolver
   Evidence), not four separate external `validate-*` subprocess calls.**
   Design.md's own prose ("using the same hand-rolled validators —
   `validate-facet-manifest`/etc., Epic A4; `validate-resolver-evidence`,
   this feature") names `validate-resolver-evidence` as this feature's own
   validator for its own Evidence self-check — but that script is T-008's
   own, not-yet-built deliverable, so no external validator exists for
   Resolver Evidence at all at this task's own implementation time. Rather
   than shell out to `validate-facet-manifest` (which does exist) for one
   artifact and hand-roll the other three inconsistently, this task
   reimplements a single draft-07 subset engine locally (`$ref`, `if`/
   `then`/`else`, `oneOf`, `propertyNames`, `pattern`, `uniqueItems`,
   `minItems` — the same keyword set `validate-facet-manifest.py`'s own
   engine implements, read per this task's own Must Read) and applies it
   uniformly to all four schema documents, each discovered via a locally
   reimplemented ADR-0025 two-step (packaged-then-git-root) procedure —
   never importing or invoking `registry_discovery.py` for this purpose,
   since that shared module's own `VERSION_CHECKS` table is closed to
   Epic A2's own three registry-family filenames and this feature's own
   Global Constraints forbid editing any file under `plugins/**`. A
   genuinely absent/unreadable schema at this discovery step maps to the
   `contract-discovery-failed` diagnostic REQ-002 already names for
   exactly this case ("any of Epic A4's three schemas ... fails ADR-0025's
   discovery procedure").
2. **This suite's own driver plants two test-harness-only stand-in schema
   files (`context-projection.schema.json`/`capability-summary.
   schema.json`, transcribed verbatim from Epic A4's own frozen `design.md`
   API/Contract Plan) into every fixture's own isolated `contracts/`
   directory, alongside the two real, already-landed schemas (`facet-
   manifest.schema.json`, `resolver-evidence.schema.json`).** This is the
   same "real dependency plus one deliberately-failing stub" pattern this
   driver already established for `canonicalize-sdd-yaml`/`generate-
   registry-digest` (T-002/T-003), applied to a schema document instead of
   a script, and is necessary for T-002/T-003's own two pre-existing
   success fixtures (`two-components`/`omits-components`, both Full-track)
   to keep reaching `exit 0` once this task's own step 10-13 code — which
   they now also exercise, since neither Blocks before step 10 — reaches
   step 12's Context Projection self-check. The `context-projection.
   schema.json` stand-in's own `projectedComponent` definition is
   deliberately looser (`additionalProperties: true`) than Epic A4's own
   real, fully-typed one (only partially transcribed at this task's own
   read time); this is a documented, deliberate simplification of a
   test-only fixture, not a claim about Epic A4's own real contract.
   `capability-summary.schema.json`'s own stand-in is planted for
   completeness/future reuse (e.g. by T-006's own future Lite-track suite)
   but is not actually exercised by any of this task's own four fixtures
   — none of them reaches a Capability Summary schema check (see next
   item).
3. **All three of this task's own new Block fixtures are deliberately
   shaped so none of them ever reaches a Capability Summary schema
   check.** `lite-check-source-undefined` Blocks inside step 10b's own
   aggregation loop, before a Capability Summary is ever assembled to
   schema-check. Both `output-schema-validation-failed` sub-cases and
   `snapshot-generation-mismatch` use the Full track (matching the two
