## Specification Differences

Two follow-on fixes to T-002-owned test infrastructure, both disclosed
here since T-002's own fixtures/driver code are shared, not this task's
own new files, but needed a small, necessary update to keep working once
this task extended the same script's own scope past step 3:

1. **`run_projection_success_case`'s own two fixtures now legitimately run
   steps 4-9, not just step 3.** Before this task, that function asserted
   a step-3-only `exit 0` (the pre-T-003 script's own actual behavior).
   This task's own extension makes that same success path continue into
   real `resolve-component-paths`/Registry-discovery/`registry_digest`
   subprocess calls before returning `exit 0` — so the fixture was widened
   (a real baseline git commit + a real, empty-capabilities Registry
   fixture, `capability-registry-empty.json`, new) rather than narrowed,
   to keep testing a genuine end-to-end clean resolve instead of an
   artificially truncated one. One of T-002's own five original assertions
   on this fixture ("no step-4-or-later subprocess," a PATH-based spy
   check) was **removed**, not silently dropped: this task's own
   `_script_argv` always finds a real dependency in `script_dir` before
   ever consulting `PATH`, so that spy can no longer distinguish "no
   subprocess ran" from "a subprocess ran, just not through PATH" — its
   own label would now assert something false. Every one of the OTHER
   four original assertions on this fixture is unchanged and still passes.
2. **`omits-components`'s own capture stub now captures only the FIRST
   JSON-mode canonicalizer call it sees.** Step 6 (`registry_digest`)
   reaches the identical `canonicalize-sdd-yaml.py` path via `generate-
   registry-digest`'s own internal call, which — unpatched — silently
   overwrote step 3's own already-captured projection bytes with the
   Registry's own canonicalized bytes instead, breaking the fixture's
   entire assertion. One-line fix (`if not CAPTURE.exists(): shutil.
   copyfile(...)`), verified by re-running: the fixture's own 9 field/
   content assertions on the ORIGINAL step-3 projection now pass again.
3. **`omits-components`'s own real `resolve-component-paths` invocation
   cannot parse its own source YAML.** Verified directly: Epic A3's own
   restricted YAML parser (`resolve-component-paths.py`, unmodified,
   outside this task's scope) requires a source document's `components`
   key to be explicitly present — it does not default an entirely-omitted
   key to `[]`, unlike this feature's own `contracts/project-context.
   schema.json` (where `components` is optional). `omits-components.yaml`
   deliberately omits `components` to exercise step 3's own default-fill
   rule and must stay byte-for-byte unedited for that reason (it is a
   T-002-authored fixture whose whole point is that omission), so this
   ONE fixture gets a fixed, always-succeeding step-4 stub instead
   (`resolve-component-paths-stub-empty.py`, new) — `two-components`
   (which does declare `components`) uses the REAL dependency throughout,
   unstubbed.
