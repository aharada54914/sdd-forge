## Summary

Implemented `plugins/sdd-quality-loop/scripts/check-hook-activation-handshake.py`
(+ `.sh`/`.ps1` thin dispatch wrappers, mirroring
`detect-policy-weakening.sh`/`.ps1`'s established pattern exactly) --
the redesigned host-canary challenge/response hook-activation handshake
design.md's "Hook-activation handshake CLI contract" fixes. The prior
standalone-probe draft (the script performing its own child-process
file-write attempt and inspecting its own result) is closed as unable to
observe the property it claims to prove: `sdd-hook-guard.py` is invoked BY
THE HOST RUNTIME as a `PreToolUse` hook, intercepting a tool call the AGENT
SESSION itself proposes; a subprocess this script spawns via ordinary file
I/O never reaches that dispatch. This script therefore NEVER performs a
write attempt itself (design decision B4) and has exactly three modes:

- `--emit-challenge`: emits `{"schema": "sdd-hook-challenge/v1", "nonce":
  <fresh, secrets.token_hex(16)>, "canary_target":
  "sdd/.hook-canary-sentinel", "tool_call_template": {<per-runtime>}}` on
  stdout, exit 0. At the START of every invocation, a read-only
  `os.path.lexists` check (never following a symlink to decide presence,
  never a write) detects a pre-existing sentinel and reports
  `STALE_SENTINEL_DETECTED` on stderr -- but always still emits a fresh
  challenge regardless (the calling skill, out of this task's file scope
  except this one contract, is responsible for the actual cleanup attempt
  against a stale sentinel; T-011/T-012's own scope).
- `--verify-response --nonce <n> --recorded-result <path> --runtime
  <claude-code|codex-cli|copilot-cli>`: reads the caller-supplied evidence
  file (never written by this script) and applies a per-runtime documented
  expected-deny-signature check plus a nonce-match check. `HOOK_ACTIVE`
  (exit 0) ONLY when both hold; every other case (missing file, unreadable/
  malformed JSON, nonce mismatch, a result showing the write executed, an
  unrecognized/ambiguous non-executed result) reports
  `CAPABILITY_RUNTIME_UNAVAILABLE` with a stable per-category exit code and
  a `reason` field.
- `--confirm-cleanup --nonce <n> --recorded-cleanup-result <path>`: reads a
  caller-supplied cleanup-delete result and reports
  `SENTINEL_CLEANUP_CONFIRMED` (exit 0) or `SENTINEL_CLEANUP_UNCONFIRMED`
  (non-zero, reason `NO_CLEANUP_RESULT`/`CLEANUP_DENIED`/
  `STALE_CHALLENGE_REJECTED`), always restating the standing
  `capability_status: "CAPABILITY_RUNTIME_UNAVAILABLE"` alongside its own
  `cleanup_status` -- an independent verdict that never retroactively
  changes the original probe's own result.

**Recorded-result evidence schema (this implementation's own realization of
REQ-010's per-runtime prose description)**: design.md fixes the CLI surface
and the high-level per-runtime signature DESCRIPTION, not the byte-level
JSON field names of a caller-recorded evidence file -- there is no prior
schema or contract file to conform to, so this session designed one,
documented in full in the script's own module docstring. Every evidence
file carries a shared `nonce` (string) + `executed` (boolean) envelope;
`executed: true` ALWAYS short-circuits to `WRITE_EXECUTED` regardless of
any other field (proof the write ran outranks any contradictory denial
claim elsewhere in the same file -- verified directly, see Mutation B
below). When `executed: false`, each runtime additionally requires:
claude-code -- `guard_emit_mode: "exit"` + a non-zero integer `exit_code`
(mirrors `sdd-hook-guard.py`'s own `--emit exit` convention, accepting ANY
non-zero code since that is what a Claude Code `PreToolUse` hook's own host
observes, not a specific value); copilot-cli -- `permissionDecision:
"deny"` (mirrors `sdd-hook-guard.py`'s own `--emit copilot` JSON shape; an
absent or `"allow"` value is the well-known "Copilot subagent hook often
does not fire" case, correctly falling through to `UNRECOGNIZED_RESULT`,
never a special case); codex-cli -- `plugin_hooks_enabled: true` AND
`denied_by_plugin_hooks: true` (an unset/false `plugin_hooks_enabled`
collapses into `CAPABILITY_RUNTIME_UNAVAILABLE`/`PLUGIN_HOOKS_DISABLED`
REGARDLESS of `denied_by_plugin_hooks`'s own value -- verified directly,
see the TEST-027 codex-cli `cx-flag-disabled` fixture).
