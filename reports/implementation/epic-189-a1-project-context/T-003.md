## Summary

Implemented `contracts/approval-sidecar.schema.json` (verbatim from
design.md's API/Contract Plan) and
`plugins/sdd-quality-loop/scripts/generate-approval-sidecar.py` + thin
`.sh`/`.ps1` dispatch wrappers (mirroring T-002's
`canonicalize-sdd-yaml.{sh,ps1}` dispatch-only shape exactly, including
the byte-exact-passthrough `[System.Diagnostics.Process]` rationale in the
`.ps1`).

`generate-approval-sidecar.py` computes `context_sha256` by dispatching
the `--content` file to T-002's `canonicalize-sdd-yaml.py` as a subprocess
(`--hash-only`, YAML mode) -- never reimplemented. It accepts `--schema`,
`--content`, `--approver`, `--status` (must be exactly `"Approved"`),
`--second-approver`, `--effective-at`, and `--live-sidecar`, and refuses
to sign (`DUPLICATE_APPROVER_IDENTITY`, before any hashing) when
`--approver` equals `--second-approver`. The HMAC preimage is the full
approval object with `hmac` excluded, dispatched to the canonicalizer's
JSON input mode (never reimplemented); `SDD_CONTEXT_KEY` resolution
mirrors `sdd-hook-guard.py`'s `_resolve_sudo_key` byte-for-byte (env var ->
env-file -> `<HOME>/.sdd/context-key` -> none, fail-closed, same
BOM/whitespace-stripping). Output is staging-only: a temporary sibling
directory holds the signed candidate + a byte-exact approved-context
snapshot (the `--content` bytes read once, never re-read from disk) +
`MANIFEST.sha256` (both hashes, re-derived from disk, plus a fresh
64-hex-char nonce); a single atomic directory rename commits all three
files at once into `sdd/.staging/<schema-id>/<nonce>/` (or `--stage-dir`
if given) -- any failure before that rename leaves the final staged path
entirely absent, never partially populated, and the temp directory is
removed. The live sidecar/anchor paths are never opened for writing under
any invocation.

**Provenance-field resolution and seam** (design.md "HMAC preimage and
signing", tasks.md T-003's rewritten Out of Scope): reads `--live-sidecar`;
if absent, this is bootstrap (`predecessor_context_sha256` /
`weakening_verdict` = `null`, `approval_epoch` = `1`) and signing completes
immediately. If present, `predecessor_context_sha256` /
`approval_epoch + 1` are read from it, and `weakening_verdict` is resolved
through a single, dedicated in-process invocation seam
(`_invoke_weakening_detector_seam`) that attempts to load
`detect-policy-weakening.py` (T-005) via `importlib.util.spec_from_file_
location` (mirroring `sdd-hook-guard.py`'s own `_load_guard_invariants`
precedent) and call its `compute_verdict()` entry point. Since T-005 has
not landed, the file does not exist, so every non-bootstrap invocation
fails closed with `WEAKENING_DETECTOR_UNAVAILABLE` and writes no staged
artifact at all -- proven directly (not merely asserted) via two dedicated
verification logs per runtime (Outputs, below). The generator never
accepts a caller-supplied verdict (no such CLI flag exists); the CLI's
only second-approval-related fields are the identity/timestamp ones.

Two test-only, non-production hooks exist, both documented as such in
their own docstrings and CLI help (`argparse.SUPPRESS`): `--dump-preimage`
(AC-012 -- reads a full approval JSON object, excludes `hmac`, prints the
canonical preimage bytes; needs no key and never signs/stages) and
`--simulate-mid-write-failure {after-sidecar,after-snapshot}` (AC-034 --
deterministically interrupts staging at a named point instead of relying
on OS-level fault injection).

## Quality Gate Remedy (seq0350, verdict NEEDS_WORK)

The independent evaluator (`reports/quality-gate/2026-07-30T142236Z-T-003.md`,
commit `f30ea64d`) reproduced 5/5 a single Major finding:
`generate-approval-sidecar.py:302,347` -- `os.makedirs(parent_dir)` and
`os.rename(tmp_leaf, stage_dir)` could raise `OSError` subclasses
(`NotADirectoryError`, `FileExistsError`, `PermissionError`) that escaped
`main()`'s narrow `except GenerateApprovalSidecarError` handler, producing a
raw Python traceback and undocumented exit 1 -- contradicting the module's
own "never an uncaught traceback" docstring promise and the stable,
documented `CATEGORY_EXIT_CODES` contract the `--help` epilog advertises.
Reproduced cases: (a) `--stage-dir` = an existing non-empty directory; (b)
`--stage-dir` = an existing regular file; (c) `--stage-dir`'s parent is a
regular file; (d) `--stage-dir`'s parent is `chmod 500`; (e) the DEFAULT
path (no `--stage-dir` at all) where `sdd` itself is a regular file. The
evaluator judged this Major, not Critical, because fail-closed behavior
itself was already intact in every case (no stray `.tmp-*` directories, no
partial/unsigned artifact).

**Remedied** (TDD, minimal diff, scope held to this one finding):
`_write_staged_outputs`'s entire filesystem sequence -- directory
creation, both temp-file writes, the re-hash reads, and the final commit
rename -- is now inside one `try`/`except OSError`, which wraps any such
error as a new, documented category, `STAGING_IO_ERROR` (exit 16 -- the
next free slot in the existing `0/2/10-15/90` exit-code space), while an
`except BaseException` clause below it preserves the existing
cleanup-then-reraise behavior for the `SIMULATED_MID_WRITE_FAILURE` test
hook unchanged (that exception is not an `OSError`, so it still falls
through to the second clause). The `--help` epilog's exit-code table is
generated directly from `CATEGORY_EXIT_CODES`, so it updated automatically
with no separate doc edit needed. All 5 of the evaluator's reproduction
cases were re-verified fixed by hand (`STAGING_IO_ERROR`, exit 16, no
traceback, zero stray temp directories/partial artifacts in every case)
before any test was written.

Two new regression classes added to both suites as `TEST-HARDEN(d)`
(7 assertions in `bash`, 7 in `pwsh`): (i) a `--stage-dir` collision
(existing non-empty directory; existing regular file), and (ii) the
DEFAULT path with no `--stage-dir` override, where `sdd` itself is a
regular file. Each asserts the documented exit code (16), `STAGING_IO_ERROR`
named in stderr, no traceback text, and -- separately -- that no staged
artifact or stray temp path was created. Genuine TDD Red (both suites' 3
new "clean exit code" assertions fail against the pre-remedy script with a
real captured traceback; the pre-existing "no staged artifact"/"no stray
temp dir" assertions in the same class already passed pre-remedy, matching
the evaluator's own "fail-closed was already intact" observation) -> Green
(`bash` 57/57, `pwsh` 55/55) captured for both runtimes at
`specs/epic-189-a1-project-context/verification/T-003/remedy-{red,green}-{sh,ps1}.log`
(implementation temporarily reverted to the pre-remedy commit `46daef11`,
suites re-run, then restored -- the same technique T-002's own remedy
rounds used).

The two Minor findings (AC-013's `resolve_evidence_key` half resting on
source inspection rather than execution; the `pwsh` suite's one documented
`TEST-HARDEN(b)` delivery-method difference) are unchanged by this remedy
and remain open, per the evaluator's own scoping and the coordinator's
