**Major 3 — `TEST-040`'s `DUPLICATE_COMPONENT_ID`/`DUPLICATE_BINDING_ID`
assertions were tautological.** `duplicate_id_check(instance, array_path,
code)` returned the caller-supplied `code` verbatim on detection, and the
CLI compared that returned value against the SAME caller-supplied value —
so the comparison could never fail on code identity, exactly as the
evaluator demonstrated with `TOTALLY_BOGUS_CODE`/`''`/`'42'`. Fixed by
assertion against a fixed table, TDD Red→Green, in both embedded
validators (kept byte-identical, re-confirmed 233/233 lines):

```python
DUPLICATE_ID_CODES = {
    "components": "DUPLICATE_COMPONENT_ID",
    "bindings": "DUPLICATE_BINDING_ID",
}


def duplicate_id_check(instance, array_path):
    arr = instance.get(array_path, [])
    seen = set()
    for item in arr:
        iid = item.get("id")
        if iid in seen:
            return DUPLICATE_ID_CODES.get(array_path)
        seen.add(iid)
    return None
```

`duplicate_id_check` no longer takes `code` as an argument; the CLI's
`dup-check` command still receives an `expected_code` from `argv[4]` and
compares it against the function's OWN table-derived return value, so a
wrong `expected_code` now fails the comparison for real.

Three new mutation-proof assertions were added directly beneath the
existing TEST-040 block, in both `.sh` and `.ps1` (same fixtures, opposite
polarity — expecting NON-detection):
1. `components` duplicate probed with the wrong code (`DUPLICATE_BINDING_ID`).
2. `bindings` duplicate probed with the wrong code (`DUPLICATE_COMPONENT_ID`).
3. `components` duplicate probed with an arbitrary bogus code
   (`TOTALLY_BOGUS_CODE`, the evaluator's own probe string).
