## Summary

Four documents now carry one identical, machine-checkable six-case decision
table, delimited by `<!-- sdd:track-selection-contract v1 -->`:

| Case | Project Context | Flag | Resolution |
|---|---|---|---|
| C1 | physically absent | any | `COMPATIBILITY_FALLBACK` |
| C2 | physically present, REQ-005 validation fails | any | `PROJECT_CONTEXT_INVALID` |
| C3 | present and valid, `spec_profile: lite` | `--full` | `PROMOTE_FULL` |
| C4 | present and valid, `spec_profile: lite` | `--lite` | `NO_OP_LITE` |
| C5 | present and valid, `spec_profile: full` | `--lite` | `ERROR_STOP` |
| C6 | present and valid, `spec_profile: full` | `--full` | `NO_OP_FULL` |

**The resolution order is the contract, and the suite enforces it as such.**
Physical presence is a filesystem test decided FIRST and alone; REQ-005
validation runs SECOND, only once the file is known to exist. C1 and C2 are
therefore reachable only by genuinely different routes. Collapsing them into a
single "is there a usable Project Context?" test is the B5 track-selection
fail-open (security-spec.md:69/84): an attacker who can induce a validation
failure against an EXISTING Project Context — sidecar tampering, replay, a
key-rotation window — would thereby regain the permissive flag-first
behaviour ADR-0023 exists to remove. C2 is a named stop, never C1's fallback,
and never an implicit `full`/`lite` grant.

Choosing one delimited table replicated across all four documents (rather than
a pointer from each consumer to `PLUGIN-CONTRACTS.md`) is deliberate: AC-039
requires each consumer to be exercised independently, and a skill an agent
reads in isolation must carry the rule it is expected to follow. The
replication is not unchecked duplication — the suite compares every
document's table against one spec-derived constant, so drift between the four
is itself a test failure.

Each of the three consumer entry points additionally carries REQ-010's
challenge/response wiring, delimited by `<!-- sdd:handshake-wiring v1 -->`
(partial AC-035 evidence; the five-consumer inventory completes in T-012).

### Deliberate runtime divergence (a variant axis, not duplication)

The `.sh` suite extracts and validates the contract tables with a Python
helper; the `.ps1` twin reimplements the extractor **natively in PowerShell**
and derives its expectations independently. A parser defect that survives one
reading — a mis-skipped alignment row, backticks stripped by only one
implementation, a greedily-matched closing marker — is caught by the other.
Both lanes drive the same real `generate-approval-sidecar.py` /
`validate-approval-sidecar.py`, because those tools *are* the production
behaviour under observation.

### Why the assertions cannot pass vacuously

Three defects in this feature's history were "an assertion that passed for the
wrong reason". Four structural defences are built in from the first Red:

1. **Expectations never come from the artifact under test.** `EXPECTED_ROWS`
   is transcribed from ADR-0023/AC-024/AC-039 into each suite. A document
   supplying its own correctness criterion would make the comparison an echo
   of its own input.
2. **Which case applies is observed, not assumed.** C1/C2 are decided by a
   real filesystem probe plus the real validator's real exit code; C3..C6 read
   `spec_profile` back OFF DISK. The fixtures decide the branch; the documents
   decide the resolution; neither supplies the other's answer.
3. **Specific exit codes, not "non-zero".** TEST-026 asserts 37/32/39/40/41/42
   individually. Six fixtures all failing for one shared reason would look
   identical to six independent routes under a bare non-zero check — and the
   valid fixtures are separately asserted to PASS, so C3..C6 cannot be
   exercising the invalid branch under a valid-looking label.
4. **Every mutation is a DELTA.** Each `assert_mutation` requires the pristine
   copy to CONFORM *and* the mutated copy to be rejected *by the specific
   expected finding*. A mutation assertion goes vacuous exactly in the TDD Red
   state; here all 13 TEST-MUT assertions fail in Red for honest, readable
   reasons ("mutation changed nothing", "not measurable: the pristine baseline
   does not conform") rather than reporting a green that measures nothing.
