## Summary

Implemented `plugins/sdd-quality-loop/scripts/apply-human-copy.sh` and
`.ps1`: two FULLY INDEPENDENT implementations (no shared `.py` master,
T-007's own architecture constraint) of the anchored-publisher-equivalent
guarantee ADR-0011 established for a Windows-only native tool, generalized
here to a cross-platform sh/ps1 pair per design.md's Human-copy publisher
transactional bundle contract.

**Held-handle / handle-relative traversal realization (documented
architecture decision, not a silent downgrade)**: POSIX shell has no
`openat()`/`renameat()` binding, and cross-platform `pwsh` (this tool runs
via `pwsh` on Windows, macOS, AND Linux — the CI matrix runs every `pwsh`
step on all three OSes) cannot portably call Win32
`NtCreateFile`/`SetFileInformationByHandle` either. Both runtimes instead
realize "a held directory handle, walked one segment at a time" via the
process's own kernel-mediated current-working-directory binding — POSIX
`chdir()` / .NET `Directory.SetCurrentDirectory()` are both genuine
syscalls that pin to a directory's INODE, immune to a later rename of that
directory's own path string (verified: `getcwd()`/its .NET equivalent
reconstructs the current path by walking `..` from the pinned reference,
so it correctly reflects a rename rather than losing the anchor). Walking
one segment at a time, with a symlink/reparse-point check strictly BEFORE
descending into each segment, is a genuine, kernel-backed equivalent of
handle-relative traversal — not a hand-wavy approximation. This is
documented in both scripts' own header comments and cross-referenced from
ADR-0025's "Consequences" section. **Documented residual** (never silently
implied as fully closed, matching this repo's established pattern, e.g.
design.md Test Strategy item 8's residual-gap notation): the narrow window
between a segment's own symlink check and its `cd`/`Set-Location`, and
between the final pre-rename state and the `mv`/`File.Move` syscall
itself, is not closed by a single held syscall the way a real
`openat()`/`renameat()` or `NtCreateFile` chain would close it — this is
the strongest guarantee achievable without an FFI-capable interpreter,
which T-007's own architecture constraint (no hidden `.py`/interpreter
engine) deliberately excludes.

**Two implementation-time security findings, found and fixed during this
session** (both discovered via genuine TDD failures against the real
implementation, not merely theorized):

1. **sh**: the initial "immediately-before-use identity re-check"
   compared `pwd -P` before vs. after the anchored write. This is WRONG:
   `pwd -P`/`getcwd()` always reflects a directory's CURRENT name, so a
   LEGITIMATE rename-and-continue (i.e., the exact substitution-resistance
   behavior AC-033 requires) always shows a path-string mismatch and was
   being incorrectly REJECTED — the check as originally written defeated
   the very feature it was meant to reinforce. Fixed by comparing
   `(device, inode)` via `stat` instead of a path string.
   **Corrected description (quality-gate seq0357 Minor #1)**: the
   dev/inode comparison is NOT itself the source of substitution
   resistance — it is dead defense-in-depth that can never fire once the
   `pwd -P` false-positive is removed (measured directly: `stat -f
   '%d:%i' .` returns the SAME value both before and after the anchored
   directory is renamed aside, so `now_id != dest_parent_id` is
   unreachable in practice). The GENUINE substitution resistance comes
   from the cwd pin itself — the anchored process's kernel-level
   current-directory reference, which continues to resolve relative
   writes to the true original directory regardless of what it is
   currently named — and that mechanism is what TEST-033o actually locks
   in. This report's original wording overstated what the dev/inode
   check contributes; corrected here per the evaluator's own finding.
2. **ps1**: PowerShell cmdlets (`Copy-Item`, `Test-Path`, `Move-Item`)
   resolve a relative `-LiteralPath` via PowerShell's own `$PWD` (itself
   just cached path-string bookkeeping, exactly like `Push-Location`/
   `Pop-Location`), NOT via `[System.Environment]::CurrentDirectory` (the
   genuinely kernel-pinned one). This meant a cmdlet call inside the
   anchored block would silently follow an attacker's rename to the
   SUBSTITUTED directory instead of staying anchored — a real
   substitution-resistance defect, not a test-fixture artifact. Fixed by
   routing every actual destination-side read/write in
   `Publish-OneTarget`/`Restore-OneTarget` through raw
   `[System.IO.File]`/`[System.IO.Directory]` calls, with the target path
   freshly recombined via `[System.IO.Path]::Combine([System.Environment
   ]::CurrentDirectory, <relative-name>)` at the moment of each operation
   — never a PowerShell cmdlet, never a path string captured earlier and
   reused later.

Both findings, their root cause, and their fix are documented in the
scripts' own header/inline comments so a future maintainer does not
reintroduce either class of bug.

**Journaled multi-target transaction** (design.md "Human-copy publisher
transactional bundle contract"; ADR-0025, which was already drafted and
committed prior to this session — see "ADR-0025 pre-existence" below):
prepare (re-hash every staged candidate together; back up existing live
bytes to `sdd/.staging/<batch-nonce>/pre/<basename>`) → journal (durable,
atomic write of `TRANSACTION.json` BEFORE any rename) → commit (one atomic
rename per target, in journal order) → complete (delete the journal) →
crash recovery (runs automatically at the START of every invocation,
before any new batch; compares every journaled target's current live hash
against its recorded PRE/POST values and drives the whole batch to
exactly one of two terminal states — recovery is itself idempotent and
re-entrant).

**CLI** (no explicit contract subsection is defined for REQ-007 beyond
prose, so this task designed a sensible generic surface): `apply-human-copy.sh
--staging-dir <dir> --manifest <GNU-sha256sum-format file>` (paths
relative to CWD, matching every sibling script's "invoked from the project
root" convention — no `--repo-root` flag); recovery always runs first,
unconditionally; omitting `--staging-dir`/`--manifest` runs recovery-only.
Three TEST-ONLY fault-injection flags mirror `generate-approval-sidecar
.py`'s established `--simulate-mid-write-failure` convention:
`--simulate-crash-after {journal-write|rename-N}` (sends a genuine
`SIGKILL`/`[Environment]::Exit`, never a soft exit, so recovery tests
exercise real crash semantics), `--simulate-crash-during-recovery-after
revert-N`, and `--simulate-substitution` (used only by TEST-033o).
