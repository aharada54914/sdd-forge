## Quality Gate Focus

`Risk: high`, `Security-Sensitive: true` — the parser's fail-closed
posture (every out-of-subset construct rejected, never best-effort
interpreted) and the JCS numeric formatter's correctness (verified
independently against 25 known ECMAScript `Number::toString` boundary
cases before being wired into the implementation — see Working Notes) are
the highest-value review targets, since a defect here would let an
ambiguous document's canonical hash diverge from a human reviewer's
understanding of its content (this task's own Risk Rationale; ADR-0019's
hash-recomputation Blocker-attack class). The `.ps1` wrapper's byte-exact
passthrough fix (Working Notes) is also worth independent scrutiny: it
changes how the child `python3` process's stdio is inherited.

## Working Notes

- Confirmed `tests/run-all.sh`/`.ps1`'s numeric-order dependency on T-001
  was already satisfied (commit `4bd2ec3`) before resuming, and that T-004
  had already inserted its own entry ahead of T-002/T-003 under the
  documented "no real conflict, T-002/T-003 contributed no lines yet"
  exception — this task's own registration was inserted BETWEEN T-001's
  and T-004's existing lines to restore correct numeric order.
- Before wiring the RFC 8785 (JCS) numeric formatter into the
  implementation, independently derived it from the RFC 8785 §3.2.2.3 /
  ECMAScript `Number::toString` algorithm (extracting shortest-round-trip
  significant digits from Python's own `repr()` — proven shortest-
  round-trip since Python 3.1 — rather than re-deriving Grisu/Ryu from
  scratch) and verified it against 25 hand-checked boundary cases (0, -0,
  the 1e20/1e21 and 1e-6/1e-7 fixed/exponential switchover points,
  `DBL_MAX`, `5e-324`, trailing-zero and double-precision-rounding cases)
  before writing any test fixture against it, to avoid a test that would
  only prove the implementation and its own golden vector shared the same
  mistake.
- Found and fixed a real bug during manual verification (before writing
  the test suite around it): `_check_document_markers`'s first draft
  counted raw `---` LINE occurrences and required 2+ to classify
  `MULTI_DOCUMENT_REJECTED`, which is wrong — a single `---` separator
  between two non-empty sections already produces two documents. Fixed by
  segmenting the stream at each marker and counting segments with real
  content, which also correctly keeps a genuinely single-document
  "leading `---` on one document" case in `UNSUPPORTED_SYNTAX_REJECTED`
  instead.
- Found and fixed a second bug: `_looks_like_mapping_entry`'s first draft
  treated ANY content starting with a quote character as a mapping-entry
  probe, misrouting a bare top-level quoted-scalar document (e.g. a
  document whose entire content is `"just a string"`) into mapping
  parsing. Fixed by actually locating the quoted token's closing quote
  and checking for an immediately-following `:`.
- Found and fixed a third bug, in `canonicalize-sdd-yaml.ps1` itself (not
  the parser): when this wrapper's own stdout is redirected (as any
  CI/automation invocation does), PowerShell's `&` call operator routes
  the child `python3` process's output through PowerShell's native-command
  success pipeline, which can silently append a trailing newline byte the
  child never wrote — breaking the byte-exact stdout-framing this REQ
  requires. Reproduced independently of this script (plain `/bin/echo -n`
  and `/bin/cat` through the same call shape) and fixed by starting the
  child via `[System.Diagnostics.Process]` directly with
  `UseShellExecute=$false` and no redirection, which makes it inherit this
  process's raw OS-level stdout/stderr handles instead of going through
  PowerShell's pipeline. Confirmed byte-exact (51 bytes, no trailing
  newline) both via the test suite's own `[System.Diagnostics.Process]`
  + `MemoryStream` capture and via plain shell redirection
  (`pwsh -File ... > file`).
- Verified `plugins/sdd-quality-loop/scripts/sdd-hook-guard.py`'s
  human-copy staging exemption (referenced in T-001's Blockers as "option
  (a), prepared and pre-verified") is now actually present in the guard
  source (`_HUMAN_COPY_STAGING_RE` at `sdd-hook-guard.py:979`) before
  concluding that this task's own staging deferral is a working-tree
  scheduling conflict, not a residual guard denial.
