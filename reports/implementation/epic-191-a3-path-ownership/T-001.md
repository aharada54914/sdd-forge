## Post-gate defect fix addendum (2026-08-09)

A separate defect, found in passing during other work and recorded rather
than fixed at the time, was verified and remediated after this task's own
quality gate: the YAML tab-indentation guard in `_Lines.__init__`
(`resolve-component-paths.py`, mirrored in `YamlLineReader`'s constructor in
`resolve-component-paths.ps1`) never fired for a bare leading tab (or,
inspected further, for ANY tab appearing anywhere in a line's leading
whitespace). Root cause: the guard measured indent depth by stripping only
literal space characters (`_indent_of`/`Get-IndentOf`), then re-sliced the
line to exactly that many characters and checked THAT slice for a tab — a
slice which, by construction, contains only the space characters that were
just stripped and can never contain a tab. Confirmed via a direct call to
the real config-loading function with a bare-leading-tab fixture
(`components:\n\t- id: desktop\n...`): the buggy guard let the tab-indented
document flow into the parser instead of failing closed, which then
surfaced as a confusing downstream `"unexpected trailing content"` error
rather than the intended `"YAML indentation must use spaces, not tabs"`
diagnostic — i.e. this was a silent-fail-open in the guard's own stated
purpose, not merely a wrong-message cosmetic issue.

Fixed in both twins by computing the leading-whitespace run over BOTH `" "`
and `"\t"` before checking it for a tab (`_leading_whitespace` in the
Python master, `Get-LeadingWhitespace` in the PowerShell twin), so the
check actually inspects the whitespace it is meant to police. Confirmed
space-only configs are unaffected (still parse) and non-vacuity was proven
by reverting each guard, observing the new regression assertion fail, and
restoring it.

Because `tests/component-path-resolver.tests.{sh,ps1}` — this task's own
suite, where a config-parsing regression test would otherwise belong — was
concurrently being remediated by another agent for T-005 at the time of
this fix, the new regression fixture and assertion
(`DEFECT-002.1`) were instead added to
`tests/component-path-diff-basis.tests.{sh,ps1}` (T-002's suite), which
exercises the same shared `resolve-component-paths.{py,ps1}` config loader
via the same real CLI entry point. See T-002's own report for that suite's
updated Outputs-table hashes; this addendum only updates the two rows above
