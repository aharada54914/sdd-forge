## Working Notes

- **Delegation**: none.
- **A fifth distinct PowerShell pitfall** was found and fixed during this
  task: dot-sourcing a script that has its own `param()` block, when
  invoked with no arguments, CLOBBERS same-named variables already bound
  in the CALLING script's scope (`check-component-coverage.ps1` dot-sources
  `resolve-component-paths.ps1` to reuse its config/classification/git-diff
  functions; both scripts share several parameter names — `$Config`,
  `$ChangedPathsFile`, `$SourceRev`, `$TargetRev`, `$IncludeUntracked`,
  `$RepoRoot` — and the dot-source silently reset all of them to
  `resolve-component-paths.ps1`'s own defaults). Confirmed via a minimal
  repro. Fixed by capturing `check-component-coverage.ps1`'s own parameter
  values into differently-named local variables (`$myConfig`, etc.)
  immediately before the dot-source line, and using those from then on.
  This required a companion fix to `resolve-component-paths.ps1` itself:
  guarding its own CLI dispatch logic behind
  `if ($MyInvocation.InvocationName -ne '.')` so dot-sourcing it (with no
  bound parameters) only defines its functions/classes without also
  running its CLI logic and calling `exit` in the shared, dot-sourced
  scope.
- **A second instance of the previously-documented IEnumerable-unwrapping
  pitfall** was found in `Import-ProviderBindingsFile`: an `if/else` block
  used as an expression to look up `$data["bindings"]` collapsed a
  1-element bindings array to its bare scalar element, and a bare
  `return @()` for the empty-array case then collapsed to `$null` —
  stacking two instances of the same class of bug. Fixed with a plain
  (non-expression) `if` statement for the lookup and a leading-comma
  `return ,@()`/`return ,@($out)` for every array-returning exit path.
- Confirmed empirically that `PHASE2_TARGETS`'s edited order determines
  where new entries land in `protected_gate_suffixes`'s validated
  baseline/residual union — verified by running the real
  `generate-guard-invariants.py --check` against the scratch copy (exit 0)
  rather than assuming the ordering.
