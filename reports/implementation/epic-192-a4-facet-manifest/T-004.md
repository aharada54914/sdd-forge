## Cycle-2 Gate Remediation (2026-08-17)

Independent quality-gate evaluator seq0761 returned **NEEDS_WORK** (Major 3,
Minor 7) against cycle-1. The evaluator stated the comparator's own *logic*
behaved correctly against every adversarial/multi-component-semver input it
constructed — the gap was that the **suite** did not lock several behaviors
the implementation already had right. This section records what changed in
response, each item cross-referenced to its finding:

1. **Major-1 (branch 2 vs. branch 4 precedence unlocked)** — no fixture
   combined a major bump with BOTH a changed digest and a genuinely
   differing semantic output, so moving branch 2 (major-forced) to after
   branch 4 in `classify()` left the suite 46/46 green (the evaluator's own
   reproduction). New fixture `major-bump-semantic-changed-new.json`
   (`resolver.version` major bump + `registry_digest` changed + `capabilities`
   changed) with a pinned-reason assertion (`stale:major-version-forced`,
   never `semantic-output-changed`) closes this. Mutation-kill proof: moving
   branch 2 after branch 4 flips exactly this one assertion to FAIL (47/48
   both runtimes, 0 collateral regressions) —
   `verification/T-004/gate-c2-mutation-proof.log`, Trial 1.
2. **Major-2 (5 of 9 `SEMANTIC_FIELDS` completely unlocked)** — deleting any
   of `schema`/`feature`/`affected_components`/`required_facets`/
   `lite_eligibility` from `SEMANTIC_FIELDS` left the suite 46/46 green (the
   evaluator's own reproduction; fail-open direction — a real stale
   transition would be silently reported `fresh`). Four new end-to-end
   fixtures (`feature-change-new.json`, `affected-components-change-new.json`,
   `required-facets-change-new.json`, `lite-eligibility-change-new.json`,
   each paired against `base-old.json` with a `registry_digest` change to
   reach branch 4, matching the existing TEST-020/021/022 pattern) close 4 of
   the 5. The 5th, `schema`, is **impossible** to close with a real fixture
   pair: `contracts/facet-manifest.schema.json` fixes `schema` as a JSON
   Schema `const`, so two independently schema-valid Facet Manifest
   documents can never differ in that field — any fixture attempting it
   would be rejected at branch 0 before ever reaching branch 4. Closed
   instead with a `classify()` unit-level check (a `python3 -c`/PowerShell
   heredoc snippet embedded in both suites that imports the comparator
   module directly and calls `classify()` on two hand-built dicts differing
   only in `schema`, bypassing the CLI's own schema-conformance front door
   without bypassing the actual comparison logic under test). Mutation-kill
   proof: removing `schema` from `SEMANTIC_FIELDS` flips exactly the new
   `schema`-field assertion to FAIL (47/48 both runtimes, 0 collateral
   regressions) — `verification/T-004/gate-c2-mutation-proof.log`, Trial 2.
3. **Major-3 (sibling-import failure not fail-closed)** — a missing/broken
   `validate-facet-manifest.py` previously crashed at **module import
   time** (before `main()`/`argparse` even ran), which (a) broke `--help`
   and (b) exited via Python's own unhandled-traceback default, exit code 1
   — indistinguishable from a legitimate `stale` verdict to a caller that
   branches on exit code alone (design.md's own stated caller contract).
   Fixed by making the sibling import lazy (`_load_vfm()`, cached, called
   from `main()` only after argument parsing succeeds) and wrapping it in a
   broad `except Exception` that reports `validator-import-failed` on the
   exit-3/stderr-only diagnostic channel, matching every other "this is not
   a verdict" condition. Verified: `--help` now prints usage and exits 0;
   a scratch-directory copy of only the comparator script (sibling absent)
   now exits 3 with a clean, traceback-free diagnostic on stderr and empty
   stdout — both runtimes assert this directly (copying the real script
   into a fresh temp directory at test time, not a hand-maintained fixture).
4. **Minor-4 (9 vacuous assertions)** — `ok "...proven by TESTNNN
   above"`/`Write-Host 'ok: ...'; $script:Pass++` lines that passed
   unconditionally, inflating the tally (self-evident from the pre-
   remediation RED log, where these same lines still passed with the
   comparator entirely absent). All 8 such lines (TEST-044's three
   exit-code-mapping restatements, TEST-046's five positive-per-tier
   restatements) converted to plain cross-reference comments in both
   suites — they name which earlier, real assertion already proves the
   same fact, but no longer count as passing checks themselves.
5. **Minor-5 (Specification Difference #4 correction)** — the prior report
   framed the multi-component semver interpretation ("coarsest changed
   component wins") as an open judgment call design.md left implicit.
   design.md's own Invocation section text, "...to differ at exactly that
   semver component (**and no coarser one**)," is logically equivalent to
   that same interpretation — the spec was already closed, not open, and
   design.md governs the CLI contract (design.md's own text: "This
   section's shape... is normative") even though requirements.md's
   parallel prose omits the parenthetical. Specification Differences #4
   below is rewritten to state this directly. A genuine multi-component
   fixture (`multi-component-bump-new.json`, `1.1.0` -> `1.2.5`, both minor
   and patch differ) was added: declaring `patch` is rejected (exit 3,
   actual tier `minor`), declaring `minor` is accepted and proceeds.
6. **Minor-6 (AC-046 missing patch-vs-major mismatch case)** — only a
   patch-vs-minor mismatch fixture existed for the "declared coarser... no,
   finer than actual" direction against a major diff specifically. Added: a
   `patch` declaration against `major-bump-new.json`'s actual major diff,
   asserted as an exit-3 argument error in both suites.
7. **Minor-7 (implementation-report git-commit misstatement)** — corrected
   in the Summary above: cycle-1's four commits (`1f054f52`/`d2ea1008`/
   `80d1ebf8`/`6b0c8e97`) had already landed before this remediation began;
   the prior "no git commit was made" statement was accurate only for the
   session that produced cycle-1's own diff, not for the state this report
   describes.
8. A robustness bug in the `.ps1` twin's own new `schema`-field unit check
   was discovered and fixed during this remediation's own RED-capture pass
   (not named by the evaluator, but a genuine defect: the check's output
   capture called `.Trim()` on a `$null` value whenever the piped `python3 -`
   invocation produced no stdout at all — e.g. because the comparator script
   it targets was itself absent, exactly the RED-run condition this suite is
   supposed to tolerate per RT-20260817-003 — which crashed the entire
   script under `$ErrorActionPreference = 'Stop'` instead of recording a
   single `FAIL` line, truncating the RED capture from 48 to 43 assertions).
   Fixed by capturing combined stdout+stderr via `Out-String` and guarding
   against `$null` before `.Trim()`. A second, same-class bug in the new
   Major-3 sibling-import-failure check's own `Copy-Item` call (its SOURCE
   is the comparator script under test, which is legitimately absent during
   a RED run) was fixed with `-ErrorAction SilentlyContinue`, matching how
   the `.sh` twin's plain `cp` already degrades gracefully (a failed `cp`
   under `set -uo pipefail` without `set -e` does not abort the script).
   Both fixes are internal to the test harness, not the comparator itself,
   and are why the cycle-2 RED log required two authoring passes before
   both runtimes reached exact 1-ok/47-FAIL parity.
9. Suite counts updated everywhere in this report: 18 -> 24 fixtures, 46/46
   -> 48/48 assertions (both runtimes, exact parity).
