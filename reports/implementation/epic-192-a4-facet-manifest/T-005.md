## Fix-by-review-ticket work (outside T-005's Planned Files)

These two items are explicitly outside T-005's own Planned Files (tasks.md)
but were bundled into this task's landing per the assignment brief. Kept
separate here so the gate can see the scope boundary clearly.

**RT-20260817-004** (`validate-facet-manifest.py`/`validate-capability-
summary.py` non-UTF-8 traceback leak): both scripts' `main()` caught
`except (OSError, json.JSONDecodeError)` around their respective `--manifest
.json`/`--summary .json` load call, which does NOT catch
`UnicodeDecodeError` (raised by the implicit UTF-8 text decode inside
`open(..., encoding="utf-8")`) — `UnicodeDecodeError` is a `ValueError`
subclass, not a `JSONDecodeError` subclass. A non-UTF-8 byte-stream input
therefore leaked an unhandled Python traceback instead of the intended
`manifest-unreadable`/`summary-unreadable` diagnostic.
`validate-context-projection.py`/`compare-facet-manifest-staleness.py`
already carried the correct `except (OSError, ValueError)` form (confirmed
by grep before editing — this was the one remaining gap, not a pattern
needing to be introduced from scratch). Fixed both remaining sites
(`validate-facet-manifest.py:544`, `validate-capability-summary.py:436`,
post-fix line numbers). Regression fixtures added: `tests/fixtures/facet-
manifest/schema/manifest-non-utf8-bytes.bin`, `tests/fixtures/facet-
manifest/capability-summary/summary-non-utf8-bytes.bin` (both `\xff\xfe
...` — deliberately invalid UTF-8, `.bin` extension so `check-
placeholders.sh`'s binary-file skip applies); assertions added to `tests/
facet-manifest-schema.tests.{sh,ps1}` (2 new assertions each: diagnostic
present + no traceback, and exactly one output line) and `tests/
capability-summary-schema.tests.{sh,ps1}` (same 2-assertion shape). Mutation
proof: `verification/T-005/gate-mutation-proof.log` Mutations 1-2.

**RT-20260817-005 item 1** (`compare-facet-manifest-staleness.py` sibling-
import guard misses `SystemExit`): the lazy `_load_vfm()` import guard in
`main()` caught `except Exception`, which does NOT catch `SystemExit`
(`SystemExit` subclasses `BaseException` directly, not `Exception`). A
sibling `validate-facet-manifest.py` whose own top-level code called
`sys.exit(N)` (e.g. a corrupted install) would propagate that raw exit code
straight through with NO diagnostic on either channel — silently colliding
with this contract's own fixed `0`/`1`/`2`/`3` exit-code enum (e.g.
`sys.exit(2)` would be indistinguishable from a legitimate `blocked`
verdict to a caller that only inspects the exit code). Fixed to `except
(Exception, SystemExit)` (`compare-facet-manifest-staleness.py:310`,
post-fix line number). Regression assertion added to `tests/facet-manifest-
staleness.tests.{sh,ps1}`: copies the comparator into a scratch directory
alongside a corrupted sibling `validate-facet-manifest.py` whose only
top-level statement is `sys.exit(7)`, and asserts the comparator now fails
closed on exit 3 with a `validator-import-failed` diagnostic (never raw
exit 7). Mutation proof: `verification/T-005/gate-mutation-proof.log`
Mutation 3 — reverting the fix reproduces the exact regression (`got exit=7
stdout=[] stderr=[]`, no diagnostic on either channel).
