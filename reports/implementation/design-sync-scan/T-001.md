## Specification Differences

None from `design.md`'s Script contract, pattern catalogue, or exit-code
precedence. Two implementation-time decisions, both within the latitude
`tasks.md`/`design.md` leave to the implementer, are recorded for the
reviewer:

1. **TEST-082's concrete fixture for "a valid-length run immediately
   adjacent to one more digit on either side."** AC-011/Edge Case 8 states
   this abstractly. Appending exactly one digit to a valid-length P2 run can
   only produce a genuine negative if the run is already at the 15-digit
   maximum (which collapses to the same fixture shape TEST-081 already
   covers); to test the boundary's other, structurally distinct edge, TEST-082
   uses a digit sitting immediately **before** the required `+` (e.g.
   `ID9+123456789`), which the `(^|[^0-9])` leading-boundary alternative
   correctly rejects even though the digits after `+` are, in isolation, a
   valid 8-15-digit run. A same-shape positive control
   (`ID +123456789`, same digits, no leading-adjacent digit) is asserted to
   still match, proving the row exercises the boundary and not the
   quantifier. Recorded because the acceptance criterion's own wording is
   satisfiable by more than one concrete fixture and this is the one chosen.
2. **`check-placeholders.sh`'s own naive substring scan flags this feature's
   two new files when run against them.** `design-sync-scan.sh`'s pattern
   catalogue necessarily contains the literal alternatives `TODO|FIXME|...`
   as regex source (its entire purpose is to detect them), and the test
   suite's fixtures necessarily embed the same literals as data. Running
   `bash plugins/sdd-quality-loop/scripts/check-placeholders.sh
   plugins/sdd-bootstrap/scripts/design-sync-scan.sh
   tests/design-sync-scan.tests.sh` reports 21 findings, all of this shape.
   This is not a defect introduced here: `check-placeholders.sh` produces
   the identical self-referential finding (4 findings) when pointed at its
   own source
   (`plugins/sdd-quality-loop/scripts/check-placeholders.sh:12,15,18,19`),
   confirming the pattern-definition/pattern-detector class of file is
   structurally exempt from this particular gate by construction, not by
   omission. `quality-gate/SKILL.md:45` scopes `check-placeholders` to
   "changed production files only," so this is flagged here for the
   reviewer's/gate's explicit acceptance rather than worked around (e.g. by
   obscuring the literal pattern text, which would harm reviewability for no
   security benefit).

## Working Notes

Validated every regex pattern (S1-S7, P1, P2, and the reused placeholder
pair) against real `/usr/bin/grep` (BSD grep, GNU-compatible, no
`--exclude-dir` support) in a scratch harness before writing the script, to
avoid two local pitfalls specific to this environment: (a) this interactive
session's own `grep` shell function (a Claude Code sandboxing wrapper that
forces `-G`/basic-regex and is exported into `bash -c` subshells inconsistently)
silently breaks `-E` when patterns are tested by typing `grep` directly in
this chat's Bash tool -- a fresh `bash script.sh` subprocess (how the suite
and any real caller invoke this script) does not inherit it, confirmed
empirically; (b) a pattern beginning with `-` (S1's `-----BEGIN...`) must be
passed via `grep ... -e "$pattern"`, not as a bare trailing argument, or
grep parses it as an option string and errors. Both are handled in the
script (`-e` used throughout) and were the two real bugs the scratch harness
caught before they reached the suite.
