## Working Notes

**The TEST-049 regression, in full.** This task's Done-When item 2 ("No
other change to `claude-design-workflow.md`... otherwise read unchanged
except at the one insertion point above") only speaks to this feature's
own edit surface; it does not, by itself, surface the existence of a
byte-identity regression check owned by a *different* feature
(`design-sync-standing-consent`) over the *same* file. The first-authored
edit inserted a new `## Standalone Scan (Manual/Codex Hosts)` section
between the pre-existing "When no visual input is supplied, record:" line
and `## Manual Steps`. That placement independently satisfied this task's
own TEST-047 (confirmed GREEN in an intermediate run) and left the
sibling's own bullet byte-untouched (confirmed by diff) -- both of this
task's own explicit constraints. It was only running
`tests/design-sync-standing-consent.tests.sh` as a baseline-comparison
step (per this task's own "baseline comparison... new FAIL zero"
instruction, exercised proactively rather than skipped because this
task's own Done-When does not name that suite) that surfaced TEST-049's
failure. Root cause, found by reading that suite's own TEST-049
implementation directly: it computes
`sha256(sed -n "1,${prefix}p")` and `sha256(sed -n "${suffix},\$p")` around
two textual anchors (`"a normal specification edit."` and `"When no
visual input is supplied, record:"`), and compares both against
constants baked in when the standing feature's own T-004 landed. The
first-authored edit's insertion point fell *inside* the suffix-anchored
span (everything from the second anchor to EOF), which is exactly the
span TEST-049 freezes. The fix -- relocating the new bullet into the gap
*between* the two anchors, the same gap the sibling's own bullet already
occupies -- leaves both spans, and therefore both hashes, untouched. This
was corrected within this same task/commit, before any GREEN or
Implementation Complete claim was made public; the pre-correction
transcript is preserved (see Outputs) rather than discarded, as evidence
of the defect and its correction, not as a passing artifact. The general
lesson (recorded for future tasks touching a file more than one feature's
suite locks down): **a "no regression" instruction scoped to "run the
suites this task's own plan names" is not sufficient when a file is a
shared, multi-feature edit target; the sibling feature's own suite must be
run and its result read, not assumed compatible from a Done-When item's
silence about it.**

**Test-authoring technique**: reused T-003's `t003_flatten_file` /
`Get-T003FlattenedFile` helper rather than redefining it, since it is a
generic whitespace-normalization utility over an arbitrary file path
argument, not itself part of T-003's own frozen assertion content --
calling it does not modify T-003's block, and duplicating it would violate
DRY for no gain. Used case-sensitive substring checks throughout TEST-047
(`grep -Fq` / `.Contains(...)`), mirroring T-003's own TEST-031 (which
names a script and a target-directory literal in the same way) rather
than T-003's TEST-033 (`grep -Fiq` / case-insensitive `-match`, used there
for a looser conceptual-scope claim) -- AC-029's own claim is a set of
literal names and a specific precondition-free statement, closer in kind
to TEST-031 than to TEST-033.
