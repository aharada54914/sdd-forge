## Summary

Implemented the Python-master registry digest CLI plus thin sh/ps1/js
dispatchers. The master imports T-003's `registry_discovery`, dedupes both CSV
selector sets, rejects unknown caller-selected IDs with
`unknown-fragment-id`, closes capability selection over each capability's
`gate_ids`, and stable-sorts the selected capability and gate arrays by ID.
`--whole` passes the complete Registry object to canonicalization without
sorting its author-ordered arrays. No-selector invocation fails with
`fragment-selector-required`; mixing `--whole` with fragment selectors fails
closed with `fragment-selector-conflict`.

NFC normalization, RFC 8785 serialization, and hashing are not implemented in
T-005. A temporary JSON file is passed to the A1 canonicalizer subprocess with
its published JSON/hash interface, and only the validated 64-hex payload is
emitted by this CLI.

Acceptance-first Red used an intentionally duplicate/order-sensitive
implementation that omitted capability-transitive gates. Green replaced that
fragment builder with set-based closure and stable ordering. Both final suites
pass 14/14 and prove raw-byte wrapper parity (`64 hex + LF`) across sh, ps1,
and js.
