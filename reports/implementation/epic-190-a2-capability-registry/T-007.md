## Summary

Authored `tests/capability-registry-parity.tests.sh`/`.ps1`: an
integration-level, golden-fixture parity harness over the four wrapper sets
T-002/T-004/T-005/T-006 already shipped (`evaluate-predicate`,
`validate-capability-registry`, `generate-registry-digest`,
`generate-gate-capabilities`). No production script was touched.

The harness builds three simulated installed-plugin contexts from three new
descriptor fixtures (`parity-runtime-claude-code.json`,
`parity-runtime-codex-cli.json`, `parity-runtime-copilot-cli.json`), reusing
T-003's own TEST-027 installed-layout pattern: each context lives at a
distinct absolute root under an `mktemp` tree outside this repository (so no
`.git` is reachable), carries only the packaged copy at the script-relative
`plugins/sdd-quality-loop/contracts/` offset, gets a host-specific marker
file, and has no runtime environment variable set. The `codex-cli` descriptor
additionally reaches every staged script through a per-file symlink into a
separate real tree -- the same variation T-003's own codex-cli fixture uses,
which is what proves `__file__` resolution rather than the invocation path
decides artifact discovery.

Every invocation is handed the identical fixture input at one identical
absolute path (the predicate/component-properties pair split once from
`predicate-trigger-context.json`, plus `validate-registry-fully-clean.json`
and `gate-capabilities-clean-registry.json`), so "identical fixture input"
(AC-031/AC-033) is literally true rather than merely equivalent.

**TEST-031** compares `.sh` vs `.ps1` (vs `.js` for the digest) raw stdout
bytes inside one fixed reference context, and additionally pins each
comparison to a committed golden -- two new golden captures for
`evaluate-predicate` and `validate-capability-registry`, T-006's existing
`gate-capabilities-clean-expected.json` for the projection, and, for the
digest, a value reconstructed independently by invoking Epic A1's
canonicalizer directly on the same fixture Registry. Without the goldens the
matrix would still pass if all wrappers drifted together.
`generate-gate-capabilities`'s observable output is the file it writes, so
parity is asserted on those bytes too, with the output slot cleared between
wrappers so neither can pass by inheriting the other's file.

**TEST-033** compares exit codes and stdout for every script and wrapper
across all three contexts, plus the written projection bytes, plus a
`--check` exit-zero assertion in all six runtime x wrapper combinations, plus
a sweep confirming no invocation in any context emitted a
`registry-discovery` fail-closed diagnostic (AC-027's contract, re-asserted
at invocation level).

A **non-vacuity canary** runs on every invocation of the suite: a fourth,
throwaway context whose staged `.ps1` wrapper carries a deliberately injected
divergence is pushed through the same byte-comparison function, and the suite
fails if that divergence is *not* reported. The same injection mechanism,
exposed as `SDD_PARITY_INJECT=wrapper|runtime`, is what produced this task's
RED evidence; it only ever patches the disposable staged copy inside the
suite's own `mktemp` tree.
