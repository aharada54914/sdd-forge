## Summary

Authored `plugins/sdd-quality-loop/scripts/registry_discovery.py`, a
shared Python helper implementing ADR-0025's three-step, script-relative
discovery procedure: (1) script-relative packaged copy at
`<module-real-dir>/../contracts/<filename>`, resolved from the module's
own symlink-resolved real path, no runtime environment variable consulted;
(2) `git rev-parse --show-toplevel` fallback (with an upward `.git` walk
if `git` itself is unavailable); (3) fail-closed on either an unresolved
path or a failed per-artifact version check, with a diagnostic naming
every attempted path. Each of the three artifacts has its own independent
version check (`capability-registry.json`: `schema ==
"capability-registry/v1"`; `capability-registry.schema.json`: `$schema`
present and `$id` equals the exact value T-001 declared; `lite-upgrade-
reason-catalog.json`: `schema == "lite-upgrade-reason-catalog/v1"`). A
location that exists but fails its version check is a terminal
fail-closed diagnostic -- discovery does not fall through to the other
location, since doing so would itself be an undocumented second
resolution path.

Also authored `plugins/sdd-quality-loop/scripts/vendor-capability-
registry.{py,sh,ps1}`, the vendoring/packaging step: refreshes
`plugins/sdd-quality-loop/contracts/*` from the canonical `contracts/*`
originals (located via `git-root`, since this step is that vendored
copy's own producer and never reads its own output as a source, mirroring
`generate-gate-capabilities.py`'s identical convention). `--check` mode
computes both sides' sha256 in memory, writes nothing, and exits non-zero
on any mismatch, exactly matching `generate-guard-invariants.py --check`'s
own contract. Ran the vendoring step for real against this repository's
canonical `contracts/*` (T-001's outputs): the three vendored copies now
exist at `plugins/sdd-quality-loop/contracts/*` and `--check` confirms no
drift.

TDD Red->Green was followed literally: the 21-check suite (both runtimes)
was authored first and run against two deliberately broken stubs (registry
discovery always reporting a fixed wrong path with no checks; vendoring
`--check` always reporting no drift) -- RED showed 15/21 meaningful
failures per runtime (the remaining 6 incidental passes are individually
explainable: the two vendored-copy-drift "clean tree" assertions pass
vacuously under a stub that always reports success, and the three
self-registration/human-copy checks are suite-scaffolding assertions
unrelated to the scripts under test). The stubs were then replaced by the
real implementations above -- GREEN shows 21/21, both runtimes.
