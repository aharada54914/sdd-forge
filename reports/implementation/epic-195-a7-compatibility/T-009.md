## Summary

**Path taken: verify, not re-implement.** All four of T-009's own Planned
Files already carried a complete, passing implementation before this
session, landed inside the same scope-leaked `45dda57f` commit T-005's own
prior session already documented and disclosed for this feature. This
session independently re-verified the pre-existing implementation against
T-009's own Done When and design.md's own API / Contract Plan, reconstructed
a genuine RED via the scratch-copy technique (old emitter scripts + current
tests = "tests written, implementation missing"), re-captured genuine
GREEN, checked the implementation against design.md's contract line-by-line,
found and disclosed one narrow undocumented-but-non-contradicting
divergence, and completed the report, `CHANGELOG.md` entry, and status
flip.

`emit-run-record.sh`/`.ps1` add `--capability-enforcement`/
`-CapabilityEnforcement` (validated against the exact
`disabled-legacy|advisory|required` enum, case-sensitively — bash via a
`case` statement identical in structure to the pre-existing
`require_effort_control_value`, PowerShell via a `HashSet[string]`
constructed with an explicit `[System.StringComparer]::Ordinal`) and
`--capability-block-id`/`-CapabilityBlockId`, each setting a new
`emit_capability`/`$emitCapability` flag that is set only by these two
flags and never by any `--effort-*`/`-Effort*` flag (confirmed by `grep`),
mirroring `emit_v2`'s own gating pattern exactly. The four documented
flag-combination outcomes are all produced correctly: no-flag emits the
`v1` heredoc, confirmed byte-identical to its pre-task form by a direct
diff against `45dda57f^`; `--effort-*`-only emits the unchanged `v2`
effort-only heredoc, with no `capability` key; `--capability-enforcement`
supplied without any `--effort-*` flag exits 1 with a diagnostic to
stderr before any output file is computed, matching
`require_effort_control_value`'s own fail-closed style; both families
together emit `v2` with both the existing `effort` object and the new,
additive `capability` object (`{enforcement, block_id}`, `block_id`
serializing as JSON `null` when `--capability-block-id` is not supplied),
via a new heredoc (bash) / `$record.Insert(7, "capability", ...)`
(PowerShell) that leaves the effort-only heredoc/branch above it
untouched.

One divergence from design.md was found and is disclosed, not fixed by
this session (see Specification Differences): the implementation adds an
internal gate — supplying `--capability-block-id` alone, without
`--capability-enforcement`, is rejected before the four-combination
table's own row 3 check even runs — that design.md's own API / Contract
Plan table does not name and that no test in
`tests/emit-run-record-feature-scope.tests.{sh,ps1}` exercises. It does
not contradict any of the four documented outcomes and is not a Done-When
violation.
