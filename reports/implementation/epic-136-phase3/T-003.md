## Summary

Stream D marks a deterministic lane boundary INSIDE the CI workflow's single
`test` job rather than splitting the job (design.md Design Decisions OQ-5).
The staged candidate produced here:

1. prefixes all **65** existing `test`-job step names with `[deterministic] `
   (GitHub Actions' native `name:` convention);
2. adds **one** documented, currently-empty YAML comment placeholder marking
   exactly where a future LLM-invoking eval lane would be added **as a
   separate job**;
3. appends Stream A's and Stream B's new bash-only CI steps inside the same
   job — bringing the candidate's `test`-job step count to **67**;
4. leaves job count, job names, and `required-checks`' `needs:` membership
   **byte-unchanged** (BL-001 preserved by construction).

The candidate was produced by a deterministic transformation script
(`verification/T-003/build-candidate.py`, committed as reproducibility
evidence) applied to a read-only byte copy of the live workflow, rather than
by hand-authoring 627 lines — this removes the "silently dropped step" class
of error that this task's own risk rationale names as its primary hazard,
and TEST-017's RED leg proves the check that would catch such a drop is
non-vacuous.

**A guard constraint changed this task's delivery shape.** See
Specification Differences below: the staged candidate lives at a
NON-protected draft path, and placing it at the human-copy staging path is a
human action.

## Specification Differences

**1. The staged candidate is at a draft path, not the human-copy staging
path — a guard constraint, resolved by an explicit human decision.**

The approved `tasks.md` Planned Files and `design.md` both assume the
implementing agent writes the staged candidate under
`specs/epic-136-phase3/human-copy/` at the workflow's own relative path.
That assumption does not hold against the current guard:

- `plugins/sdd-quality-loop/scripts/sdd-hook-guard.py`'s
  `_is_protected_gate_file` (:976-989) normalizes the path and returns true
  when it **ends with** any entry of `PROTECTED_GATE_SUFFIXES`
  (`plugins/sdd-quality-loop/scripts/generated/guard_invariants.py:4`), which
  includes this workflow's repository-relative path.
- A human-copy staging path ends with that same suffix, so it is denied
  **identically to the live file**. There is no `human-copy` carve-out
  anywhere in the guard; `PHASE2_HUMAN_COPY_TARGETS`
  (`guard_invariants.py:18`, referenced at guard :887/:909) is import/export
  bookkeeping only and grants no write exception.
- Confirmed empirically, not just by reading: a direct write attempt at the
  staging path was denied by the live PreToolUse hook with the R-10 message,
  creating neither file nor directory.

Resolution (human decision, 2026-07-23): the **draft approach** — the agent
authors the byte-exact candidate content at a non-protected draft path, runs
the self-check against it, and records the digest in `MANIFEST.sha256`;
placing that content at the staging path becomes a human action, exactly like
applying it to the live file. The guard was not bypassed, re-worded around,
or circumvented by any alternative write path.

Consequence for verification semantics: TEST-016/017/020 assert against the
draft, which is byte-identical to what the human places. The human-copy
staging path is empty until the human's first copy.

**2. The two appended Stream A/B steps also carry the `[deterministic] `
prefix**, although `design.md`'s quoted YAML block shows their names without
it. AC-016 requires *every* `test`-job step to carry the prefix, and a
prefix-less new step would fail TEST-016's own "all steps prefixed"
assertion. The stricter reading was applied so both requirements hold
simultaneously.

**3. Placement of the new steps and the comment block**: immediately before
the trailing "Upload test logs" step, keeping the new test steps with the
other test steps and the artifact-upload step last. `design.md` fixes the
step content but not its position within the job.

**4. `tasks.md`'s approved Planned Files / Done-When prose was not rewritten**
to match difference 1 — deviations are recorded here, per the same
convention T-001/T-002/T-004 used.
