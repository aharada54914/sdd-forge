## Specification Differences

- **`PATH` construction technique**: requirements.md's Field Definitions and
  design.md's API/Contract Plan both describe the combo-construction
  technique as "a real python3-free base (`/usr/bin:/bin` on a host
  confirmed lacking python3 there, or an explicit empty-PATH fixture
  directory on hosts where that base is not python3-free)". Verified at
  implementation time: on THIS host (and, per Apple's Xcode Command Line
  Tools / many Linux distributions' system-python packaging, plausibly many
  CI hosts too), `/usr/bin/python3` is a real, working Python 3.9.6
  interpreter — so `/usr/bin:/bin` is NOT genuinely python3-free here,
  triggering the documented fallback. Rather than implement the
  CONDITIONAL branch (probe `/usr/bin:/bin` first, fall back only if
  needed), this suite applies the fallback's own "explicit fixture
  directory" shape UNIFORMLY to every one of the six combos — every combo's
  `PATH` is `<combo-specific-dir>:<shared-coreutils-dir>`, never
  `/usr/bin:/bin` directly. This is one of the two options design.md's own
  prose explicitly names (not a third, invented technique), applied
  consistently rather than conditionally: it makes every "absent" premise
  genuine BY CONSTRUCTION on every host shape, rather than depending on
  which of the two documented branches a given CI runner happens to hit,
  and it needs no runtime branching logic to decide which technique to use.
  The shared coreutils directory (`sh`/`dirname`/`cat`/`grep`/`pwd`/`printf`,
  symlinked from the REAL host binaries captured before any `PATH`
  override) keeps `sdd-hook-guard.sh`'s own internal shell operations
  working under the narrowed `PATH` — necessary because a bare command name
  like `sh` is ALSO resolved against a temporarily-overridden `PATH=`
  prefix by both bash and the POSIX shell (verified empirically during
  implementation; not obvious from `tests/collection-layer.tests.sh`'s own
  simpler `/usr/bin:/bin`-only usage, which happens to already contain `sh`
  itself).
- No other differences from requirements.md / design.md / acceptance-tests.md:
  every AC-001..007 branch, both emit modes, the thin-forwarding-shim
  design, and the marker-based precedence proof match design.md's API/
  Contract Plan and Design Decisions verbatim.
- **`run-all-full-attempt.log` was trimmed after a genuine
  `check-placeholders.sh` false positive**: the first, raw 615-line capture
  verbatim-quoted `tests/check-placeholders.tests.sh`'s OWN self-test line
  (that suite legitimately asserts it correctly flags an all-caps
  placeholder-marker fixture string), which `check-placeholders.sh`'s own
  recursive scan of `specs/epic-136-phase3/` then flagged as a real
  placeholder marker once that text was quoted inside a saved log under this
  directory. Fixed by trimming the log to its suite-marker/result lines
  (still fully evidentiary — every `==>` and pass/fail summary line is
  preserved) and eliding only that one self-referential fixture line;
