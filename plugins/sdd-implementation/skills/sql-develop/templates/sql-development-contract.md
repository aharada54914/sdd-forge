## SQL開発契約

既存 `design.md` に組み込む。秘密を記入せず、不明な項目は未確定として確認する。
未確定の対象へ接続したり、検証用の既定値で本番条件を埋めたりしない。

| 項目 | 決定内容 |
|---|---|
| engine／version | <実engine、正確な版、edition／compatibility／SQL mode等> |
| 製品・環境 | <ローカル／Azure SQL Database／Managed Instance／RDS等、隔離／共有／本番> |
| 管理主体 | <migration ownerと版、正本となるファイル、対象オブジェクト、衝突の有無> |
| 変更前と変更内容 | <前版、query／schema／backfill／routine、変更対象> |
| データ | <行の意味、キー、型、NULL、重複、参照整合性、日時・照合順序・精度、保存期間、分類> |
| クエリの契約 | <入力、出力列・型、順序の要否、空集合・境界値の期待結果> |
| アプリ互換性 | <旧／新アプリの読み書き、移行段階、依存する実装タスク> |
| 影響とトラック | <データ量・分布、破壊／権限変更等、Lite候補またはFullの理由、既存判定> |
| 隔離検証先 | <作成・接続先確認・破棄の責任と資源IDの記録方法、合成データ、network／権限の分離> |
| 実行上限 | <statement／lock／資源の上限、並行適用の排他、キャンセルとDB側停止の確認> |
| 回復 | <atomic／非atomic、途中失敗後の確認、再開キー、roll-forward／restoreと損失範囲> |
| 性能 | <対象か、測定条件・反復・事前の合格閾値。対象外なら理由> |
| 実行・比較コマンド | <既存owner／project checks、履歴検証と実schema比較を分離。秘密は含めない> |
| 未決事項 | <実装・接続を止める不足情報、別範囲の確認事項> |

### 受入条件へ反映する項目

- 新規構築と前版更新で一致させるschema・キー・値・制約。
- 新旧アプリ、空／欠損／重複などの境界、失敗・二重実行・timeout後の期待状態。
- 選択engine固有の非atomic操作、rollbackできない状態と回復の確認。
- 必要な性能計測と合格基準、未実施・対象外の扱い。
- 共有・本番DBへの接続／適用は初版に含めないこと。
