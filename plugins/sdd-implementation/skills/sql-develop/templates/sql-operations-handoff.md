## SQL運用引き継ぎ

既存設計または実装報告に組み込む。この表は本番実行の承認ではない。
初版のSQLフローは共有・本番DBに接続せず、適用を外部の保護CIへ自動送信しない。

| 項目 | 引き継ぐ内容 |
|---|---|
| 検証済み範囲 | <隔離engine／実測版、fixture、実施した確認。実クラウドと区別> |
| 対象成果物 | <SQL／migration／dacpac、source revision、dirty状態、buildと比較対象> |
| 適用対象 | <製品、engine／版、対象DBの識別方法、接続秘密を含まない参照> |
| 実行主体 | <移行用DB権限、cloud ID、保護CI、運用承認者。アプリ権限と分離> |
| 前提状態 | <schema／履歴、適用直前のdrift再確認と一致条件> |
| 適用順 | <expand、アプリ、backfill、確認、別タスクのcontract、依存と排他> |
| 停止・観測 | <lock／時間／エラー・整合性条件、監査先、DB側の処理停止確認> |
| 回復 | <roll-forward／復元、復元先と接続切替、RPO／RTO、失われる更新、復旧試験の状態> |
| 再レビュー条件 | <成果物、対象、前提schema、実行条件が変更された場合> |
| 未実施 | <本番適用、Azure SQL／RDS／Aurora実環境受入、実負荷性能・復旧など> |

実装完了、隔離試験の成功、cloud基盤のapply成功を、本番SQL適用の成功へ読み替えない。
backup取得だけで復旧可能とせず、実際の復元・切替が未検証ならそのまま記録する。
